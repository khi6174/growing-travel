# 02. 화면 흐름

상태: CODEX_START와 PDF S05, D12 승인 흐름·D13 모바일 앱 중심 방향·D14 혜택 탭과 대학생 구분을 반영한 기준. 별도 전달 패키지 docs 원문 미확보. D01·D06·D08·D12~D14를 만족시키기 위한 상세 화면과 문구는 구현 선택(P01~P20)이다. [결정 장부](00_DECISIONS_AND_SOURCES.md)를 함께 읽는다.

## 전체 흐름

현재 D12 흐름: 개인 설정 → 이번 여행 조건 → 지역·혜택 비교 → 지역 선택 → 경험 추천과 근거 상세 → 코스 편집 → 저장/재열람.

D14에서는 첫 실행의 개인 설정 화면과 같은 하단 메뉴에서 혜택 탭으로 바로 이동할 수 있다. 혜택 열람에는 설정 완료·추천 결과·저장 코스가 필요하지 않다. 개인 설정의 대학생 여부는 선택 안 함·대학생·대학생 아님으로 구분한다. 세부 화면 디자인은 미루고 기존 구조에 필요한 기능만 추가한다.

후속 단계에서는 실제 후기 비교를 코스 수정·저장 전에 연결하고, 여행 후에는 개인 기록 → 선택적 공개·방문 후 확인 → 다음 추천으로 이어간다. 게시판은 코스 후기·뚜벅이 질문/이동 팁·혜택 변경 제보를 중심으로 검토하며 현재 구현 범위 밖이다.

첫 구현은 UX01~UX04를 연결했고 D12에서는 UX01의 입력과 비교 단계를 확장한다. UX05~UX08은 후속 단계이며 아직 화면이나 동작이 구현된 상태가 아니다. 화면 수·경로·메뉴 구성은 구현 선택이며 운영 서비스 확정이 아니다.

## 첫 흐름의 상태 전이

`개인 설정 → 여행 조건 입력 → 입력 검증 → 지역·혜택 비교/결과 없음/오류 → 지역 선택 → 추천 요청 중 → 결과/결과 없음/요청 실패 → 근거 확인 → 코스 초안 → 저장 중 → 저장됨/저장 실패 → 재열람`.

- 개인 설정은 현재 화면에서 사용하거나 명시적으로 브라우저에 저장한다. 저장한 설정만 삭제하는 동작과 저장 코스 삭제는 별개다. 코스에 함께 저장된 당시 입력은 과거 스냅샷이라는 점을 알린다.
- 혜택 우선 비교는 사용자가 선택한다. 입력 정보 부족·조건 불일치·기간 종료를 구분하고, 해당 후보가 실제 발급 대상이라고 표현하지 않는다. 공식 혜택 링크는 가상 지역 혜택과 별도 영역에 둔다.
- 선택 지역을 바꾸거나 새 여행 조건을 제출할 때 기존 코스 초안을 무단으로 덮어쓰지 않고 새 추천으로 전환하는 영향을 설명한다. 이전 저장 코스는 기존 형식으로 재열람할 수 있어야 한다.

- 입력 검증 실패는 입력 중으로, 결과 없음과 요청 실패는 입력 수정 또는 재시도로 돌아간다.
- 목적지가 미정이면 원하는 활동으로 경험을 탐색한다. 지역이 다른 후보나 이동 정보가 없는 코스를 적합하다고 보장하지 않고, 선택 후 지역 확인·시간 경고로 연결한다.
- 요청 중 입력이 바뀌면 오래된 응답을 현재 입력의 결과로 표시하지 않는다. 요청 ID와 입력 스냅샷을 비교한다.
- 편집한 코스는 추천 원본과 구분한다. 추가·삭제·순서 변경 후 예상 시간과 가정을 다시 보여준다.
- 시간 초과나 이동 시간 미확인인 초안은 경고 확인 후 저장 가능하게 하는 것을 제안한다. 저장 상태는 여행 가능성을 보장하지 않는다. 빈 코스와 알 수 없는 경험 참조는 저장하지 않는다.
- 저장 성공은 데이터 저장 후 재조회로 내용을 확인할 수 있는 상태다. 저장 중/실패를 성공으로 표시하지 않는다.

## 근거·동의 표시 규칙

`가상 데이터 · 시연용`, `작성자 방문 진술`, `출처 확인 필요`처럼 의미가 드러나는 문구를 제안한다. 가상 표시는 목록·상세·코스 저장본에서도 유지한다. 실제로 확보하지 않은 장소·후기를 화면 샘플용 실적처럼 쓰지 않는다(D07).

개인 기록 저장, 공개, 다른 여행자의 추천 활용, 방문 후 확인은 독립된 행동이다. 첫 코스 저장 화면에서는 이 행동들이 자동 실행되지 않는다. 동의의 상세 문구와 범위는 Q07, 방문 확인 방식은 Q08이다.

후속 공개 경험에는 변경 제보·신고·운영자 검토 경로와 제휴/후원 표기를 제안한다(P11). 다음 추천에서는 익숙한 취향과 새로운 경험 탐색을 조절할 수 있게 하며, 선택하지 않은 경험을 자동으로 싫어한다고 간주하지 않는다(P12).

## 접근성과 연결 기준

필드별 오류와 저장 결과를 텍스트로 전달하고, 색상만으로 상태를 구분하지 않으며, 키보드로 선택·순서 변경·저장할 수 있게 한다. D13에 따라 작은 화면에서의 터치·가독성·입력 보존을 우선한다. 이번 시연의 구체적 화면 구성은 아래 P19로 구분하고 운영 디자인 시스템·지원 기기·네이티브 기술은 Q03과 함께 정한다. 화면별 데이터는 [데이터 및 AI 계약](03_DATA_AND_AI_CONTRACT.md), 실제 검증 시나리오는 [완료 기준](05_ACCEPTANCE_TESTS.md)에 대응한다.

## 모바일 앱 중심 화면 구성 — P19

현재 기능을 개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험 추천·근거 → 코스 편집·저장의 단계별 화면으로 나눈다. 한 화면에서 한 단계의 주된 선택을 수행하고, 다음·이전 이동으로 연결한다. 상단에는 현재 단계와 이전 이동을, 하단에는 여행·저장한 코스·내 설정 메뉴를 제공하는 방식이다. 구체적인 경로·너비·조작 방식은 로컬 시연의 구현 선택이며 네이티브 앱 확정이 아니다.

| 화면/조작 | 지켜야 할 기준 |
| --- | --- |
| 개인 설정·여행 조건 | 각각 한 단계에서 입력. 나이·거주 미입력 허용과 유효성 검사를 유지. 오류가 있으면 해당 입력 화면과 안내를 보여줌 |
| 지역·혜택 비교 | 조건을 검증한 결과만 현재 입력의 추천으로 표시. 지역 선택 시 경험 추천으로 이동하고 가상/공식 자료 구분 유지 |
| 경험 추천·코스 확인 | 근거 상세에서 돌아오면 선택 상태 유지. 코스 확인 동작으로 선택 항목·동선·경고·저장 화면에 연결 |
| 이전 이동·하단 메뉴 | 같은 실행 중 입력·선택·코스 초안 유지. 화면 이동만으로 저장·삭제·초기화하지 않음. 추천 선행 조건 없이 결과 화면으로 건너뛰면 필요한 입력 단계로 안내 |
| 저장한 코스 | 기존 저장본을 목록에서 열어 코스 편집 화면으로 연결. 새 개인 설정을 자동 덮어쓰지 않으며 당시 입력 표시를 알림 |
| 작은 화면 | 세로 읽기와 한 열 카드 우선. 손가락으로 누를 수 있는 조작 영역, 입력 중 가독성, 하단 메뉴와 콘텐츠가 겹치지 않는 여백 확보 |

화면 전환 시 현재 위치와 초점을 이해할 수 있어야 하며, 보이지 않는 화면의 입력을 조작하도록 남겨두지 않는다. 이번 시연은 기존 브라우저에서 검증하므로 네이티브 뒤로가기·스마트폰 가상 키보드·실제 안전 영역 동작은 별도 실기기 확인이 필요하다. 수행 결과는 [모바일 시연 기록](../plans/05_MOBILE_APP_DEMO.md)에 남긴다.

## 혜택 탭과 대학생 설정 — P20

D14의 추가 범위에서는 하단 메뉴를 여행·혜택·저장한 코스·내 설정으로 확장한다. 기존 P19의 단계별 여행 화면은 유지한다. 혜택 탭에서 돌아오면 입력값·선택한 경험·코스 초안을 보존하고, 혜택을 여는 행동이 개인 설정 저장이나 코스 변경을 일으키지 않는다.

혜택 목록은 공식 자료의 명칭·분류·신청/이용 기간·대상 조건·공식 링크·확인일·확인 한계를 보여준다. 현재 기준일과 확인된 기간을 비교한 상태를 표시하되, 기간 미확인·오래된 공고·상시 소개를 ‘진행 중’으로 일괄 표시하지 않는다. 기간이 지났으면 종료로 구분하고, 현재 모집을 입증하지 못한 안내는 확인 필요로 남긴다. 목록의 진행 상태와 개인에게 적용되는 자격은 별개의 정보다. 가상 지역 혜택은 이 공식 목록에 섞지 않는다.

첫 개인 설정과 하단 내 설정은 같은 대학생 선택값을 사용한다. 기본은 선택 안 함이며, 재학 여부를 추정하거나 학교 인증을 요구하지 않는다. 기존 저장본에 필드가 없어도 열 수 있어야 하고 과거 코스의 입력을 새 설정으로 조용히 바꾸지 않는다. 실제 변경·검사는 [혜택·대학생 설정 기록](../plans/06_BENEFITS_STUDENT.md)에 남긴다.

## 맞춤 혜택 탐색 — P21

D15의 탐색은 `혜택 탭 → 비교에 쓰는 개인 설정 확인 → 조건이 맞는 후보/추가 확인 필요 → 항목별 이유·남은 확인 → 공식 안내`로 연결한다. 여행 조건 입력은 선행 조건이 아니다. 개인 설정을 고치면 현재 조건으로 다시 비교하되 명시적 저장 전에는 저장됐다고 표시하지 않는다. 저장 코스를 여는 행동이 별도로 저장한 개인 설정이나 맞춤 혜택의 기준을 조용히 바꾸지 않도록 기준의 출처를 설명한다.

| 개인별 표시 | 의미와 사용자 행동 |
| --- | --- |
| 조건이 맞는 후보 | 확인된 개인 조건이 입력과 맞음. 어떤 조건이 맞았는지 읽고 가입·증빙·잔여 예산 등 남은 사항을 공식 안내에서 확인 |
| 추가 확인 필요 | 필요한 값 미입력, 시군구·출생연도처럼 현재 필드의 한계, 공식 근거·현재성 부족. 부족한 이유와 설정 수정/공식 안내 경로 제공 |
| 알려진 조건 불일치 | 확인된 조건 중 입력과 다른 항목이 있음. 이유를 보여주고 입력 오기라면 수정 가능. 영구적인 자격 거절 표현 금지 |
| 현재 기간 아님 | 공고 시작 전 또는 종료. 개인 조건이 맞더라도 진행 중 후보처럼 우선 노출하지 않음. 공고 기간과 기준일 표시 |

정렬은 위 표 순서를 기본으로 하는 구현 선택이다. 같은 그룹 안에서는 불필요하게 순서가 흔들리지 않게 유지한다. 분야·기간 필터를 적용한 결과가 0개면 등록 자료 중 결과가 없다고 설명하고 필터 해제·설정 수정 경로를 제공한다. 표시되지 않은 사업이 존재하지 않는다고 단정하지 않는다.

각 카드는 개인 조건 상태와 공고 상태를 다른 문구로 표시한다. 예를 들어 `조건이 맞는 후보`와 `상시 제도 안내`가 함께 있을 수 있다. 근거·확인일·미확인 조건을 숨긴 채 성공색과 체크만 표시하지 않는다. 색상 외에 텍스트를 사용하고 후보/추가 확인 그룹 제목을 화면 읽기 순서에 포함한다. 클로드 디자인의 세부 배치·색·타이포는 [디자인 전달서](../handoff/claude/DESIGN_BRIEF.md)에 제안 요청으로 분리한다.
