## 1단계 작업 분해

1. **DEV01 입력과 후보 계약:** 최소 필드·단위·유효성·후보 근거·가상 라벨을 정리하고 한 화면에서 입력한다.
2. **DEV02 추천과 근거 확인:** 허용 후보 안에서 추천, 이유/불확실성 표시, 0건·오류·잘못된 참조 처리. 모델 없이 계약 검증 가능.
3. **DEV03 코스 구성:** 선택·제거·순서 변경과 시간 가정을 표시한다. 시간 초과·미확인 상태를 설명한다.
4. **DEV04 저장과 재열람:** 합의한 저장 범위에서 선택·순서·표시를 유지한다. 실패·중복 클릭·버전 충돌을 다룬다.
5. **DEV05 흐름 검증:** AC01~AC08을 수행하고 실제 실행 방법·결과·한계를 기록한다.

자세한 입출력과 범위는 [첫 개발 과제](../plans/02_FIRST_VERTICAL_SLICE.md)에 모은다. 각 작업은 따로 화면만 만드는 것이 아니라 저장까지 연결되는 한 흐름의 일부다.

## 데이터·AI 연결 순서

표시된 가상 자료로 구조와 흐름 검증(P05) → 사용 권한·출처를 확보한 실제 경험 일부로 검증(Q05) → 필요할 경우 선택한 모델 연결(Q06) 순서를 제안한다. 가상 시연 통과를 실제 추천 품질이나 실제 방문 검증으로 바꾸어 보고하지 않는다.

AI를 연결하더라도 후보 접근 제어·응답 검증·저장 계약을 유지한다. 실제 데이터 부족을 AI가 만든 장소·후기로 채우지 않는다. 운영정보 확인·추천 품질 연구·비용 검토는 각각 별도 증거가 필요하다.

## 현재 범위와 보고

최초 작업의 0단계 문서와 정적 검사 결과, D09 첫 시연 검사 이력은 그대로 보존한다. 현재는 D12에 따라 개인 설정·여행 조건·지역 비교를 기존 시연에 연결한다. PDF S05 12쪽을 반영했으며, 별도 패키지 docs와의 대조는 Q01로 남긴다. PDF 9쪽의 첫 시험판 네 기능은 사용자의 D06에 맞춰 1~3단계로 나눴다. 기술·저장 선택은 [시연 결정](08_LOCAL_DEMO_DECISIONS.md)에 기록했다. 실제 후기·평점·게시판과 개인 기록·공개·방문 확인은 다음 단계이며 배포·유료 가입·Git 커밋·푸시는 이번 범위에 없다.

후속 게시판은 우선 코스 후기·뚜벅이 질문/이동 팁·혜택 변경 제보로 검토한다. 실제 자료 확보·이용 허락, 계정·소유권, 수정·삭제·신고·운영 절차를 함께 준비한다. 후기 작성과 코스 연결은 선택적 공개 흐름에 맞추고, 초기 가상 데이터로 실제 별점·후기 수를 채우지 않는다.

구현 단계마다 바뀐 파일, 실제 실행한 검사, 미실행 이유, 데이터가 가상인지 실제인지, 남은 결정 항목을 보고한다. 기술 선택 전부터 프레임워크 명령이나 모델명을 실행 가능한 확정 명령으로 적지 않는다.
