## 변경·충돌 처리

기존 코드·패키지 docs가 없어 그 자료와의 충돌 여부는 판단할 수 없다. 확보한 S01·S02·S05의 중심 방향은 일치한다. S05의 목적지 미정 탐색에 맞춰 초안의 지역 필수 제안을 수정했고, S05가 설명하는 네 기능은 사용자의 첫 개발 범위에 맞게 순차 개발로 나눴다. 상세 차이는 [PDF 반영 대조표](07_SOURCE_REVIEW.md)에 남긴다. 별도 패키지가 도착하면 원문 보존 후 D/P/Q별로 비교한다. 문서 제안을 사용자 결정으로 바꾸지 않는다.

S06은 기존 방향을 바꾸지 않고 첫 흐름의 로컬 구현을 추가로 요청한 것이다. D03의 최초 문서 정리 이력은 보존하고, 현재 실행 범위는 D09로 갱신했다. Q02~Q04 전체를 해결됐다고 표시하지 않고 시연에 한정한 선택과 운영 미확정을 분리했다.

S07은 일반 여행자 중 우선 설계할 타겟을 좁히는 방향이며 핵심 경험·기록 순환을 폐기하는 요청은 아니다. S08의 혜택 범위는 명시적으로 반영했다. 당시에는 타겟·혜택 개발 검토안과 출처만 기록했고 시연 코드는 변경하지 않았다. 타겟을 좁히는 것 자체를 경쟁 우위 검증으로 기록하지 않는다.

S11은 S10의 검토안을 D12의 실행 범위로 승인한 요청이다. 이번 변경은 개인 설정·여행 조건·지역 비교와 코스 저장의 연결까지이며 실제 후기·게시판은 후속이다. 기존 문서·원문 사본·이전 검사 기록을 보존하고 현재 범위와 P18의 구현 선택을 추가한다. 새 검사의 결과는 실행 증거가 생긴 항목만 [확장 기록](../plans/04_PROFILE_TRIP_DEMO.md)에 기록한다.

S12는 서비스의 핵심 기능을 바꾸는 요청이 아니라 모바일 앱 중심으로 시연 화면을 구성하라는 방향이다. D12 기능·가상 자료 구분·후속 범위를 유지하며 P19로 화면 전환과 조작 방식을 구체화한다. 이전 검사 기록은 보존하고 이번 화면·탐색 결과를 별도로 기록한다. 스마트폰 실기기 검증이나 네이티브 앱 구현을 수행하기 전에는 완료로 표시하지 않는다.

S13은 혜택을 여행 추천 전에도 살펴볼 수 있게 하고 대학생 여부를 구분하는 기능 추가다. D14를 기록하고 P20으로 최소 입력과 공식 상태 표시 경계를 정한다. 화면 디자인을 다시 만드는 작업은 미루며 기존 앱 흐름·저장 자료·가상 표시·실제 후기와 게시판의 후속 범위를 유지한다. 단순 제도 소개나 과거 공고를 근거로 현재 진행 상태를 만들어내지 않는다.

S14는 기존 개인 설정을 공식 혜택의 설명 가능한 우선 정렬에 활용하는 요청이다. D15/P21로 범위를 추가하고 과거 검사 결과는 보존한다. 디자인 전달 문서는 현재 사실·사용자 결정·설계 제안·미확정을 분리한 작업 입력이며, 문서 생성만으로 외부 서비스에 전송하거나 디자인을 구현했다고 주장하지 않는다.

S15는 S14의 디자인 전달서를 바탕으로 진행한 디자인 비교에서 사용자가 고른 방향이다. D16·D17로 기록하며 D14의 대학생 여부 구분과 D15·P21의 상태 구분은 그대로 유지한다. 비교 과정에서 작업자가 제안한 조건 수정 시트의 ‘이번 비교에만 적용 / 내 설정에 저장’ 선택, 만 나이 입력 범위 같은 세부는 사용자 결정으로 승격하지 않는다. 시연 코드와 이전 검사 기록은 이번 기록으로 바뀌지 않는다.

S16은 디자인 전달서를 바탕으로 기존 로컬 시연의 화면 작업을 진행하라는 요청이다. D18로 실행 범위를 추가하되 D16·D17 외의 세부는 P22로 선택 이유를 남긴다. 자료 확인일·공식 조건·가상 표시·명시적 저장 경계를 유지하며 디자인 예시 수치를 실제 계산 결과로 복사하지 않는다. 이전 검사 기록과 전달 원문은 보존하고 이번 실행 증거는 [디자인 구현 기록](../plans/09_DESIGN_IMPLEMENTATION.md)에 별도로 남긴다.

S17은 1차 구현 이후 바뀐 디자인 세부와 자료를 제공한 요청이다. 사용자 직접 확인한 승인 1~5는 D19로 기록하고, 요청한 접근성 동작을 기존 코드에 연결하는 방법은 P23으로 구분한다. 원본 HTML·화면 사진을 이번에 확보했으나 사진은 헤드리스 렌더이며 실기기 캡처가 아니다. D18 당시 원본 미확보·오류 버튼 비활성 검사는 당시 이력으로 보존한다. 최신 오류 제출 동작과 새 화면 검사는 [2차 기록](../plans/10_DESIGN_SECOND_PASS.md)에 분리하며 자동·문서·브라우저 검사는 실제 실행한 범위만 보고한다.

S18은 기존 타깃과 기능 범위 안에서 디자인 방향을 선택한 요청이다. 1번의 동선 중심 구성과 3번의 혜택 쿠폰 틀 결합만 D20으로 기록하고, 구간 통합·정보 접기·생성 이미지 사용 등 구체적인 코드는 P24로 구분한다. 생성 시안은 실제 장소·혜택의 현재성·이동 가능성이나 픽셀 일치의 근거가 아니다. 현재 작업 폴더는 Git 저장소가 아니며 이전 기록·출처 사본·저장 계약을 보존한다. 이번 검사 결과는 [동선·쿠폰 개선 기록](../plans/11_ROUTE_COUPON_REFINEMENT.md)에 별도로 남기고, 진행 중인 화면 확인을 완료로 쓰지 않는다.

S19는 당시 MCP 연결·관리 화면 검토 요청으로 해석해 D21에 기록했으나, S20에서 여행 서비스 주요 화면이 목적임이 정정되었다. 당시 운영자 대상·여섯 화면·탐색 구조·메모리 시뮬레이션은 P25로 구분한다. LazyCodex/OmO의 설치된 frontend 기준과 역할별 검토 활용은 별도 `lazycodex-ai` MCP 도구를 호출하거나 실제 MCP를 연결한 결과가 아니다. 연결 후보·도구·활동 기록은 가상이며 인증 성공·실제 권한 부여·운영 시스템 상태의 증거로 쓰지 않는다. 기존 여행 시연의 이전 검사 결과는 새 와이어프레임 통과 근거로 재사용하지 않고 [이번 검사 기록](../wireframes/mcp-management/QA.md)에 직접 수행한 범위만 남긴다.

S20은 이전 산출물이 여행 서비스 주요 화면이 아니라는 사용자 정정이다. 작업자의 MCP 운영자 콘솔 해석을 바로잡아 D22를 현재 범위로 삼고, 기존 D21/P25와 파일은 잘못된 범위 해석의 이력으로 보존한다. 사용자에게 새로운 관리 제품 방향을 선택한 책임을 돌리거나 당시 구현을 여행자 주요 화면의 완료 증거로 쓰지 않는다. P26의 9개 화면·별도 메모리 시연은 여행자 흐름을 검토하기 위한 구현 선택이다. 기존 여행 MVP 저장 자료를 변경하지 않으며 새 화면의 실제 검사는 [여행 서비스 와이어프레임 검사 기록](../wireframes/traveler-service/QA.md)에 별도로 남긴다.

S21은 여행자용 와이어프레임을 검토한 뒤 기존 MVP에 적용하도록 승인한 요청이다. D23으로 적용 범위를 추가하고 구체적인 코드·탐색·배치는 P27로 남긴다. D22/P26 단계의 별도 메모리 시연 경계를 기존 MVP의 저장 방식으로 바꾸어 해석하지 않는다. 기존 도메인·공식 혜택 자료·저장 키·과거 코스는 보존하고, 실제 실행한 검사는 [MVP 적용 기록](../plans/12_WIREFRAME_TO_MVP.md)에 별도 기록한다. 이전 83개 검사나 와이어프레임의 화면 확인을 이번 MVP 검사의 통과 근거로 재사용하지 않는다.
