# 08. 로컬 최소 시연의 기술·저장 선택

## 최신 확장 — 실제 여행 계획 D24/P28 (2026-10-27)

서울 출발 춘천·가평·강릉을 대상으로 공개 출처가 있는 실제 장소 8개를 기본 추천에 연결한다. 청량리·서울·용산의 출발역 3개, 장소별 체류 계획, 출발·현지·복귀 구간을 제공한다. 아래 최초 시연·가상 자료의 결정과 검사 기록은 당시 이력이며 최신 범위는 [실제 여행 기록](../plans/13_REAL_TRAVEL.md)과 [출처 장부](13_REAL_TRAVEL_SOURCES.md)를 따른다. 별도 전달 패키지 docs 원문 미확보.

기존 HTML/CSS/JavaScript·Node.js 서버·localStorage를 유지하고, `travel-domain.mjs`·`travel-journey.mjs`·`travel-links.mjs`에서 실제 계약과 과거 예시 계약을 분기한다. 기존 저장 키·버전·요청 이력과 스냅샷을 보존하며 현재 카탈로그로 과거 저장본을 다시 계산하지 않는다. 과거 가상 코스는 ‘이전 예시 코스’로 구분한다. 화면 이동과 현재 조건 변경은 자동 저장이 아니다.

실제 장소에는 공식 주소·운영 안내·출처·확인일을 붙인다. 체류 시간은 사용 계획 제안이고 공식 소요 시간이 아니다. 확인된 정기 휴무는 해당 요일의 추천에서 제외하되 나머지 날짜의 당일 영업을 보증하지 않는다. 계단 여부 미확인을 접근성 확인으로 바꾸지 않는다. 미확인 교통비·이동 시간·도보량·총비용은 `null`로 유지하고 실제 혜택을 차감하지 않는다.

좌표가 있는 구간은 카카오 외부 대중교통/도보 길찾기를 열고, 없는 구간은 도착 장소 검색임을 명시한다. 철도 시간·좌석·운임은 코레일에서 확인한다. 앱에 실시간 경로 API를 연결하거나 교통편을 예약하지 않는다. 사용자가 지도에서 확인한 구간 시간을 직접 입력할 수 있으며 해당 값의 출처는 ‘직접 입력’이다. 모든 왕복 구간 시간이 입력된 때만 체류 계획과 합산한 전체 시간을 제공한다. 순서를 바꾸면 동일한 방향·출발/도착 구간에만 입력값을 재사용한다. 전체 시간을 계산해도 교통비·도보 거리·당일 운행이 확인된 것은 아니다.

여행자 화면에서 기술 용어·긴 개발 설명을 줄이고 주소·운영·출처는 장소 상세에 모은다. 실제 코스에 가상 장소 생성 사진을 사용하지 않는다. 동선 편집과 혜택 전용 쿠폰·명시적 설정 저장·기존 오류 안내는 유지한다. 운영 기술·계정·동기화·배포·결제·예약·실제 후기·방문 검증은 이번 확장으로 완료되지 않는다.

## 사용자 결정과 구현 선택

사용자가 결정한 것은 기준 문서를 바탕으로 상황 입력 → 경험 추천과 근거 확인 → 코스 저장·재열람을 **로컬에서 실행 가능한 최소 시연**으로 만들고, 최소 기술·저장 구성의 선택 이유와 가상 자료 표시를 남기는 것이다(D09). 배포·유료 가입·Git 커밋·푸시는 하지 않는다.

아래 기술명은 사용자가 직접 확정한 스택이 아니다. 구현자가 이번 시연을 위해 선택했다. 운영 확장 시 Q02~Q06을 다시 검토한다.

## 입력·추천의 시연 범위

최초 D09 시연은 가능 시간·관심과 선택적인 지역·동행·이동·계단 회피를 입력했다. D12 확장에서는 개인 설정과 여행 조건을 구분한다. 만 나이·거주 지역은 선택이며 성별·정밀 주소는 받지 않는다. 개인 설정의 관심·걷기 허용량을 활용하되 이번 여행의 가상 출발역·날짜·가능 시간·1인 예산·인원·도보 한도를 지역 비교 전에 받는다. 인원은 혼자 1명이 기본이다. 미정인 조건을 AI가 추측해 채우지 않는다.

가상 온유동·가상 바람마을 등 시연 지역과 경험은 전부 창작한 자료다. 경험 설명, 방문 당시 조건, 장단점, 소요 시간과 근거 ID 역시 **가상 데이터·시연용**이다. 실제 후기·운영정보·검증된 방문으로 표시하지 않는다. 근거 참조는 이 시연 자료 안의 일관성을 위한 연결이며 현실의 증명이 아니다.

규칙 기반 추천은 허용된 후보를 조건에 맞춰 거르고 정렬한 뒤, 입력 항목과 가상 근거를 연결한 이유를 보여준다. 없는 경험·근거 참조를 정상 결과로 저장하지 않는다. 후보가 없으면 조건을 몰래 완화하지 않고 0건과 재입력 경로를 보여준다. 목록·상세·저장본 모두에서 가상 표시를 유지한다.

새 여행의 이동 조건은 `walk_transit`으로 도보 또는 대중교통 경험을 함께 허용한다. 지역 비교에 잡힌 도보 전용 경험이 추천 단계에서 누락되지 않도록 같은 범위로 필터링한다. 기존 코스의 `any`·`walk`·`transit` 값과 의미는 유지하며 자동 변환하지 않는다.

외부 AI·지도·관광정보·영업 정보 API를 호출하지 않는다. AI 제공사·모델·요금은 Q06으로 남긴다. 현재 영업·대기·실제 이동 시간·방문 안전을 보장하지 않는다.

## 코스와 시간 표현

선택·제거·순서 변경·제목 편집과 저장·재열람을 연결한다. 기존 코스의 활동 시간은 가상 자료의 값을 합산하고 실제 이동 시간은 `null`/미확인으로 유지한다. D12의 추가 journeySnapshot은 가상 구간과 가격으로 시연 합계를 보여주는 별도 자료다. 시연 계산이 가능하더라도 현실의 소요 시간·귀가·예약 가능성이 확인된 것은 아니다. 활동 합계만으로 총 코스 시간이 가능하다고 표시하지 않는다.

활동 합계가 입력 시간을 넘거나 이동 시간이 없으면 그 이유를 표시하고 사용자가 경고를 확인한 초안만 저장한다. 빈 코스와 알 수 없는 경험 참조는 저장하지 않는다. 코스 저장이 예약·방문·기록 공개를 뜻하지 않는다.

가상 동선에 알 수 없는 구간이 있으면 총 시간·총 도보량은 `null`로 남긴다. 다만 이미 확인된 가상 구간의 최소 합계만으로 입력 한도를 넘었으면 제약은 `unmet`로 표시한다. 미확인 구간이 있다는 이유로 이미 드러난 초과를 `unknown`으로 낮추지 않는다. 비용은 1인 예산과 비교하며 가상/공식 혜택 할인액을 자동 차감하지 않는다.

## 저장 범위와 복구 원칙

기본 주소는 `http://127.0.0.1:4173`이다. 같은 브라우저 프로필·같은 주소로 접근하면 저장본을 새로고침·브라우저 재시작·서버 재시작 후에도 읽도록 구현한다. 이는 브라우저가 데이터를 유지할 때의 범위다. `localhost`, 다른 포트·프로필·브라우저는 다른 저장소이며 자동 이전하지 않는다.

저장본은 이 브라우저에만 있고 서버 파일로 전송하지 않는다. 브라우저 데이터 삭제, 비공개 모드 종료, 저장소 제한으로 사라지거나 쓰기가 실패할 수 있다. 백업·계정 복구·기기간 동기화는 없다. 같은 프로필을 사용하는 사람 사이의 비밀 보장도 없다. `local-browser` 소유자 표시는 단일 시연의 논리 범위이며 인증된 사용자 ID가 아니다.

저장 성공은 저장 후 다시 읽을 수 있는 상태를 뜻한다. 같은 저장 요청을 재시도하면 중복 코스를 만들지 않고, 같은 요청 키에 다른 내용이면 충돌로 처리한다. 수정은 버전을 비교해 오래된 탭의 내용으로 새 저장본을 덮어쓰지 않는다. 저장소 접근·용량·손상 오류가 나면 실패를 알리고 편집 내용을 유지한다. 손상 데이터를 자동 삭제하거나 빈 목록으로 덮어쓰지 않는다. Web Locks가 없는 환경의 처리 방식도 성공으로 위장하지 않고 제한을 알린다.

## 유지하는 미확정과 검증 범위

Q02의 실제 대상·운영 지역, Q03의 운영 스택, Q04의 인증·서버 저장·백업은 해결된 것으로 표시하지 않는다. 실제 출처 이용 권한(Q05), AI 데이터 전송·보관(Q06), 공개·철회(Q07), 방문 확인(Q08), 팀·수익·성과(Q09)도 그대로 남긴다.

검사는 [AC01~AC08](05_ACCEPTANCE_TESTS.md)의 이번 범위에 적용되는 시나리오로 한다. 계정형 전용 검사는 단일 사용자 로컬 저장 선택에 따라 해당 없음으로 기록하며, 접근 제어 통과로 계산하지 않는다. AC09~AC13의 개인 기록·공개·방문 후 확인·다음 추천 반영은 후속 단계다.

실행하지 않은 검사를 통과라고 쓰지 않는다. 이 문서는 선택·계약의 기록이며 성공 결과 자체가 아니다.

## D12 확장 선택과 이유

기존 최소 스택을 유지한다. 새 기능은 입력·규칙 비교·스냅샷 저장으로 구현할 수 있어 프레임워크·외부 AI·계정 서버를 추가할 필요가 없다. 개인 설정은 localStorage의 `growing-travel.local-profile.v1` 키에 사용자가 명시적으로 저장하거나 삭제한다. 저장하지 않은 설정으로도 진행하며, 삭제 안내에는 과거 코스에 남은 입력 스냅샷과의 차이를 표시한다.

지역 비교에는 기존 가상 온유동·가상 바람마을을 유지하고 가상 출발역·동선·도보량·가격·지역 혜택 예시를 사용한다. 이는 현재 실제 경로·혜택 API가 확보되지 않은 상태에서 선택 흐름을 검증하기 위한 구현 선택이다. 공식 혜택 정보는 [확인 범위](10_BENEFIT_SOURCES.md)에 따라 별도 안내하며, 가상 지역에 적용되거나 자동으로 비용이 절감되는 것으로 연결하지 않는다. 혜택 우선 비교는 사용자가 선택한다.

코스는 기존 `growing-travel.local-demo.v1` 키를 유지하고 선택적인 `journeySnapshot`으로 당시 설정·여행 조건·지역 비교 정보를 보존한다. 확장 전 저장본에 이 필드가 없어도 읽기·수정할 수 있으며 자동 초기화·무단 데이터 이전을 하지 않는다. 수정 전 생성한 v1 고정 자료를 사용해 기존/신규 코스 공존, 원형 재열람·수정, 새 스냅샷 보존·변조 거부를 자동 검사했다. 실제 후기·별점·게시판, 운영용 인증·데이터 보관·AI 모델 선택은 포함하지 않는다.

## D13 모바일 앱 화면 선택과 이유

사용자가 요청한 방향은 어플 개발을 우선하는 시연 화면이다(D13). 이번에는 기존 빌드 없는 HTML/CSS/JavaScript 로컬 시연에서 화면 분할·단계 이동·하단 메뉴를 구현해 앱 UX를 먼저 검증한다(P19). 이미 연결한 입력·추천·저장 기능을 활용하면서 작은 화면에서의 사용 흐름을 바꿀 수 있기 때문이다. 네이티브 앱 프로젝트, Flutter·React Native 등 운영 스택, iOS/Android 우선순위, 설치·스토어 배포를 확정한 것은 아니다.

개인 설정·여행 조건·지역 비교·경험 추천·코스 편집을 한 화면씩 보이고, 여행·저장한 코스·내 설정의 하단 탐색을 제공한다. 좁은 화면의 한 열 배치, 충분한 터치 영역, 하단 안전 영역과 콘텐츠 여백을 적용하는 것을 시연 기준으로 삼는다. 넓은 브라우저에서는 앱 화면 폭으로 미리 본다. 화면 전환은 현재 입력과 초안을 유지하며, 실제 저장은 기존의 명시적 저장 동작만 수행한다.

이번 변경은 화면 구성과 탐색에 한정한다. 기존 개인 설정 키·코스 키·가상/공식 자료 구분·추천 및 저장 계약은 유지하며 데이터 이전이나 초기화를 하지 않는다. 로컬 브라우저의 좁은 화면 검증과 스마트폰 실기기·가상 키보드·네이티브 뒤로가기 검증은 서로 다른 범위다. 검증을 수행하기 전에는 통과로 표시하지 않는다.

## D14 혜택 탭·대학생 구분 선택과 이유

추가 화면 디자인은 미루고 기존 로컬 앱에 혜택 탭을 추가한다(P20). 초기 화면에서 입력을 마치기 전에 공식 안내를 살펴볼 수 있도록 추천 흐름의 선행 조건을 요구하지 않는다. 자료는 확인한 공식 출처와 날짜를 가진 목록으로 관리하며, 외부 API·스크래핑·자동 갱신 서비스를 새로 도입하지 않는다. 이 선택은 현재 확인 가능한 범위를 그대로 보여주기 위한 최소 구성이다. 정적 목록의 한계를 감추고 실시간 진행 상태처럼 표시하지 않는다.

공식 기간이 확인되면 현재 기준일에 따른 진행 중·예정·종료를 표시한다. 상시 제도 안내만 확인했거나 현재 모집 기간을 알 수 없으면 확인 필요로 남긴다. 공식 기간상 진행 중이어도 조기 소진·개인 자격·예약 가능 여부는 별도 확인 대상이다. 실제 혜택을 가상 코스에 적용하거나 비용에서 차감하지 않는다.

대학생 여부는 `studentStatus`의 선택 안 함·대학생·대학생 아님으로 받는 구현 선택이다. 별도의 가입 단계나 재학 인증 없이 첫 개인 설정 및 내 설정에서 바꿀 수 있다. 기존 프로필 저장 키를 유지하며 필드가 없는 과거 설정·코스는 미입력 상태로 해석하고 원형을 보존한다. 당시 설정 스냅샷이 현재 개인 설정과 다를 수 있다는 기존 안내를 유지한다.

대학생만을 전체 타겟으로 확정한 것은 아니며 D10의 20대 혼자·무차량 여행 방향을 유지한다. 기관별 학적 인정 범위·증빙·개인 자격 판단·운영 갱신 정책은 Q10으로 남긴다. 선택·저장·새로고침·이전 저장본·혜택 상태·시작 화면 접근의 실제 검사 결과는 별도 기록한다.

## D15 맞춤 혜택·전달 문서 선택과 이유

기존 브라우저 모듈에서 확인된 공식 조건을 규칙으로 비교하고, 후보와 추가 확인을 먼저 보여주는 방식을 선택한다(P21). 같은 입력·같은 공식 자료가 같은 이유와 순서로 이어져야 하므로 모델 호출이나 임의 점수 대신 설명 가능한 상태를 사용한다. 후보 분류가 신청·수혜 심사가 아님을 명확히 하고 확인되지 않은 조건은 남은 확인 사항으로 제공한다.

개인별 상태와 공고 기간 상태는 분리한다. 정확한 출생연도·시군구·학생 자격을 현재의 만 나이·시도·자기 보고에서 추정해 확정하지 않는다. 학생 조건이 확인된 혜택이 없으면 대학생 입력에 따른 가점을 만들지 않는다. 근거 확보 범위에 따라 개인화가 제한되는 것은 기능의 오류와 구분해 표시한다. 저장 키와 과거 스냅샷 계약을 유지하고 비교만으로 저장하지 않는다.

클로드 전달용 제품·개발 설명과 클로드 디자인용 화면·상태·문구 명세를 별도 Markdown 파일로 준비한다. 문서만 첨부해도 핵심 방향과 경계를 이해하도록 자체 설명을 넣고 복사할 요청문을 제공한다. 새로운 서비스 가입·업로드·외부 전송을 수행하지 않으며, 디자인 결과물·프레임·네이티브 화면을 만들었다고 보고하지 않는다. 최종 시각 방향·플랫폼·서버·모델은 후속 결정이다. 실제 검사와 변경은 [맞춤 혜택 기록](../plans/07_PERSONALIZED_BENEFITS.md)에 남긴다.

## D18 디자인 전달 반영의 선택과 이유 — P22

[디자인 개발 전달](../handoff/claude/DESIGN_HANDOFF_2026-10-26.md)의 D16 여행 티켓·흑연/코발트와 D17 학생 경로 표시·필터를 기존 빌드 없는 로컬 앱에 연결한다. 비공개 Claude 캔버스의 원본이나 화면 픽셀을 확보하지 않아 문서의 구조·색·상태·접근성 주석으로 구성하며 픽셀 일치 검증을 주장하지 않는다. 전달서 원문과 이전 검사 기록은 보존한다.

혜택 요약 카드는 판단에 필요한 짧은 이유와 공고 기간을 먼저 보이고 한 번에 하나씩 펼친다. 조건 이유 전체는 네이티브 `dialog`로 제공한다. 학생 경로 여부는 공식 근거를 가진 기존 조건 규칙에서, 짧은 이유는 실제 비교 결과에서 계산한다. 별도 수동 필드나 가상의 학생 우대를 만들지 않으며 연령 또는 학생이라는 대체 경로도 유지한다. 카드 안에서 개인 조건과 공고 상태는 절취선 양쪽의 별개 정보로 표시한다.

조건 수정 시트는 원본과 분리한 초안으로 입력하고 ‘이번 비교에만 적용’과 ‘내 설정에 저장하고 비교’를 구분한다. 닫아도 미적용 시트 초안은 같은 실행 중 유지하며 새로고침 또는 현재 개인 설정 변경 때 초기화한다. 저장 실패는 성공으로 표시하지 않고 초안을 보존한다. 현재 개인 설정·관심·걷기 선호는 재열람한 과거 코스와 별도로 유지하고, 당시 코스 스냅샷을 바꾸지 않는다. 명시적 설정 저장·코스 저장 외에는 기존 저장 키에 쓰지 않는다.

공통 화면에 흑연/코발트와 5단계 진행 표시를 적용하고 저장 성공 후 목록 알림, 목록 전체 카드 링크, 빈 목록·읽기 실패 안내를 연결한다. 숫자 입력은 기존 범위를 유지하고 90% 같은 임의 ‘한도 근접’ 판정은 추가하지 않는다. 글꼴은 로컬 대체 글꼴을 사용하며 외부 폰트 로딩이나 새 패키지 설치는 하지 않는다. 구체적 구현·실행 증거와 미실행 범위는 [디자인 구현 기록](../plans/09_DESIGN_IMPLEMENTATION.md)에 남긴다. 이 선택은 네이티브 기술·최종 정보 구조·운영 디자인 시스템 전체의 확정이 아니다.

## D19 디자인 2차의 병합 선택과 이유 — P23

[2차 시작 안내](../handoff/codex-design-2026-10-26/00_START_HERE.md)와 [명세](../handoff/codex-design-2026-10-26/DESIGN_SPEC.md)의 승인 세부를 기존 로컬 시연에 필요한 부분만 병합한다. 1차와 달리 원본 HTML 23개·화면 사진 21장을 확보했지만 사진은 헤드리스 Edge 렌더이며 실제 기기·캔버스 화면의 캡처가 아니다. 픽셀 일치보다 명세의 구조·상태·표현을 기준으로 삼으며 원본의 도구 전용 템플릿 문법을 앱에 복사하지 않는다.

조건 요약은 나이·거주·학생의 이름표와 값으로 분리하고 학생 자기 보고를 ‘본인 입력’으로 표시한다. 메타 문장의 가운뎃점은 쉼표로 바꾸되 ‘거주 시·도’처럼 의미가 있는 고유 표기를 보존한다. 이유 이름표는 문장 위에 두고 실제 동선 순서가 아닌 화살표는 문장으로 바꾼다. 반원 홈은 혜택 티켓에 한정하며 지역·저장 코스는 점선으로 구분한다. 카드·입력·안내·요약칸·태그·하단 메뉴·알약 버튼의 모서리 위계를 적용하되 코발트와 로컬 대체 글꼴 방향은 유지한다.

사용자의 최신 직접 요청에 따라 시트 오류가 있어도 적용·저장 버튼을 켜 둔다. 누르면 기존 검증 계약의 오류를 필드에 연결하고 첫 오류로 초점을 옮기며 적용·저장은 수행하지 않는다. 이는 1차의 버튼 비활성 처리를 대체한다. P22의 분리된 초안·명시적 저장·Esc 닫기·초점 복귀는 그대로 유지한다. 입력 `name`·자동완성 설정, 3px 코발트 포커스, 안전 영역과 시트 스크롤 제한, 최소 글자·조작 영역 및 동작 줄이기 환경을 반영하는 구체적인 코드는 구현 선택이다.

표현을 정리하는 과정에서 혜택 판정·공식 자료 확인일·현재성 한계·저장 키·과거 코스 스냅샷을 변경하지 않는다. 현재 공식 혜택을 가상 코스 비용에서 차감하거나 디자인의 가상 수치·가상 혜택 A를 실데이터로 넣지 않는다. 이번 실제 자동·문서·390px 브라우저 검사는 [2차 기록](../plans/10_DESIGN_SECOND_PASS.md)에 분리한다. 실기기·화면 낭독기·운영 스택·최종 브랜드 전체의 확정은 포함하지 않는다.

## D20 동선 중심·쿠폰 결합의 선택과 이유 — P24

2026-10-27 사용자가 고른 [동선 시안](../plans/design-2026-10-27/source-route.png)과 [쿠폰 시안](../plans/design-2026-10-27/source-coupon.png)을 [결합 시안](../plans/design-2026-10-27/source-combined.png)으로 정리하고, 기존 로컬 `dist/`에 필요한 부분만 병합한다. 새 프로젝트나 운영 기술을 확정하지 않고 기존 추천·판정·저장 계약과 과거 코스 스냅샷을 보존한다. 작업 폴더가 Git 저장소가 아니므로 Git 비교를 수행했다고 보고하지 않으며, 이전 기준·출처와 검사 기록은 유지한다.

코스 화면의 경험 편집 목록과 별도 전체 동선 목록을 연속된 세로 경로로 통합해, 역·이동 구간·경험의 순서와 수정 동작을 함께 읽도록 한다. 상단의 가상 총시간·가상 도보·1인 예상 비용은 현재 코스의 `journeySnapshot` 계산값을 사용한다. 시안에 그려진 임의 수치나 출발·도착 시각을 복사하지 않는다. 구간 값이나 합계가 `null`이면 미확인으로 남기고 0분·0원으로 바꾸지 않는다. 스냅샷이 없는 과거 코스에서도 알 수 없는 이동·비용을 추정하지 않으며 실제 운영·교통 확인 여부는 가상 계산과 별도로 표시한다.

역·정원·서가의 래스터 이미지는 선택된 시안의 시각 방향에 맞춰 생성한 가상 시연 이미지다. 실제 역·장소 사진·방문 증거가 아니며 다른 경험에 임의 대응시키지 않는다. 기존 흑연·코발트, 모서리 위계와 조작·오류 안내를 유지하면서 여백·제목·정보 밀도를 조정한다. 혜택 쿠폰은 개인 조건과 공고 상태를 분리하는 기존 의미를 유지하고, 코스에서는 독립 혜택 탭으로 이동하는 안내로 사용한다. 코스 본체·지역·저장 카드에 혜택의 반원 홈을 확장하지 않는다.

조건 요약은 나이·거주·학생 3칸과 학생의 ‘본인 입력’을 유지한다. 설정 저장 안내와 고급 필터는 필요할 때 펼쳐 읽도록 정리하되 ‘이번 비교 적용’, ‘내 설정 저장’, ‘코스 저장’의 구분과 미적용 초안 보존·오류 제출 동작을 바꾸지 않는다. 화면을 정리한 사실이 혜택 공식 원문의 현재성 재확인·개인 수혜 확정·자동 할인 적용을 뜻하지 않는다.

이번 자동·문서·브라우저 검사와 시안 비교 결과는 [동선·쿠폰 개선 기록](../plans/11_ROUTE_COUPON_REFINEMENT.md)에 실제 수행 범위만 기록한다. 2차의 83개 검사와 이전 캡처를 새 화면의 검증 근거로 재사용하지 않는다. 실제 기기·화면 낭독기·외부 예약·결제·배포·Git 커밋·푸시는 이번 범위에 포함하지 않는다.
