# 09. 20대 혼자 뚜벅이 여행자를 위한 개발 방향

작성일: 2026-10-24. 사용자 제시 타겟 방향 D10, 혜택 범위 D11 및 승인된 현재 흐름 D12를 반영한 개발 기준. 별도 전달 패키지 docs 원문 미확보. 세부 필드·가상 자료·저장 방식은 구현자 선택 P15~P18이며, 실제 결과는 [확장 기록](../plans/04_PROFILE_TRIP_DEMO.md)에 남긴다.

## 사용자 방향과 제품 약속

사용자가 제시한 주 타겟은 **20대 청년 중 차량 없이 기차·대중교통과 도보로 혼자 여행하는 사람**이다. 추가로 정리할 혜택의 첫 범위는 사용자가 선택한 **교통·숙박·여행·문화**다. 주거·취업 등 청년 정책 전반은 이 범위에 넣지 않는다.

제안하는 제품 설명: **차 없이 혼자 떠나는 20대를 위해, 역에서 시작하는 여행과 확인할 혜택을 함께 찾는 서비스.** 기존의 경험 발견 → 상황 추천 → 코스 구성·수정 → 개인 기록 → 선택적 공개·방문 후 확인 → 다음 추천 반영 흐름은 유지한다.

20대라는 연령만으로 모든 사용자의 예산·체력·취향·혜택 자격이 같다고 가정하지 않는다. 이 방향은 우선 설계·검증할 고객군이지 다른 연령의 이용을 막는 가입 제한을 의미하지 않는다. 정확한 연령 계산 방식과 국내 운영 범위는 미확정이다. 초기에는 국내 당일 여행을 시험하는 것을 제안하며, 1박 이상은 이후 검토한다.

## 집중할 사용자 문제와 기능 제안

| 사용자 문제 가설 | 제안하는 대응 | 필요한 근거 |
| --- | --- | --- |
| 기차에서 내린 뒤 차 없이 코스를 이어갈 수 있는지 판단하기 어려움 | 도착역 → 경험 → 경험 → 복귀역 형태의 코스, 구간별 도보·대중교통 표시 | 지도/운영기관의 구간·거리·시간 정보. 없으면 미확인 |
| 여러 장소를 담다 보면 너무 많이 걷거나 환승이 늘어남 | 하루 총 도보량, 구간별 걷기, 환승 횟수, 쉬는 지점 | 경로 자료와 사용자 허용 범위. 단순 직선거리로 도보 시간 단정 금지 |
| 혼자 식사·체험하기 괜찮은지 정보가 부족함 | 1인 주문·1인 참여 조건, 혼자 머문 상황이 담긴 경험 | 운영정보와 작성자의 당시 경험을 분리. 사진만으로 추정 금지 |
| 돌아오는 교통편에 맞춰 계획을 마쳐야 함 | 사용자가 입력한 귀가/복귀 마감에 맞춘 여유 시간·초과 경고 | 여행일별 교통편 출처·확인 시점. 막차·귀가 가능을 임의 보장하지 않음 |
| 할인·지원이 나에게 해당하는지 여러 곳을 찾아야 함 | 여행과 관련된 혜택 후보, 적용 조건, 공식 확인 링크 | 연령 기준·거주지·기간·예약 조건 등. 조건 미충족과 확인 필요 구분 |

주된 가치 가설은 **혼자 차 없이 실행할 수 있는 짧은 여행을 결정하기 쉽게 만든다**는 것이다. 혜택은 그 여행의 비용·이용 조건을 판단하도록 돕는 정보다. 타겟을 좁혔다는 이유만으로 경쟁 우위나 수요가 검증된 것으로 보고하지 않는다.

## 승인된 현재 화면 흐름

1. **개인 설정:** 만 나이·거주 지역은 혜택 조건 비교에 필요한 선택 입력이다. 관심과 걷기 허용량을 설정한다. 성별은 초기 입력에서 제외한다. 저장하지 않고 진행하거나 명시적으로 이 브라우저에 저장·삭제할 수 있다.
2. **이번 여행 조건:** 거주지와 별도로 출발역을 고르고 여행일·가능 시간·1인 예산·인원·도보 한도를 입력한다. 인원 기본값은 혼자 1명이다. 지역 추천 전에 이번 조건을 받아야 이동·기간·예산을 함께 비교할 수 있다.
3. **지역·혜택 비교:** 목적지 미정으로 비교한 뒤 지역을 선택한다. 여행 적합도와 선택 가능한 혜택 우선 기준을 제공한다. 가상 지역·동선·가격·지역 혜택임을 표시하고 공식 혜택은 별도의 안내 영역에 둔다. 프로필 정보가 없으면 혜택 조건 확인 필요로 남기고 여행 비교는 계속할 수 있다.
4. **경험 추천과 근거:** 추천 이유, 역과의 연결, 혼자 이용 조건, 도보·시간 정보와 확인 상태를 본다. 모르는 구간이나 현재 운영정보를 임의로 채우지 않는다.
5. **코스 편집·저장·재열람:** 경험 선택·제거·순서를 바꾸고 경고를 확인한 뒤 저장한다. 당시 설정·여행 조건·가상 동선/혜택 비교를 스냅샷으로 보존한다. 기존 코스도 계속 열 수 있어야 하며, 저장은 예약·혜택 적용·공개를 뜻하지 않는다.

실제 평점·후기 읽기와 여행 후 솔직한 기록, 게시판은 다음 단계다. 실제 후기가 없으면 없다고 표시하고 가상 경험에 실제 별점·후기 수를 붙이지 않는다. 후속 공개 후기에는 후기 수·방문 시기·동행/이동 조건을 함께 보여주고 작성자 방문 진술과 별도 확인 자료를 구분한다.

후속 여행 기록에는 실제로 걸은 부담, 환승의 어려움, 혼자 이용한 조건, 계획 변경 이유를 선택적으로 남기도록 제안한다. 감상·자기 보고·외부 확인을 분리하고 공개 동의 원칙을 유지한다.

## 혜택 데이터·표시 계약 제안

혜택마다 명칭, 운영기관, 분류, 적용 교통/활동, 연령 기준과 기준일, 거주 조건, 신청/사용 기간, 사전 가입·인증, 예산·좌석 제한, 중복 조건, 공식 URL, 확인일, 확인한 범위, 확인 불가 항목을 기록한다. 상세 출처 조사는 [혜택 출처 장부](10_BENEFIT_SOURCES.md)에 분리한다.

표시 상태는 `조건 확인 필요 / 입력 조건상 후보 / 알려진 조건 불일치 / 기간 종료 / 원문 확인 불가`를 제안한다. 입력 조건상 후보도 기관의 자격 심사·발급·좌석 보장을 뜻하지 않는다. 연령·거주지 정보가 없으면 대상을 확정하지 않는다. 연령 또는 출생연도와 시·군·구 등 필요한 최소 정보만 선택적으로 받고, 주민등록번호·신분증·정밀 주소 인증은 공식 서비스에서 수행한다.

신청 기간, 여행일의 이용 가능 기간, 공식 페이지 확인일은 별개의 값이다. 예전 공고나 검색 색인만 확인한 항목을 현재 신청 가능으로 표시하지 않는다. AI는 원문 요약을 보조할 수 있지만 혜택·조건·할인율·신청 상태를 새로 만들어내지 않는다. 실제 할인 좌석·예산·중복 여부를 확인하기 전에는 예상 절감액을 코스 총비용에서 자동 차감하지 않는다.

실제 공식 혜택 정보와 가상 여행 카드는 별도 자료 유형이다. 현재의 가상 온유동·가상 바람마을, 창작 경험에 실제 혜택이 적용된다고 연결하지 않는다.

## 현재 로컬 확장과 후속 과제

D12에 따라 아래 범위를 기존 시연에 연결한다. 실제 구현 파일·검사 결과는 [확장 기록](../plans/04_PROFILE_TRIP_DEMO.md)에서 구분한다.

- 현재 입력 → 경험·근거 → 코스 저장 흐름 앞에 **개인 설정 → 이번 여행 조건 → 가상 지역·혜택 비교**를 추가한다. 가상 역 출발·복귀, 혼자 기본값, 무차량, 도보 허용량을 반영한다.
- 가상 구간 자료는 화면과 저장본에서도 가상이라고 표시한다. 실경로·실시간 교통 연동 없이 현실의 소요 시간·복귀 가능성을 주장하지 않는다.
- 별도 **혜택 안내 영역**에 소수의 공식 정보와 확인 상태·공식 이동 링크를 제공한다. 첫 버전은 안내·후보 확인까지로 한정하고 개인별 확정 할인 계산은 제외한다.
- 저장 구조를 바꾸면 기존 localStorage 코스를 읽는 호환 또는 명시적 이전 절차를 먼저 설계한다. 기존 저장 데이터를 초기화하지 않는다.
- 정상 입력, 이동 정보 없음, 걷기 한도 초과, 복귀 시간 불명, 대상 연령 경계, 거주 정보 없음, 종료/접근 불가 출처, 가상 코스와 실제 혜택의 혼동, 기존 코스 재열람을 검증한다.

후속 게시판은 코스 후기·뚜벅이 질문/이동 팁·혜택 변경 제보를 중심으로 제안한다. 개인 기록을 선택적으로 공개 후기와 연결해 중복 작성을 줄이되, 계정·수정·삭제·신고·운영 절차와 실제 자료 확보를 함께 준비한다. 이번 로컬 확장에는 이 기능을 구현하지 않는다.

## 검증할 가설과 남은 선택

사용자에게 최근 혼자 차 없이 떠난 여행에서 막힌 선택을 물어보고, 같은 여행을 이 흐름으로 계획하게 해 본다. 관찰할 것은 이동 부담을 이해했는지, 실제로 갈 만한 코스를 골랐는지, 혜택을 수혜 확정으로 오해하지 않는지다. 조사 인원·일정·성공 수치는 아직 확정하지 않았고 인터뷰·실사용 검증도 수행하지 않았다.

초기 출발권역·목적지역, 당일/1박 범위, 역·보행 경로 자료 확보, 혼자 이용 조건 확인 방식, 혜택 원문 갱신 담당·주기, 신청 상태를 확인할 방법이 남아 있다. 경쟁 서비스와의 실제 비교 검증도 아직 수행하지 않았다.
