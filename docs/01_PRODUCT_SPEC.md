# 01. 제품 명세

상태: CODEX_START와 PDF S05, D12 승인 흐름 및 D13~D14 후속 요청을 반영한 기준. 별도 전달 패키지 docs 원문 미확보. 사용자 결정은 [결정 장부](00_DECISIONS_AND_SOURCES.md)의 D 항목이며, 상세 요구사항과 시연 기술 선택은 P01~P20으로 구분한다.

## 제품 목적

Growing Travel은 여행자가 경험을 발견하고 자신의 상황에 맞는 짧은 여행을 구성한 뒤, 남긴 기록을 다음 추천에 활용하는 서비스다(D01). 경험은 장소 이름뿐 아니라 무엇을 했는지, 어떤 상황에 적합했는지, 무엇이 확인되지 않았는지를 함께 설명하도록 제안한다. 공개는 선택이며(D08), 개인 기록을 남겼다는 이유만으로 타인 추천에 사용하지 않는 방향은 확보된 전달 자료 S02와 구현 제안 P04에 따른다.

사용자가 제시한 우선 타겟 방향은 **20대 청년의 혼자·무차량·기차/대중교통·도보 여행**이다(D10). 교통·숙박·여행·문화 혜택 정보를 먼저 정리한다(D11). 구체적인 출발권역·지역·여행 길이·연령 기준은 Q02, 혜택 갱신·적용 조건은 Q10으로 남긴다. 외국인 전용 한국 여행 플랫폼, 한일 업체 컨시어지, 자동 예약·결제 대행은 범위 밖이다(D02).

PDF 1~6쪽은 일반 여행자를 대상으로 목적지가 정해지지 않은 경험 탐색도 제안한다. 경험 카드는 장소·활동, 방문 당시 조건, 좋았던 점·아쉬움, 출처로 구성한다(P02, P09). 함께 쌓이는 경험 선택지와 개인 맞춤 추천은 별도로 개선·검증하며, 후기 수 증가만으로 개인화 향상을 주장하지 않는다(P12).

그중 우선 타겟을 좁혀 역과 경험의 연결, 도보 부담·환승, 혼자 이용 조건과 확인할 혜택을 다루는 방향을 [타겟 개발 방향](09_TARGET_FOCUS.md)에 정리했다. D12에 따라 개인 설정 → 여행 조건 → 지역·혜택 비교 → 코스 추천·저장·재열람을 현재 로컬 시연 범위로 확장한다. 실제 혜택과 가상 지역·경험·혜택의 출처를 구분한다. 기존 F01~F08과 새 흐름의 검사 결과는 실제 실행 증거를 기준으로 기록한다.

## 첫 구현 범위

최초 입력 → 후보/근거 보기 → 선택/순서 수정 → 코스 저장/재열람(D06, P01)에 D12의 개인 설정·지역 비교를 연결한다. 개인 설정은 선택적인 만 나이·거주 지역과 D14의 대학생 여부, 관심·걷기 허용량을 포함한다. 대학생 여부는 자기 보고이며 선택하지 않아도 진행할 수 있다(P20). 성별은 초기 수집 항목에서 제외한다. 거주지와 이번 출발역을 구분하고 혼자 1명을 기본으로 둔다. 여행일·가능 시간·1인 예산·인원·도보 한도를 지역 비교 전에 입력한다. 개인 설정의 브라우저 저장은 명시적 선택이며 저장하지 않고 진행할 수 있다.

지역 비교는 여행 적합도와 사용자가 선택하는 혜택 우선 기준을 제공한다. 가상 지역의 가상 혜택으로 조건 비교를 시연하고, 실제 공식 혜택은 출처·확인일·미확인 상태를 갖춘 별도 안내로 제공한다. 혜택이 없는 후보도 감추지 않으며 미확인 자격을 적용 확정으로 표시하거나 비용에서 자동 차감하지 않는다. 상세 확장 수용 항목은 [확장 기록](../plans/04_PROFILE_TRIP_DEMO.md)에 둔다.

D14의 혜택 탭은 첫 실행부터 열 수 있는 독립 탐색 경로다. 개인 설정·여행 조건을 완료하지 않아도 교통·숙박·여행·문화의 공식 안내를 볼 수 있어야 한다. 공식 자료에 명시된 기간과 확인 기준일에 따른 진행 중·예정·종료를 구분하며, 상시 제도 소개만 확인했거나 현재 신청 가능 여부가 불명확하면 확인 필요 상태를 표시한다. 확인된 진행 중 항목이 없으면 0건과 확인할 안내를 표시하며 가상 혜택으로 채우지 않는다. ‘진행 중’도 조기 소진·개인 자격·실제 예약 가능을 보증하지 않는다. 이번 구현에서는 기존 화면에 기능을 추가하고 세부 화면 디자인은 후속으로 미룬다(P20).

저장 시 예약·결제·방문 확인·기록 공개는 발생하지 않는다. 실시간 영업 여부, 가격, 정확한 이동 시간, 예약 가능 여부를 출처 없이 단정하지 않는다(P03). 실제 평점·후기 열람과 후기 작성·게시판은 다음 단계로 남기며, 현재 가상 경험에 실제 별점이나 가짜 후기 수를 붙이지 않는다.

추천 0건, 일부 조건 불충족, 응답 지연/오류, 저장 실패를 정상적인 분기로 설계한다. 조건을 몰래 완화하거나 허위 후보를 채우지 않는다. 입력 수정은 사용자가 결정한다. 코스가 가능 시간과 충돌하거나 이동 시간이 없으면 해당 상태와 이유를 표시한다.

## 정보 품질과 개인정보

- 출처 유형·관측 시점·확인 범위를 노출한다. 자료가 없으면 확인 필요로 표시한다.
- 대학생 여부는 선택 안 함·대학생·대학생 아님을 구분하고 학교명·학생증·재학 증빙을 수집하지 않는다. 대학생 선택만으로 실제 혜택 대상이라고 확정하지 않으며 기관별 연령·거주·학적·신청 조건을 별도로 확인한다.
- 가상 데이터와 그 데이터로 만든 추천·코스에는 가상/시연 표시를 유지한다(D07).
- 비공개 기록은 소유자의 추천에만 사용할 수 있다. 다른 사람에게 노출하거나 다른 사람의 추천 후보로 쓰려면 별도의 유효한 공개·활용 동의가 필요하다(P04).
- AI 설명은 근거가 있는 입력·경험 필드를 가리킨다. AI 출력 자체는 방문 또는 운영정보 검증 근거가 아니다(P03, P06).
- 열람·저장·동의 변경 등 행동은 곧바로 취향이나 만족으로 확정하지 않는다(P08).
- 과거 경험을 현재 영업·대기·실제 이동·방문 안전의 보장으로 바꾸지 않는다. 광고성 순위 구매와 일반 추천을 분리하고, 공개 자료의 수정·신고·검토를 제공하는 것은 후속 운영 제안이다(P11).

## 맞춤 혜택과 디자인 전달 — D15

공식 혜택 탐색은 나이·거주 시·도·대학생 여부와 공식 근거가 있는 조건을 비교해 우선 순서를 제공한다(P21). 사용자가 입력하지 않은 값은 불일치가 아닌 미확인이다. 확인된 개인 조건이 맞는 후보와 추가 확인이 필요한 항목을 구분하고, 알려진 조건 불일치·현재 기간 아님도 이유와 함께 별도로 볼 수 있게 한다. 개인별 상태와 공고의 진행 상태를 각각 표시하며 ‘추천됨’을 ‘신청 가능·지원 확정’으로 읽게 만들지 않는다.

후보는 현재 비교 가능한 개인 조건이 맞는다는 뜻이다. 가입·대상 인증·소득·과거 수혜·지역 예산·재고·실제 사용처 등 비교하지 않은 조건은 남은 확인 사항으로 제공한다. 공식 조건이 출생연도·시군구·기관별 재학 범위를 요구하면 만 나이·시도·대학생 자기 보고만으로 이를 채우지 않는다. 여행 목적지 조건은 거주지 조건으로 바꾸지 않는다. 학교명이 없다는 이유로 전체 혜택 열람을 막지 않으며, 학생 조건이 확인되지 않은 사업에 학생 가점을 만들지 않는다.

클로드 및 클로드 디자인 전달 자료는 제품·개발 기준, 모바일 화면 명세, 상태별 문구·가상 예시와 복사할 요청문으로 준비한다. 현재 구현 기능과 후속 디자인 제안을 구분하고, 운영 스택·AI 모델·네이티브 플랫폼을 확정한 것처럼 쓰지 않는다. 실제 후기·게시판·예약·결제는 전달 자료에서도 후속 범위로 유지한다. 자료 작성 후 외부 서비스로 전송하거나 디자인 도구를 실행하는 것은 이번 작업에 포함하지 않는다.

## 성공 판단

첫 구현의 완료는 AC01~AC08의 적용 가능한 시나리오 통과와 저장된 코스 재열람으로 판단하는 것을 제안한다. 계정형 전용 검사의 적용 여부는 Q04 선택에 따라 명시한다. 추천 이해도·코스 저장 성공률·방문 수·검증된 후기 수 같은 성과는 현재 측정하지 않았다. 연구 대상, 지표 정의, 목표 수치는 Q09로 남긴다.
