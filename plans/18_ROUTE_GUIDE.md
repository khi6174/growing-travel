# 앱 안 길 안내 (D55·P79)

상태: 2026-11-05. 사용자 지적(카카오맵으로 나가면 앱의 본질이 흐려짐)에 따라 따라가기·코스 카드의 길찾기를 앱 안 길 안내로 바꿨다.

## 시험(구현 전)

| 항목 | 결과 |
| --- | --- |
| 서울 걷는 길(Overpass, 좌표만) | 65MB, 1분. 길 12만 개, 지점 54만 개, 98.7%가 하나로 이어짐 |
| 그래프 파일 | 16.2MB, 만드는 데 1초 |
| 서버 메모리 | 읽은 뒤 약 32MB 증가, 읽는 데 0.03초 |
| 경로 계산 | 무작위 300m~2km 300건 평균 0.2ms, 가장 느린 것 1.6ms. 경복궁역→경복궁 790m, 안국역→북촌한옥마을 870m, 성수역→서울숲 2.1km, 명동역→N서울타워 1.8km(직선의 1.1~1.6배) |
| 지도에 그려 본 경로 | 효자로·소파로·남산 산책길 등 실제 길을 따라감. 경복궁은 목적지 점이 궁 안이라 서쪽 문으로 들어감 |

## 만든 것

- `scripts/walk-graph.mjs`: 그래프 만들기·저장·읽기, 길 붙이기(300m 안), A* 길찾기, 단계(길 이름·종류·회전) 묶기, 선 단순화.
- `scripts/build-walk-graph.mjs`: 서울을 8칸으로 나눠 Overpass에서 받고(바쁘면 다른 공개 서버로, 요청당 3분 제한) `data/walk/seoul-walk.bin`과 `.json`(만든 때·OSM 기준 시각·개수·라이선스)을 쓴다. `data/walk/`는 Git에 넣지 않는다.
- `scripts/transit.mjs`: 카카오 대중교통 응답에서 단계별 안내(`steps`)를 함께 꺼낸다.
- `POST /api/route`: `{ mode, from, to }` → 걷기면 `walk`(거리·분·선·단계), 대중교통이면 `transit`(분·환승·요금·단계). 서울 밖 점은 400.
- `dist/route-guide.mjs`·`#route-dialog`: 지도(카카오, 선·출발·도착), 출처 표기, 단계 목록, 맨 아래 작은 카카오맵 링크. `dist/kakao-sdk.mjs`로 살아 있는 지도와 SDK를 함께 쓴다.
- 번역: 단계 문장·회전·방위 8개 등 37줄.
