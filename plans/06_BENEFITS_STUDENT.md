# 초기 혜택 탭·대학생 설정 확장

작성일: 2026-10-24 (Asia/Seoul). 사용자 결정 D14와 구현 선택 P20의 기록. 세부 화면 디자인은 후속으로 미루고 기존 로컬 앱에 기능만 추가한다. [직전 모바일 시연 기록](05_MOBILE_APP_DEMO.md)과 이전 검사 보고서는 보존한다.

## 요청과 구현 경계

사용자는 초기 화면에서 혜택 탭으로 진행 중인 혜택을 보고, 처음 시작하거나 개인 정보 설정에서 대학생 여부를 구분하기를 요청했다. 대학생 전용 서비스로의 전환·학교 인증·자동 수혜 판정은 요청하지 않았다.

P20의 선택은 초기 화면부터 열 수 있는 독립 혜택 탭과 선택적 대학생 자기 보고다. 기존 모바일 흐름과 저장소를 유지하며 새 프레임워크·AI 모델·네이티브 스택을 확정하지 않는다. 실제 후기·평점·게시판은 후속이다. 배포·유료 가입·Git 커밋·푸시·외부 예약과 결제는 수행하지 않는다.

## 점검과 보존

- 부모 에이전트가 기존 AGENTS·README·프로젝트 파일과 `git status --short`를 확인했다. Git 저장소가 아니라는 응답으로, Git diff로 사용자 변경을 분리할 수 없으므로 파일을 읽고 필요한 부분만 병합한다.
- 기존 프로필 `growing-travel.local-profile.v1`, 코스 `growing-travel.local-demo.v1` 키와 이전 저장 자료를 유지한다. 대학생 필드가 없는 저장본도 읽기·수정·재열람이 가능해야 한다.
- 개인 설정은 명시적 저장만 수행하고, 설정 변경이 과거 코스 스냅샷을 자동 갱신하지 않는다. 미입력은 비대학생과 구분한다.
- 기존 가상 지역·경험·동선·가격·혜택 및 원문 사본은 보존한다. 공식 혜택을 가상 장소에 적용하거나 비용에서 차감하지 않는다.

## 기능과 데이터 기준

| 항목 | 이번 기준 |
| --- | --- |
| 초기 혜택 진입 | 개인 설정·여행 조건을 완료하지 않아도 혜택 탭을 열 수 있음. 여행·저장 코스·내 설정을 오가도 입력과 초안 유지 |
| 대학생 여부 | 선택 안 함(`unspecified`) / 대학생(`student`) / 대학생 아님(`not_student`). 선택적 자기 보고, 학교명·학생증·재학 증빙 수집 없음 |
| 설정 호환 | 과거 필드 부재는 미입력으로 해석. 읽기만으로 원형을 다시 쓰지 않고 허용하지 않은 새 값은 거부 |
| 코스 호환 | 대학생 필드가 없는 기존 개인 설정 스냅샷과 신규 스냅샷을 함께 지원. 과거 자료의 원형·근거·버전·순서 유지 |
| 공식 진행 상태 | 확인한 공식 기간과 기준일로 진행 중·예정·종료를 구분. 상시 소개 또는 현재성 불명확은 확인 필요. 신청 기간과 사용 기간을 혼동하지 않음 |
| 사실의 한계 | 확인일·공식 링크·대상·미확인 사항 표시. 진행 중도 잔여 예산·개인 자격·예약 가능 보증이 아니며 대학생 여부 하나로 자격 확정하지 않음 |
| 없는 자료 | 현재 진행을 확인한 항목이 없으면 0건을 표시. 과거 안내나 가상 혜택으로 현재 혜택 수를 채우지 않음 |

공식 안내 6개 중 확인일 2026-10-24 기준 숙박세일 페스타·청년문화예술패스 추가 발급 2개는 **공고 기간 중**, K-패스는 **상시 제도 안내**, 청소년드림·힘내라청춘·내일로 YOUTH는 **진행 확인 필요**다. 공고 기간 안이라는 사실이 현재 접수·잔여 예산을 보장하지 않는다. 조사 중 찾은 2019년 대학생 버스 할인 FAQ는 현재 운영이 확인되지 않아 화면 목록에 추가하지 않았다. 대학생 선택은 자기 보고를 보관하며, 이번 등록 목록을 학생 전용으로 필터링하거나 수혜 확정에 사용하지 않는다.

탭 진입·필터 변경·탭 복귀 때 한국 날짜로 공고 기간을 계산하고, 혜택 화면이 계속 열려 있으면 1분마다 날짜 변경 여부를 확인한다. 이는 로컬 날짜 비교이며 공식 자료 자동 갱신이 아니다. 자료 확인일과 오늘 날짜가 다르면 당일 재확인하지 않았음을 추가로 표시한다.

브라우저에 남아 있던 가상 코스 2개의 제목·순서·버전을 그대로 보존했다. 대학생 선택은 검사용 값이며 사용자의 실제 학적을 의미하지 않는다. 저장·복원 검사를 마친 후 기존 설정의 다른 값은 유지하고 대학생 여부만 원래의 미입력으로 되돌려 저장했다. 새 코스를 추가하거나 기존 코스를 덮어쓰지 않았다.

360×800 뷰포트에서 혜택 탭의 문서 너비와 스크롤 너비가 모두 345px(세로 스크롤바 제외)이었고, 하단 메뉴 4개는 각각 약 78×60px였다. 가로 넘침 없이 필터·공고 기간·공식 출처 링크·하단 혜택 메뉴를 확인했다. [혜택 탭 화면](06_BENEFITS_TAB.png)을 저장하고 뷰포트는 원래 크기로 복원했다. 실제 스마트폰·가상 키보드 검사는 수행하지 않았다. 검사 서버는 확인 후 종료하며 `node scripts/serve.mjs`로 다시 실행한다.

## 미확정 사항과 다음 범위

공식 자료의 운영 갱신 담당·주기, 조기 종료/예산 소진 수집, 기관별 대학생 인정 범위·증빙, 개인 자격 인증과 수혜 판정은 Q10으로 남긴다. 다음 구현은 실제 지역과 학생 관련 혜택을 확보한 뒤 자격 조건·갱신 계약을 보완하는 것이다. 세부 화면 디자인, 실기기 검증, 네이티브 기술, 실제 후기·게시판은 후속이다.
