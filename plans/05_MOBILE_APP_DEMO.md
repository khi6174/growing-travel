# 모바일 앱 중심 시연 화면

작성일: 2026-10-24 (Asia/Seoul). 사용자 방향 D13과 구현 선택 P19의 후속 기록. 별도 전달 패키지 docs 원문 미확보. [직전 시연 기록](04_PROFILE_TRIP_DEMO.md)과 최초 plans/01~03 및 과거 검사 보고서는 보존한다.

## 사용자 요청과 이번 선택

사용자는 시연 화면을 구성할 때 어플 개발 위주로 진행해 달라고 요청했다. 스마트폰 앱의 사용 흐름을 우선하는 방향은 D13으로 기록했다. 이를 위해 기존 로컬 웹 시연을 단계별 단일 화면과 하단 탐색 메뉴로 구성하는 것은 구현자 선택 P19다. 특정 네이티브 기술·운영체제·스토어 출시를 사용자 확정 사항으로 취급하지 않는다.

개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험 추천·근거 → 코스 편집·저장·재열람이라는 D12 기능을 유지한다. 실제 후기·별점·게시판과 공개·예약·결제는 후속 범위이며 이번에 추가하지 않는다. 배포·유료 가입·Git 커밋·푸시를 하지 않는다.

## 점검과 보존 범위

- 기존 AGENTS·README·화면 흐름·기술 선택·프로젝트 파일을 읽고 필요한 부분만 병합한다. `git status --short`는 Git 저장소가 아니라고 응답했다. Git diff에 의한 사용자 변경 구분은 할 수 없으므로 기존 내용을 읽고 보존한다.
- 기존 HTML/CSS/JavaScript·Node.js 로컬 서버·localStorage 구성을 유지한다. 모바일 앱용 화면을 검증하기 위해 네이티브 빌드 도구나 새 프레임워크를 도입하지 않는다.
- 개인 설정 `growing-travel.local-profile.v1`, 코스 `growing-travel.local-demo.v1` 및 기존 도메인/저장 계약은 유지한다. 화면 이동이 데이터 이전·초기화·자동 저장을 뜻하지 않는다.
- 출처 사본, 가상 지역·역·경험·동선·가격·혜택과 별도 공식 안내의 구분을 유지한다. 가상 화면 검증을 실제 방문·혜택 적용의 근거로 사용하지 않는다.

## 화면 구성 기준

| 항목 | 이번 시연의 구현 기준 |
| --- | --- |
| 화면 진행 | 개인 설정·여행 조건·지역 비교·경험 추천·코스 편집을 한 단계씩 표시. 다음·이전 이동에서 현재 입력·초안 유지 |
| 하단 탐색 | 여행·저장한 코스·내 설정 세 메뉴. 여행 흐름과 저장 목록을 오가도 현재 작업 보존 |
| 입력과 결과 경계 | 잘못된 입력은 해당 화면에서 안내. 선행 조건이 없는 결과 화면으로 건너뛰지 않으며 조건 변경 후 이전 결과를 현재 추천으로 표시하지 않음 |
| 작은 화면 | 360~430px 같은 대표적인 좁은 폭을 기준으로 한 열 카드·읽기 쉬운 입력·손가락 조작 영역을 확인. 넓은 화면에서는 앱 폭으로 표시 |
| 고정 영역 | 하단 메뉴와 주요 동작이 콘텐츠·오류·저장 안내를 가리지 않도록 여백 확보. 안전 영역을 고려하되 실기기 확인 전 보장하지 않음 |
| 근거와 저장 | 상세 확인에서 복귀 시 선택 상태 유지. 코스 저장·새로고침 재열람·기존 저장본 호환 유지 |

세부 너비·메뉴·주요 버튼 배치는 구현 선택이다. 실제 지원 기기 범위와 운영 디자인 시스템은 미확정이다.

## 실제 수행 결과

2026-10-24 현재 변경 후 `node --test tests/*.test.mjs`를 실제 실행해 46개 통과, 실패·건너뜀 0개를 확인했다. 기존 41개 회귀 검사와 화면 진입 규칙 5개를 포함한다. `node --check dist/app.mjs`, `node --check dist/navigation.mjs`도 실행했다. 브라우저에서 수집한 오류·경고 로그는 빈 배열이었다. 이 결과는 실행한 로컬 환경 범위의 증거다.

문서 병합 후 `node scripts/check-docs.mjs` 1차 결과는 Markdown 19개·로컬 참조 145개·정의 76개·기존 수용 기준 13개, failures 0개, 출처 사본 2개의 SHA-256 일치였다. 결과 기록을 추가한 뒤에는 아직 생성 전인 새 보고서 링크 1개가 누락으로 잡혔다. 보고서를 생성한 후 재검사했고, 최종 결과는 Markdown 19개·로컬 참조 156개·정의 76개·기존 수용 기준 13개, failures 0개, 출처 사본 2개 일치다. 별도 JSON에 보관하며 과거 검사 JSON은 덮어쓰지 않는다.

브라우저에서는 개인 설정 → 조건 → 가상 온유동 비교 → 추천 근거 → 코스 편집 → 저장 목록 → 새로고침 → 다시 열기를 실행했다. 검사용 코스 `모바일 시연 확인 · 가상 온유동`을 추가했고 기존 `시연 확인 · 온유동 하루` 버전 2는 보존했다. 검사용 개인정보는 따로 저장하지 않았으며 새 코스에는 나이·거주 지역 공란, 예산 45,000원·걷기 55분과 변경한 서가→정원 순서가 저장됐다. 브라우저 뒤로가기는 코스에서 추천으로 복귀했고 2개 선택을 유지했다. ‘본문으로 이동’ 실행 후 `#trip`을 유지하며 `main`에 초점이 이동한 것을 DOM으로 확인했다.

반응형 검사는 인앱 브라우저의 임시 뷰포트로 수행했다. 개인 설정·코스 편집은 360·390·430px에서 문서 너비와 스크롤 너비가 각각 345·375·415px로 일치했고(15px 세로 스크롤바 제외), 표시된 버튼 높이가 모두 44px 이상이었다. 여행 조건·지역 비교는 360px, 경험 추천·근거 상세는 390px에서 화면을 확인했다. 추천 화면의 코스 확인 버튼 아래와 하단 메뉴 위 사이에는 15px 간격이 있었다. 고정 메뉴 때문에 페이지 끝이 가리지 않도록 여백을 유지했다. 검사 후 뷰포트는 원래 크기로 복원했다.

화면 증거: [390px 추천 화면](05_MOBILE_APP.png). 검사 서버는 확인 후 종료하며, 재실행 방법은 README와 같다. 저장하지 않은 입력·초안은 새로고침으로 초기화될 수 있고, 명시적으로 저장한 자료만 다시 열린다.

네이티브 앱 빌드·설치·스토어 등록, 실제 스마트폰의 가상 키보드·안전 영역·하드웨어 뒤로가기, 기기간 동기화는 수행하지 않았다. 로컬 웹 시연을 설치형 앱 완성으로 보고하지 않는다.

## 남은 선택

실제 지원 운영체제·기기, 네이티브 또는 웹 기술 선택, 운영 인증·서버 저장·오프라인 정책, 실지역·경로·혜택 정보 확보, 실제 후기·게시판 운영은 후속 결정이다. 이번 작업은 기존 최소 기능을 앱 사용 흐름으로 검증하기 위한 단계다.
