## 단계 2·3 — 화면과 AI 추천 (P35, P36, P38)

- 홈: "펫이랑 걸어서 만나는 서울", 펫 5종 바로가기, "펫 고르고 출발하기". 춘천·가평·강릉 영역과 "여행 계획하기"는 홈에서 숨김(코드·저장한 코스·혜택 탭 유지).
- `pet` 화면: 펫 5종 선택, 현재 위치 사용(선택, 약 100m 단위, 서울 밖이면 사용 안 함, 저장 안 함).
- `ai` 화면: 출발 위치(현재 위치 또는 역 16곳), 쓸 수 있는 시간, 인원, 걷기, 출발 시간대(낮·저녁, P35의 추가 선택).
- `GET /api/catalog`(펫·구·친구, 장소 제외), `POST /api/recommend`: 목적 태그 + 추정 60분 안 → 상위 20곳 → AI 3곳(순위 원칙 1~4 순서, 펫 말투) → 20곳 밖·중복·빈 항목 제거 → 부족·실패·10초 초과·키 없음은 규칙 정렬로 채움. 출력은 명세 2-4의 JSON 형식.
- `ai-results` 화면: 카드 3장(이름·구·"약 N분(추정)", 펫 얼굴과 말투 이유, 태그, 가는 법, 현장 소식, 동네 친구 힌트) → 기존 상세 창·현장 제보·확인·점수.
- 현장 제보에 유효시간을 더했다(P36). 붐빔·휴무·공사 소식이 유효한 동안 그 장소는 뒤로 밀린다.
- Claude 호출부는 현재 API 형식(`anthropic-version: 2026-10-21`, `fallbacks: "default"`, `output_config.format`)을 확인하고 유지했다. `max_tokens`는 16000으로 올렸고 시간 초과 기본값은 10초로 바꿨다.

## TourAPI 좌표 대조 (2026-11-02, 키를 받은 뒤)

사용자가 받은 TourAPI 키를 `.env`에 직접 넣었다. 처음에는 AI 키 줄에 들어가 있어(형식으로 확인, 값은 보지 않음) 사용자가 `TOURAPI_KEY` 줄로 옮겼다. 키는 출력·기록하지 않았다.

- 호출: 키 확인 1회, 장소 이름 148회, 결과가 없던 곳의 다른 검색어 82회, 고른 검색어 확인 19회, 마지막 `--write` 148회. 모두 응답했고 실패 0. 중간 결과는 저장소 밖 임시 폴더에 두고 일치 규칙을 다듬었다.
- 처음 규칙(이름 일부가 같은 가장 가까운 결과)은 실제 응답에서 행사(경복궁 생과방, 종묘대제), 지점 상점(로우로우 광장시장점, 올리브영 서래마을점), 부속 시설(국립중앙박물관 어린이박물관)을 골랐다. 그래서 규칙을 고쳤다(P37): 행사·코스·숙박 제외, 제목이 같은 결과 우선, 상점·음식점은 제목이 같을 때만.
- 이름으로 검색되지 않는 35곳은 `tourapi_keyword`에 TourAPI 제목을 넣었다(예: 최순우옛집 → "최순우 옛집", 서울로7017 → "서울로 7017", 노량진수산시장 → "노량진수산물도매시장").

### 휴대폰 첫 시도 (2026-11-02)

사용자가 "휴대폰 먼저 확인"을 골라 `--lan` 서버를 켰다(`.claude/launch.json`의 `growing-travel-lan`). 처음 드린 주소는 휴대폰에서 열리지 않았다. 원인은 두 가지였다(노트북 설정은 읽기만 했다).

1. 서버를 켠 뒤 노트북 와이파이가 bluepot-5G로 바뀌어 주소가 172.121.245.162에서 172.30.1.91(사설 대역)로 달라졌다. 서버와 인증서는 켤 때의 주소만 안다. 그래서 인증서를 다시 만들고 서버를 재시작했다. 노트북에서 새 주소로 접속하면 인증서 이름 검사를 통과하고, 코드 없이 403, 코드 주소는 303이 된다.
2. Windows 방화벽에서 `C:\Program Files\nodejs\node.exe`의 수신 허용은 '개인' 프로필만 켜져 있다. bluepot-5G는 '공용'으로 잡혀 있어 휴대폰 접속이 막힌다. 네트워크 프로필이나 방화벽 규칙을 바꾸는 것은 사용자가 판단할 일이라 바꾸지 않았다.

서버 시작 문구와 [팀 인수인계](../handoff/TEAM_HANDOFF.md)에 주소 변경·방화벽·기기 간 차단 점검 순서를 더했다.

이어서 사용자가 노트북을 휴대폰 핫스팟(HHH HOTSPOT, 노트북 10.155.128.90)에 연결했다. 인증서를 다시 만들고 서버를 재시작했지만, 핫스팟도 '공용'으로 잡혀 방화벽에 막혔다. 사용자가 네트워크 유형을 직접 '개인'으로 바꾼 뒤 **휴대폰에서 페이지가 열렸고, 인증서 경고를 넘겨 위치를 허용하자 구 도착 알림으로 동네 친구가 나타났다(사용자 보고)**. 휴대폰 기종·브라우저, 감지된 구, 현장 질문·도감 등록까지 진행했는지는 기록하지 않았다.

### 카카오맵 연결 (키를 받은 뒤)

사용자가 카카오 앱(growing-travel)을 만들고 JavaScript 키를 `.env`의 `KAKAO_JS_KEY`에 직접 넣었다(형식만 확인: 32자리 16진수).

1. 처음에는 카카오가 거절했다: 키 없이 요청하면 `App(growing-travel) disabled OPEN_MAP_AND_LOCAL service.`, 이 주소로 요청하면 `domain mismatched! caller=http://localhost:4183`. 사용자가 카카오맵 사용 설정을 켜고 JavaScript SDK 도메인 세 개를 등록하자 세 주소(`http://localhost:4183`, `http://localhost:4173`, `https://10.155.128.90:4443`) 모두 200으로 응답했다. IP 주소와 포트가 들어간 주소도 등록된다.
2. SDK 4.5.31이 본체를 `t1.kakaocdn.net`에서 받아 CSP에 막혔다 → 허용 주소에 `*.kakaocdn.net`을 더했다(지도 그림은 `mts.kakaocdn.net`).
3. 카카오 확대 버튼이 쓰는 인라인 스타일이 CSP에 막혀 "거리/동/전국" 글자가 계속 보였다 → 카카오 버튼을 빼고 앱의 "축소 −/확대 +" 버튼을 두었다. 막히는 인라인 스타일이 5건에서 1건으로 줄었고, 남은 1건은 화면에 눈에 띄는 영향이 없어 CSP는 넓히지 않았다.
4. 카카오는 오버레이를 처음 그릴 때의 크기로 위치를 잡아, 나중에 나타나는 말풍선 때문에 점이 약 70px 밀려 보였다 → 점만 상자 크기가 되도록 말풍선을 절대 위치로 바꿨다. 범위 맞추기에 여백(위 60, 좌우 80, 아래 24px)을 두고, 말풍선은 확대 수준 7 이하에서 보인다.
5. 겹친 장소의 상자가 아래 점의 클릭을 가로챘다 → 상자 크기를 점에 맞추고 상자 전체(말풍선 포함)가 상세를 연다.

확인(노트북 브라우저, `http://localhost:4183`): 서울 전체 지도에 148곳(화면 안은 53개 점), 깨워 줄 곳은 점선 z. 중구 도착(DDP 근처 가짜 위치) → "이 구를 지도에서 보기" → 중구 8곳에 맞춘 지도, "나" 표시, DDP 위에 "한산함 · 야외 광장 한산해요" 말풍선, 새로 고침 때 "동대문디자인플라자(DDP)가 깨어났어요!". 남대문시장 점을 마우스로 누르자 상세 창(주소·가는 방법·여기서 거리·걷기). 자동 검사 156개 통과. 확인용 소식 1건과 브라우저 기록은 지웠다. 휴대폰용 서버는 키를 읽도록 다시 켰다(`지도: 카카오맵 (키 설정됨)`). 이어서 **휴대폰에서도 카카오맵이 보였다(사용자 보고)**. 휴대폰에서 어떤 화면(서울 전체·구 도착 지도)까지 보았는지와 기종·브라우저는 기록하지 않았다.
