## 화면 확인

- 실제 DOM 너비 390px에서 홈·설정·조건·지역·장소·코스·저장·혜택을 조작했다. 최종 홈/강릉 코스에는 가로 넘침이 없고 관측한 표시 중인 조작 요소 높이가 44px 이상이다. [측정](evidence/mobile-metrics.json)
- 넓은 화면은 새 검사 탭에서 실제 DOM 1280×720px임을 확인한 뒤 홈·코스·혜택을 캡처했다. 가운데 앱 프레임·고정 주요 버튼·하단 탐색이 유지된다. [측정](evidence/wide-metrics.json), [홈](evidence/home-1280-after.png), [코스](evidence/course-1280-after.png), [혜택](evidence/benefits-1280-after.png)
- 1440px 설정을 시도한 기존 탭의 실제 너비는 390px로 유지됐다. 해당 결과는 `*-390-repeat`로 정정했으며 1440px 완료로 보고하지 않는다. 이전 before 캡처의 너비와 이번 검증을 혼동하지 않는다. 320px·실기기·스크린리더 검증은 미실행.
- 최종 브라우저에서 관측한 콘솔 오류 0개. [기록](evidence/browser-errors.json)
- 생성한 기존 가상 장소 사진은 새 실제 코스에 사용하지 않았다. 홈의 선 그림은 장식이며 실제 장소 사진으로 표시하지 않는다.

## 코드·검사 확인

- 최종 제품 코드에서 전체 자동 검사 95/95 통과: [로그](evidence/automated-tests.txt). 샌드박스의 임시 루프백 포트 접근 제한 때문에 동일 명령을 허용된 환경에서 실행했다. 서버 검사의 과거 홈 문구 기대값을 앱 모듈 로드·신규 공개 자산 응답 검사로 수정했다.
- 독립 코드 검토에서 제품 차단 문제 없음. URL·좌표 변조 테스트가 사본 불일치만으로도 통과하는 검증 품질 지적을 수정했고, 수정 후 관련 10개 검사 통과: [검토](../../.omo/evidence/real-travel-code-review.md), [수정 후 로그](../../.omo/evidence/real-travel-engine/mirrored-tamper-tests.txt).
- 최종 CSS에서 접힘 요약 2곳의 최소 높이를 44px로 조정한 뒤 모바일 표시 크기를 다시 측정했다.
- 정적 문서 검사는 앱 동작 검사와 별도다. [문서 검사](evidence/docs-check.json)

## 범위

실제 운행을 내장 연동한 서비스가 아니라 공식 장소 안내와 외부 지도 길찾기, 명시적 기기 저장을 연결한 현재 웹 구현이다. 실시간 교통 자동 수집, 날짜별 모든 열차·버스·요금·막차·현장 운영·계단 접근성을 검증하거나 보장하지 않는다. 지도 대표점은 특정 출입구·승차장이 아니다. 시간 입력은 사용자 계획값이며 미확인 비용·도보량을 0으로 만들지 않는다. 계정 동기화·실기기·배포·예약·결제는 수행하지 않았다.
