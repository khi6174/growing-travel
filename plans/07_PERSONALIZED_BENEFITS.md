# 맞춤 혜택·클로드 디자인 전달 기록

작성일: 2026-10-24 (Asia/Seoul). 사용자 결정 D15와 구현 선택 P21의 후속 기록. [직전 혜택·대학생 기록](06_BENEFITS_STUDENT.md)과 기존 검사 보고서는 보존한다. 별도 전달 패키지 docs 원문 미확보.

## 요청과 이번 경계

사용자는 나이·거주지·대학생 여부로 자신에게 맞는 혜택을 우선 표시하고, 조건이 맞는 후보와 추가 확인이 필요한 혜택을 구분해 기존 시연에 반영하도록 요청했다. 이 내용과 제품 기준을 클로드·클로드 디자인에 전달할 수 있는 문서 작성도 요청했다.

현재 개인 입력과 확인된 공식 규칙을 비교하는 기능이다. 후보를 최종 수혜 판정으로 표현하지 않으며 출생연도·시군구·학생 자격을 임의 추정하지 않는다. 공고 진행 상태를 개인별 상태와 분리하고 공식 혜택을 가상 코스에 적용하지 않는다. 실제 후기·게시판, 운영 인증·AI 모델·배포·예약·결제는 범위 밖이다.

## 점검·구현 기준

- 기존 AGENTS·README·구조·개인 설정·혜택 데이터·출처 장부를 읽고 필요한 내용만 병합했다. `git status --short`는 저장소가 아니라는 오류를 반환했다. 따라서 Git 기준 사용자 변경분 비교는 불가능하며, 기존 파일을 직접 읽고 필요한 부분만 수정했다. 원본 전달 사본·과거 보고서·저장 모듈·저장 키는 보존했다.
- 기존 개인 설정·코스 키, 저장본의 원형과 과거 입력 스냅샷을 보존한다. 혜택 정렬만으로 설정을 저장하거나 기존 코스를 다시 쓰지 않는다.
- `candidate / needs_info / not_matched / not_current`를 구분하고 이유·부족한 필드·남은 확인 사항을 표시한다. 기본 순서는 후보→추가 확인→불일치→현재 기간 아님이다.
- 나이·거주·대학생 여부 중 해당 공식 사업의 근거가 있는 조건만 사용한다. 학생 조건이 확인되지 않은 사업에 학생 가점을 만들지 않는다.
- 국립현대미술관 서울관의 연령 또는 학부생 조건처럼 공식 대체 경로가 있으면 OR 관계를 보존한다. 일반 대학생 입력이 학부생 확인을 대신하지 않으며, 연령 경로가 맞으면 학생 여부 때문에 탈락시키지 않는다.
- 현재 맞춤 혜택에 쓰는 개인 설정과 재열람한 코스의 당시 설정을 구분한다. 사용자가 직접 수정한 현재 입력은 명시적으로 저장하지 않아도 비교에 사용할 수 있으나 저장 여부를 알린다.

## 검사 기록

`node --test tests/*.test.mjs` 최종 실행 결과 **72개 통과, 실패·취소·건너뜀 0개, 종료 코드 0**이다. 중간 71개 통과 후 별도 검토에서 미지원 최상위 조건 키를 무시하는 문제를 재현해 수정하고 회귀검사 1개를 더했다. 수정 후 샌드박스 실행에서는 로컬 HTTP 연결 제한(`EACCES`) 때문에 서버 검사 1개가 실패했고, 허용된 환경에서 전체 검사를 다시 실행해 72개 통과를 확인했다. 과거 55개 결과를 재사용하지 않았다.

`node --check dist/app.mjs`, `node --check dist/benefit-catalog.mjs`와 조건 비교 모듈 구문 검사를 실행해 통과했다. 문서 병합 1차 정적 검사는 Markdown 27개·로컬 참조 219개·정의 80개·수용 기준 13개, 실패 0개였다. 최종 정적 검사는 **Markdown 27개·로컬 참조 233개·정의 80개·수용 기준 13개, 실패 0개**, 출처 사본 2개의 SHA-256 일치, 종료 코드 0을 확인했다. 원문은 [이번 정적 검사 결과](07_DOC_CHECK_RESULTS.json)에 별도로 저장했다. 이전 검사 파일은 덮어쓰지 않았다.

## 코드·자료 변경 파일

- [조건 비교 모듈](../dist/benefit-matching.mjs): 조건별 비교·OR 경로·현재성·후보 우선 정렬. 네트워크·저장 부작용 없음.
- [공식 카탈로그](../dist/benefit-catalog.mjs): 확인된 조건 규칙과 국립현대미술관 안내 추가, K-패스 최신 참여 지역 근거 연결. [출처 확인 기록](../docs/12_BENEFIT_MATCHING_SOURCES.md)에 공식 본문 확인과 미확인 범위를 기록.
- [화면 동작](../dist/app.mjs), [화면 구조](../dist/index.html), [스타일](../dist/styles.css): 현재 개인 입력 기준·분류/근거/필터·상태별 목록. 기존 모바일 화면 구조를 유지.
- [조건 비교 검사](../tests/benefit-matching.test.mjs), [카탈로그 검사](../tests/benefit-catalog.test.mjs): 규칙 경계와 실제 카탈로그 연결 검증.

위 문서 변경 목록과 함께 이번 작업 범위를 구성한다. 전체 앱 구현·배포·유료 가입·Git 커밋·푸시는 하지 않았다. 검사용 로컬 서버는 작업 종료 시 중지한다.

## 미확정과 다음 과제

혜택 원문 갱신·조기 소진·상세 거주지·생년 기준·기관별 학생 인정 범위와 실제 증빙은 후속 결정이다. 현재 조건으로 판정 가능한 범위가 좁다면 한계를 표시하고 공식 근거를 확보한 뒤 확장한다. 클로드 디자인의 시각 결과를 받은 다음 제품 상태의 의미·가상 표시·입력 보존·모바일 접근성이 유지되는지 검토하고, 사용자 선택 후 필요한 화면 변경을 구현한다.
