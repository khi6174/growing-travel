# Growing Travel

**여행할수록 함께 자라는 AI 여행 추천**

팀원이 처음 실행한다면 [팀 인수인계·빠른 실행](handoff/TEAM_HANDOFF.md)부터 읽는다. 설치·빌드 없이 `node scripts/serve.mjs`로 실행하며, 현재 기능·저장 범위·검증 증거·팀 전달문을 함께 안내한다.

경험 발견 → 상황에 맞는 추천 → 짧은 코스 구성·수정 → 개인 여행 기록 → 선택적 공개·방문 후 확인 → 다음 추천 반영.

2026-11-02 D27에 따라 홈을 **펫이랑 걷는 서울 여행**으로 바꿨다. [팀 명세](handoff/growing-travel/GROWING_TRAVEL_SPEC_2026-11-02.md)대로 여행 목적에 맞는 펫(골든·시바·코기·비숑·백구)을 고르고, 출발 위치(역 또는 현재 위치)·쓸 수 있는 시간·인원·걷기 정도를 정하면 서버가 서울 25개 구 148곳 중 목적이 맞고 추정 60분 안인 20곳을 거른 뒤 AI(키가 없으면 규칙 정렬)가 3곳을 펫 말투로 추천한다. 카드에서 가는 법·최근 현장 소식·동네 친구 힌트를 보고 상세 창에서 현장 제보를 남긴다. 데이터는 `data/pets.json`·`districts.json`·`gu_friends.json`·`places.json`이다. 좌표는 118곳이 한국관광공사 TourAPI 검색 결과이고, 나머지 30곳의 좌표와 모든 교통 요약은 확인 전 초안이다. "구 도착 알림 켜기"를 누르면 위치로 자치구 도착을 감지해 그 구의 동네 친구가 나타나고, 처음 만나면 근처 장소 현장 질문에 답해 도감(25칸, 이 기기에만 저장)에 등록한다. 휴대폰 위치는 HTTPS에서만 동작하므로 같은 와이파이 시연은 `node scripts/make-cert.mjs` 뒤 `node scripts/serve.mjs --lan`으로 연다(자체 서명 인증서·접속 코드). "지도 열기"(홈)·"추천 3곳 지도에서 보기"·"이 구를 지도에서 보기"는 살아 있는 지도를 연다. 유효한 현장 소식은 말풍선, 유효시간이 지난 소식은 흐린 말풍선, 48시간 넘게 소식이 없는 곳은 깨워 줄 곳으로 표시한다. 카카오맵은 `.env`의 `KAKAO_JS_KEY`가 있을 때 그리고, 없으면 같은 내용을 목록으로 보인다. [구현·검사 기록](plans/15_SEOUL_PET_MVP.md)

2026-10-27 D24에 따라 **서울에서 춘천·가평·강릉으로 떠나는 실제 여행 계획**을 기존 MVP에 연결한다(P28). 출발역 3개·실제 장소 8개와 출발/현지/복귀 동선, 카카오 대중교통·도보 길찾기·코레일 확인 링크, 구간 시간 직접 입력·명시적 저장을 제공한다. 미확인 이동 시간·비용은 그대로 남기고 과거 가상 저장본은 ‘이전 예시 코스’로 보존한다. 여행자용 문구·상세 배치도 정리한다. [실제 여행 출처](docs/13_REAL_TRAVEL_SOURCES.md)와 [이번 구현·검사 기록](plans/13_REAL_TRAVEL.md)에 확인 범위와 진행 중인 검사를 분리한다. 아래 D23 이전 설명과 검사 수치는 해당 시점의 이력이다.

2026-10-27 D23에 따라 **승인한 여행자 와이어프레임의 디자인을 기존 MVP `dist/`에 적용했다**. 여행 시작·내 설정을 포함한 9개 화면 흐름, 하단 4개 탐색, 주요 버튼과 동선 편집을 연결했고 혜택 쿠폰 형태를 유지했다(P27). 기존 추천·혜택 판정·명시적 저장·과거 코스 계약을 보존했다. 이번 전체 자동 검사 85개와 후속 지역 표시 변경 관련 22개 검사가 통과했으며, 실제 브라우저에서 저장·새로고침·재열람과 390/1440px 화면을 확인했다. 문서 정적 검사·독립 시각 검토를 포함한 최종 상태와 한계는 [와이어프레임의 MVP 적용 기록](plans/12_WIREFRAME_TO_MVP.md)에 별도로 남긴다.

직전 D22에서는 **여행자가 사용하는 Growing Travel 주요 화면 와이어프레임**을 만들었다. [여행 서비스 화면·실행 안내](wireframes/traveler-service/README.md)에서 홈·개인 설정·여행 조건·지역 비교·경험 추천·코스·혜택·저장·내 설정의 9개 모바일 화면을 검토한다(P26). D20의 동선 중심 구성과 혜택 쿠폰 방향을 적용한 별도 메모리 시연이며, 당시에는 기존 여행 MVP `dist/`와 저장 자료를 변경하지 않았다. 화면 보드와 앱 모드의 실제 확인 범위는 [와이어프레임 검사 기록](wireframes/traveler-service/QA.md)에 보존한다.

앞서 D21/P25로 기록한 [MCP 연결·관리 화면](wireframes/mcp-management/README.md)은 요청을 운영자 콘솔로 잘못 해석해 만든 과거 산출물이다. D22의 사용자 정정에 따라 현재 주요 와이어프레임에서 제외하고, 당시 자료·검사 이력만 보존한다. 여행 서비스의 제품 방향을 MCP 관리 도구로 변경하지 않는다.

2026-10-27 D20의 **1번 동선 중심 구성과 3번 혜택 쿠폰 틀**을 결합해 기존 로컬 시연에 반영했다(P24). 코스 경로와 편집을 한 흐름으로 정리하고 가상 계산값·미확인 구간·독립 혜택 안내를 구분한다. 생성 이미지는 가상 시연 자료이며 공식 혜택의 현재성을 다시 확인한 것은 아니다. 이번 전체 자동 검사 83개, 구문 검사와 코스 편집·저장·새로고침·재열람·조건 오류의 브라우저 확인을 수행했다. 기존 계약·저장본·이전 기록을 보존하며 실제 검사와 남은 범위는 [동선·쿠폰 개선 기록](plans/11_ROUTE_COUPON_REFINEMENT.md)에 남긴다.

사용자가 승인한 현재 흐름은 **개인 설정 → 여행 조건 → 지역·혜택 비교 → 코스 추천·근거 확인 → 저장·재열람**이다. **20대 혼자 뚜벅이 여행**에 집중하고 **교통·숙박·여행·문화 혜택**을 다룬다. [타겟 개발 방향](docs/09_TARGET_FOCUS.md)과 [공식 혜택 출처](docs/10_BENEFIT_SOURCES.md)를 참고한다. 실제 평점·후기와 게시판은 다음 단계로 남긴다.

이후 사용자 요청에 따라 **스마트폰 앱을 우선하는 시연 화면**으로 구성한다(D13). 개인 설정·여행 조건·지역 비교·경험 추천·코스 편집을 한 화면씩 진행한다. D14에서는 처음부터 열 수 있는 **혜택 탭**과 **선택적 대학생 여부**를 추가하고, 세부 화면 디자인은 후속으로 미룬다. 하단에서 여행·혜택·저장한 코스·내 설정으로 이동한다. 이번에는 기존 로컬 웹에서 앱 UX를 검증하는 구현 선택이며 네이티브 앱·Flutter·React Native·앱스토어 배포를 확정한 것은 아니다. 직전 [모바일 앱 시연 기록](plans/05_MOBILE_APP_DEMO.md)과 현재 [혜택·대학생 설정 기록](plans/06_BENEFITS_STUDENT.md)에 변경과 실제 검사 결과를 구분한다.

D15에서는 **나이·거주지·대학생 여부로 공식 조건에 맞는 혜택 후보를 우선 표시**한다. 추가 확인 필요·알려진 조건 불일치·현재 기간 아님과 구분하며, 후보도 가입·증빙·예산 소진 등을 더 확인해야 한다. 당시 변경과 검사는 [맞춤 혜택 기록](plans/07_PERSONALIZED_BENEFITS.md), 클로드·클로드 디자인에 복사해 전달할 설명과 요청문은 [전달 패키지](handoff/claude/README.md)에 둔다. 문서 준비는 외부 전송이나 디자인 구현 완료를 뜻하지 않는다.

D18에서는 [2026-10-26 디자인 개발 전달](handoff/claude/DESIGN_HANDOFF_2026-10-26.md)을 기존 로컬 시연에 반영했다. D16의 **여행 티켓·흑연/코발트** 방향과 D17의 **학생 경로 표시·학생 조건 필터**를 기준으로, 조건 수정 시트·이유 상세·5단계 여행 흐름을 연결했다. 당시 코드 자동 검사 **78개 통과**, 변경 모듈 2개 구문 검사와 아래에 기록한 전용 로컬 브라우저 검사를 수행했다. 구현 선택·실제 검사·남은 한계는 [1차 디자인 구현 기록](plans/09_DESIGN_IMPLEMENTATION.md)에 보존한다. 당시에는 비공개 Claude 캔버스의 원본이나 화면 픽셀을 확보하지 않아 문서 기준으로 구성했으며 픽셀 일치를 주장하지 않았다.

D19에서는 [디자인 2차 전달](handoff/codex-design-2026-10-26/00_START_HERE.md)과 명세·원본 HTML·헤드리스 렌더 화면을 바탕으로 사용자 승인 세부 D19를 병합했다. **나이/거주/학생 3칸과 ‘본인 입력’, 메타 쉼표·이유 이름표, 실제 경로만 화살표, 혜택 티켓에만 반원 홈, 모서리 위계**가 1차 이후 달라진 점이다. 접근성 구현과 조건 시트의 오류 제출 동작은 P23으로 구체화했고, 오류가 있어도 버튼을 켜 두고 누르면 첫 오류를 안내한다. 최종 자동 검사 **83개 통과**, 변경 모듈 2개 구문 검사와 전용 390×844 브라우저 확인을 수행했다. 실제 검사·캡처 9개·남은 범위는 [2차 디자인 구현 기록](plans/10_DESIGN_SECOND_PASS.md)에 분리하며 이전 78개 검사·제공된 화면 사진을 새 앱 검사의 통과 증거로 재사용하지 않았다.

직전 D12 확장은 **자동 검사 41개와 JavaScript 구문 검사 5개를 통과**했다. 당시 실제 로컬 브라우저에서 개인 설정 저장·새로고침 복원, 지역·혜택 비교, 추천 근거, 코스 제목·순서 수정·저장·재열람을 확인했다. 오류·다중 탭·모바일·브라우저 완전 종료 후 재시작까지 모두 검증한 것은 아니다. [개인 설정·여행 조건 시연 기록](plans/04_PROFILE_TRIP_DEMO.md)에 실행 범위와 한계를 기록했다. 이 결과가 새 모바일 화면 검증을 대신하지 않는다. 최초 21개 검사와 당시 화면 미실행 이력은 [이전 기록](plans/03_LOCAL_DEMO_IMPLEMENTATION.md)에 보존했다. 2026-10-24 최초 점검 당시 작업 폴더는 비어 있었으며 기존 코드·README·AGENTS.md·Git 저장소는 없었다. 최초 점검은 [파일 정리 결과](plans/01_FILE_SETUP.md)에 보존했다.

사용자 첨부 [CODEX_START 원문 사본](handoff/growing-travel/CODEX_START.md)과 추가 지정한 [Growing Travel PDF 안내서](handoff/growing-travel/growing-travel-service-guide-ko.pdf) 12쪽을 읽고 반영했다. PDF는 2026-10-08 기획 제안 v1.0이며, 사례·화면·실험 수치는 제안 또는 가상 예시다. [페이지별 반영 내역](docs/07_SOURCE_REVIEW.md)을 남겼다.

CODEX_START가 별도로 열거한 전달 패키지의 AGENTS.md와 docs/00~06 원문은 확보하지 못했다. 아래 docs는 **사용자 직접 요청·CODEX_START·PDF를 종합한 새 기준 초안**이며, 존재를 확인하지 못한 패키지 docs의 사본이 아니다. 해당 원문이 있으면 추가 대조가 필요하다.

## 로컬 실행

PowerShell에서 프로젝트 폴더로 이동한 뒤 서버를 실행한다. 현재 환경에 있는 Node.js v24.14.0을 사용하며 패키지 설치나 빌드는 필요 없다.

```powershell
Set-Location -LiteralPath 'C:\성장 여행 서비스'
node scripts/serve.mjs
```

터미널에 서버가 시작됐다고 표시되면 [로컬 시연 열기](http://127.0.0.1:4173)를 연다. 서버를 켜 둔 동안 이용할 수 있으며 `Ctrl+C`로 종료한다. 포트가 이미 사용 중이면 다른 프로그램을 임의로 종료하지 말고 서버 오류를 확인한다. HTML 파일을 직접 여는 방식 대신 위 주소를 사용한다.

Web Locks를 지원하는 최신 Chrome 또는 Edge를 권장한다. 다른 포트가 필요하면 `node scripts/serve.mjs --port 4174`로 실행할 수 있으나 저장 공간은 별도로 분리된다. 자동 검사용 서버는 작업 종료 시 중지한다.

개인 설정은 현재 화면에서 사용하거나 명시적으로 저장한다. 선택적인 만 나이·거주 지역·대학생 여부와 관심·걷기 허용량을 정한 뒤, 별도의 여행 출발역·여행일·가능 시간·1인 예산·인원·도보 한도를 입력한다. 대학생 여부는 `선택 안 함 / 대학생 / 대학생 아님`으로 구분하는 자기 보고이며 학교명·재학 증빙은 받지 않는다. 춘천·가평·강릉을 비교해 지역을 선택하고 실제 장소의 안내를 확인한 뒤 경험 선택·정렬과 코스 저장을 진행한다. 구간 길찾기에서 확인한 시간을 직접 입력할 수 있다. 모든 왕복 구간을 입력하기 전에는 전체 시간을 확정하지 않는다. 저장된 코스는 같은 브라우저 프로필에서 같은 주소로 다시 열 수 있다.

혜택 탭은 설정이나 여행 조건을 입력하기 전에도 볼 수 있다. 공식 출처에서 확인한 기간과 기준일에 따라 진행 상태를 표시하며, 상시 안내 또는 현재 신청 여부를 확인하지 못한 항목은 확인이 필요하다고 알린다. ‘진행 중’도 개인 자격·잔여 예산·예약 가능을 보증하지 않는다. 공식 혜택을 가상 코스 비용에서 자동 차감하지 않으며 대학생이라는 이유만으로 수혜를 확정하지 않는다.

맞춤 순서는 확인한 공식 개인 조건과 현재 개인 설정의 비교 결과를 사용한다. 알려진 조건이 맞는 후보를 먼저, 정보 부족·근거 부족으로 추가 확인이 필요한 항목을 다음에 보여준다. 거주 시·도와 실제 여행지는 다르며, 공식 조건이 시군구·출생연도·학적 증빙을 요구하면 현재 입력만으로 확정하지 않는다. 학생 조건이 없는 사업에는 대학생 가점을 붙이지 않는다. 비교 이유와 나머지 확인 사항을 함께 읽어야 한다.

디자인 반영에서는 혜택 카드의 개인 조건과 공고 정보를 티켓 절취선으로 나누고 요약·펼치기·전체 조건 상세로 연결한다. 학생 경로 배지는 확인된 공식 규칙에 해당 경로가 있다는 뜻이며 재학 인증이나 개인 수혜 확정이 아니다. 조건 수정의 ‘이번 비교에만 적용’은 저장하지 않은 현재 입력이며 ‘내 설정에 저장하고 비교’와 구분한다. 적용하지 않은 시트 초안은 같은 실행 중 닫았다 열어도 유지하고, 새로고침이나 현재 개인 설정 변경 시 초기화한다. 저장된 과거 코스의 당시 조건은 유지한다.

모바일 시연에서는 단계별 다음·이전 이동과 하단 메뉴를 사용한다. 화면 이동 자체가 설정이나 코스를 저장·삭제하는 동작은 아니다. 저장 버튼으로 보관한 자료와 현재 입력 중인 초안을 구분한다. 넓은 브라우저에서도 좁은 앱 화면으로 미리 보며, 실제 스마트폰·가상 키보드·네이티브 뒤로가기 검증은 별도다.

## 시연의 기술·자료·저장 범위

- 화면은 HTML/CSS/브라우저 JavaScript 모듈, 서버는 Node.js 기본 모듈로 구성한다. 설치·빌드·프레임워크 설정을 줄이기 위한 **이번 시연용 구현 선택**이며 운영용 스택 확정은 아니다.
- 추천은 규칙 기반이다. 새 추천은 공개 출처가 있는 실제 장소 자료를 사용하며, 체류 시간은 계획 제안이다. 주소·운영 안내의 정적 확인과 당일 영업·이동 가능성은 구분한다. 미확인 시간·비용·도보량을 추정하지 않고 외부 지도/코레일 확인과 사용자의 구간 시간 입력을 제공한다. 실제 후기·방문 인증·외부 AI·실시간 교통 API 조회는 없다. 과거 가상 저장본은 ‘이전 예시 코스’로 구분한다. 공식 혜택은 별도 안내이며 코스 비용에 자동 적용하지 않는다.
- 코스는 이 브라우저의 localStorage에만 저장한다. 같은 프로필·같은 `http://127.0.0.1:4173` 주소에서는 새로고침·서버 재시작 후에도 저장본을 읽도록 설계한다. `localhost`, 다른 포트, 다른 브라우저는 별도 저장 공간이다.
- 개인 설정은 코스와 별도 키에 명시적으로 저장·삭제한다. 저장하지 않고도 진행할 수 있다. 설정 삭제가 기존 코스 또는 코스에 남은 당시 입력 스냅샷까지 지우는 것은 아니다. 확장 전 저장 코스는 새 정보가 없는 상태로 읽기·수정하는 자동 검사를 통과했다.
- 계정·서버 DB·클라우드 동기화·백업은 없다. 브라우저 데이터 삭제나 비공개 창 종료로 자료가 사라질 수 있다. 같은 브라우저 프로필을 쓰는 사람 사이의 접근 보호를 제공하지 않으므로 실제 개인정보를 입력하지 않는다.

선택 이유, 오류 처리와 동시 저장 범위는 [로컬 시연 결정](docs/08_LOCAL_DEMO_DECISIONS.md)에 기록했다. 이번 실제 장소 범위는 D24로 선택했으며 운영 전체 지역·자료 갱신 체계·인증·외부 AI 모델은 여전히 미확정이다.

## 검사 명령

```powershell
node --test tests/*.test.mjs
node scripts/check-docs.mjs
```

첫 명령은 추천·코스·저장 계약의 자동 검사다. 두 번째 명령은 문서 정적 검사이며 앱 실행이나 실제 여행 품질을 검증하지 않는다. 명령 안내 자체는 통과 결과가 아니다. 수용 기준별 실제 결과는 [완료 기준](docs/05_ACCEPTANCE_TESTS.md)에 기록한다.

외국인 전용 한국 여행 플랫폼, 한일 업체용 컨시어지, 자동 예약·결제 대행은 현재 제품 방향에 포함되지 않는다.
