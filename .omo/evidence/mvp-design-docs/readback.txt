# Growing Travel

**여행할수록 함께 자라는 AI 여행 추천**

경험 발견 → 상황에 맞는 추천 → 짧은 코스 구성·수정 → 개인 여행 기록 → 선택적 공개·방문 후 확인 → 다음 추천 반영.

2026-10-27 D23에 따른 현재 작업은 **승인한 여행자 와이어프레임의 디자인을 기존 MVP `dist/`에 적용**하는 것이다. 동선 중심 코스와 혜택 쿠폰 형태를 유지하고, 주요 버튼의 우선순위와 화면 이동을 연결한다(P27). 기존 추천·혜택 판정·명시적 저장·과거 코스 계약을 보존하며, 이번 변경과 실제 검사 상태는 [와이어프레임의 MVP 적용 기록](plans/12_WIREFRAME_TO_MVP.md)에 별도로 남긴다. 이전 와이어프레임의 메모리 저장 방식을 MVP에 복사하지 않는다.

직전 D22에서는 **여행자가 사용하는 Growing Travel 주요 화면 와이어프레임**을 만들었다. [여행 서비스 화면·실행 안내](wireframes/traveler-service/README.md)에서 홈·개인 설정·여행 조건·지역 비교·경험 추천·코스·혜택·저장·내 설정의 9개 모바일 화면을 검토한다(P26). D20의 동선 중심 구성과 혜택 쿠폰 방향을 적용한 별도 메모리 시연이며, 당시에는 기존 여행 MVP `dist/`와 저장 자료를 변경하지 않았다. 화면 보드와 앱 모드의 실제 확인 범위는 [와이어프레임 검사 기록](wireframes/traveler-service/QA.md)에 보존한다.

앞서 D21/P25로 기록한 [MCP 연결·관리 화면](wireframes/mcp-management/README.md)은 요청을 운영자 콘솔로 잘못 해석해 만든 과거 산출물이다. D22의 사용자 정정에 따라 현재 주요 와이어프레임에서 제외하고, 당시 자료·검사 이력만 보존한다. 여행 서비스의 제품 방향을 MCP 관리 도구로 변경하지 않는다.

2026-10-27 D20의 **1번 동선 중심 구성과 3번 혜택 쿠폰 틀**을 결합해 기존 로컬 시연에 반영했다(P24). 코스 경로와 편집을 한 흐름으로 정리하고 가상 계산값·미확인 구간·독립 혜택 안내를 구분한다. 생성 이미지는 가상 시연 자료이며 공식 혜택의 현재성을 다시 확인한 것은 아니다. 이번 전체 자동 검사 83개, 구문 검사와 코스 편집·저장·새로고침·재열람·조건 오류의 브라우저 확인을 수행했다. 기존 계약·저장본·이전 기록을 보존하며 실제 검사와 남은 범위는 [동선·쿠폰 개선 기록](plans/11_ROUTE_COUPON_REFINEMENT.md)에 남긴다.

후속 D23은 위 여행자용 와이어프레임의 방향을 승인하고 기존 MVP `dist/`에 디자인을 적용하도록 요청한 것이다. P27에서는 동선 중심 코스·혜택 전용 쿠폰, 하단 4개 탐색과 화면별 주요 버튼·이동을 기존 기능에 병합한다. D22/P26의 메모리 전용 시연과 달리 기존 MVP의 명시적 localStorage 저장·키·과거 코스 스냅샷을 유지한다. 화면 이동으로 설정·코스를 자동 저장하거나 현재 설정으로 과거 저장본을 덮어쓰지 않는다. 기존 공식 혜택 조건·기간·자료 확인일·미확인 사항은 디자인 작업 중 다시 확인한 것으로 바꾸지 않는다. 새 이미지가 필요하면 기존 가상 자산을 먼저 확인하고 imagegen 사용 여부·생성 자산 경로를 실제 수행에 맞춰 기록한다. 이번 변경·자동 검사·브라우저 확인과 미실행 범위는 [와이어프레임의 MVP 적용 기록](plans/12_WIREFRAME_TO_MVP.md)에 별도로 남긴다. 배포·유료 가입·Git 커밋/푸시·외부 예약/결제 연동은 수행하지 않는다.

# 여행자 와이어프레임의 기존 MVP 적용

기준일: 2026-10-27 (Asia/Seoul). 사용자 승인 D23, 구현 선택 P27. 상태: 적용 작업 진행 중이며 아래 실행 결과는 실제 증거가 확보된 뒤 갱신한다. 이전 시연의 83개 검사나 와이어프레임 검사를 이번 MVP 검사의 통과로 재사용하지 않는다.

## 요청과 기준

사용자는 [여행자용 와이어프레임](../wireframes/traveler-service/README.md)을 승인하고 기존 MVP에 적용하도록 요청했다. 동선 중심 구성과 혜택 쿠폰 형태를 유지하면서 주요 버튼 배치와 화면 이동을 연결하는 작업이다. [와이어프레임 설계](../wireframes/traveler-service/DESIGN.md)의 9개 화면 개념을 참고하되 실제 기존 추천·입력 단위·검증·저장 계약을 우선한다. 구체적인 DOM 공유·탐색 구현·여백과 크기는 P27의 구현 선택이다.

대상은 20대 혼자·무차량·기차/대중교통·도보 여행자다. 여행 시작 → 취향·개인 조건 → 이번 여행 조건 → 지역 비교 → 경험 선택 → 동선 편집·저장으로 이어지고, 혜택·저장한 코스·내 설정은 하단 탐색에서 접근한다. 혜택은 여행 입력 완료를 요구하지 않는다.

## 현재 한계

이번 문서 작성 시점에 구현·브라우저 검사 완료를 주장하지 않는다. 공식 혜택 원문 현재성·개인 수혜·교통·영업·안전은 디자인 작업의 검증 대상과 다르다. 실제 경로 API·예약/결제·후기/게시판·개인 기록 공개·배포·유료 가입·Git 커밋/푸시는 이번 범위에 없다. 스마트폰 실기기·화면 낭독기·브라우저 완전 재시작 등은 실제 수행 여부를 마지막 기록에서 구분한다.
