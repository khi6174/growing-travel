# 여행자용 와이어프레임 확인 기록

2026-10-27. 사용자 정정 D22 / 구현 선택 P26. 개발자용 MCP 화면 대신 여행자가 사용하는 9개 모바일 화면을 새 경로에 구성했다. 기존 `dist/`와 저장 자료는 이번 작업에서 수정하지 않았다. 이 문서는 이번에 직접 확인한 범위이며 이전 시연의 83개 검사를 재사용하지 않는다.

## 실제 브라우저 확인

ChatGPT 인앱 브라우저의 `http://127.0.0.1:4181/`에서 아래 동작을 직접 수행했다. 화면 보드와 앱 모드는 같은 렌더러를 사용한다.

| --- | --- |
| 기본 진입 | 여행 시작·취향·여행 조건·지역 비교·경험 선택·코스·혜택·저장·내 설정 9개 프레임 표시. 운영자·MCP 설정 화면 없음 |

| 코스 편집 | 시장을 앞으로 옮긴 실제 표시 순서 확인. 이동 후 버튼 초점과 스크롤 유지. 시장 제거 후 나머지 경험 유지 |
| 명시적 코스 저장 | 확인란 미선택 제출 시 안내와 확인란 초점. 제목 변경·확인 후 저장 목록 1개 예시에서 2개로 증가 |

| 상세·설계 안내 | 혜택 조건 시트 열기·닫기, 정보 구조 안내 열기 및 표시 내용 확인 |

## 화면·조작 배치

- 1440×1000 CSS 뷰포트: 기본 보드 3열·9개, 각 프레임 390×844 CSS px. 문서 가로 넘침 없음. 헤더·주 행동·하단 메뉴와 본문 스크롤을 구분했다.
- 390×844 CSS 뷰포트: 앱 모드 문서의 측정 폭 390, 높이 844. 가로 넘침 없음. 앱 콘텐츠 프레임 약 366.4×624 CSS px. 외부 검토 도구는 작은 머리말로 축소한다.
- 모바일 홈 주 행동 높이 50px, 하단 메뉴 버튼 높이 약 52.6px를 측정했다. 본문이 이 고정 영역 뒤로 겹치지 않는다. 모든 화면의 모든 보조 버튼에 대해 전수 계측한 것은 아니다.
- 혜택 티켓의 반원 홈, 개인 조건/공고 상태 분리와 하단 상세 버튼을 실제 스크롤 후 확인했다. 쿠폰 형태를 다른 카드에 사용하지 않았다.
- 선택 방향은 밝은 화면이다. 다크 테마, 실제 휴대폰, 스크린리더, 확대 200% 검사는 수행하지 않았다.

## 코드·문서 검사

`app.mjs`, `model.mjs`, `review.mjs`, `serve.mjs`의 `node --check` 결과는 [구문 검사 기록](evidence/syntax-checks.txt)에 남긴다. 기존 `node scripts/check-docs.mjs`의 문서 링크·결정 참조·원문 사본 검사 결과는 [정적 문서 검사 기록](evidence/docs-check.json)에 남긴다. 앱 회귀 검사와는 별개다.

이번 실행에서 구문 검사 4개는 종료 코드 0, 문서 검사는 `passed: true`였다. 첫 문서 검사에서 증거용 문서 사본의 상대 링크를 문서로 잘못 읽는 문제가 발견되어 사본 내용은 보존하고 확장자를 `.snapshot.txt`로 바꾼 뒤 재실행했다.

별도 읽기 전용 검토에서 스크롤/초점 소실과 보드 입력 표시 불일치가 지적되어 수정했다. 수정 후 코드 재검토에서 남은 지적이 없었고, 위 브라우저 시나리오로 해당 동작을 직접 확인했다. [검토 기록](../../.omo/evidence/traveler-service-code-review.md).

## 한계

클릭 가능한 메모리 와이어프레임이며 입력·저장은 새로고침하면 초기화된다. 실제 추천·경로·영업·혜택 공고 연결, 비용·이동 재계산, 영속 저장, 예약·결제, 배포는 포함하지 않는다. 혜택은 공식 안내를 연결할 자리를 표현하며 실제 자격이나 신청 가능을 판정하지 않는다. 기존 MVP의 자동 회귀 검사는 이번 별도 산출물에 다시 실행하지 않았다.
