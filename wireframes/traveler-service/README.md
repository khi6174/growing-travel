# Growing Travel 여행자용 주요 화면

2026-10-27 사용자 정정 D22에 따라 다시 구성하는 **여행 서비스 주요 화면 와이어프레임**이다. 함께 디자인한 D20의 동선 중심 구성과 혜택 쿠폰 방향을 이어 여행자의 정보 탐색과 주요 행동 배치를 검토한다. 화면 수와 구체적인 전환 방식은 구현 선택 P26이다.

이전 [MCP 관리 화면](../mcp-management/README.md)은 요청 범위를 운영자 콘솔로 잘못 해석한 과거 산출물로 보존한다. 현재 와이어프레임의 대상은 20대 혼자·무차량·기차/대중교통·도보 여행자다.

## 실행과 검토

프로젝트 루트에서 실행한다.

```powershell
node wireframes/traveler-service/serve.mjs
```

서버를 실행한 동안 [여행 서비스 와이어프레임](http://127.0.0.1:4181)을 열 수 있다. 기본 보드에서는 9개 모바일 화면을 함께 비교하고, 앱 모드에서는 직접 눌러 여행자 흐름을 따라간다. 서버는 `Ctrl+C`로 종료한다.

| 화면 | 검토할 주요 행동 |
| --- | --- |
| 홈 | 여행 시작, 처음부터 혜택 열기 |
| 개인 설정 | 선택적 만 나이·거주·대학생 여부, 여행 취향 입력 |
| 여행 조건 | 거주지와 별도의 출발지, 시간·예산·도보 조건 입력 |
| 지역 비교 | 조건과 이유를 보고 여행 지역 선택 |
| 경험 추천 | 경험과 추천 근거 확인, 코스에 담기 |
| 코스 | 역에서 시작하는 동선 확인, 순서·구성 수정, 명시적 저장 |
| 혜택 | 쿠폰 형태의 안내와 확인 한계, 개인 조건·공고 상태 구분 |
| 저장 | 현재 실행 중 보관한 코스 열기 |
| 내 설정 | 현재 개인 조건과 저장 동작 확인 |

혜택은 개인 설정·여행 조건·코스 생성을 완료하지 않아도 한 번의 탐색 동작으로 열 수 있다. 상세와 조건 수정 시트는 위 주요 화면에 연결되는 여행자용 보조 화면이다. 정보 배치와 설계 이유는 [DESIGN.md](DESIGN.md), 직접 수행한 검사·캡처와 남은 한계는 [QA.md](QA.md)에 기록한다. 안내 문서나 이전 시연의 통과 수치는 이번 화면의 검사 증거가 아니다.

## 자료와 저장의 경계

이 와이어프레임은 별도 HTML 메모리 시연이다. 입력·선택·저장 상태는 현재 실행 중에만 남고 새로고침하면 초기화된다. 기존 여행 MVP `dist/`의 도메인·저장 키·과거 저장본을 수정하거나 가져오지 않는다. 기존 시연은 [프로젝트 안내](../../README.md)의 실행 방법으로 별도로 이용한다.

동선·역·지역·경험·수치는 가상 예시이며 실제 이동 가능성·영업·후기·방문 확인을 나타내지 않는다. 혜택 안내의 알려진 조건과 공고 상태를 분리하고 공식 자료 확인일·현재성 한계를 유지한다. 대학생 여부는 본인 입력이며 인증·수혜 확정이 아니다. 혜택을 가상 코스 비용에서 차감하지 않는다.

실제 경로 데이터 연동·공개 후기·개인 기록 공개·예약·결제·외부 서비스 연결·영속 저장·배포는 포함하지 않는다. 운영 앱의 기술 스택이나 최종 화면을 확정한 것도 아니다. 결정·구현 선택의 근거는 [출처 장부 S20·D22·P26](../../docs/00_DECISIONS_AND_SOURCES.md)에 구분한다.
