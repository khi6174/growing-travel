# Growing Travel 여행자용 와이어프레임

## 목적

2026-10-27 사용자 정정 D22에 따라 여행자가 실제 사용하는 서비스 주요 화면을 다시 만든다. 앞서 만든 MCP 운영 화면은 요청을 잘못 해석한 산출물이며 이번 와이어프레임의 사용자 흐름으로 사용하지 않는다. 기존 여행자 MVP의 D12~D20 흐름과 동선 중심·혜택 전용 쿠폰 방향을 참고한다. 구체적인 화면 수·시작 화면·배치는 P26 제안이다.

## 사용자와 목표

20대 혼자·무차량·기차/대중교통·도보 여행자가 자신의 조건에 맞는 짧은 여행을 고르고 코스를 보관하는 흐름이다. 여행 조건, 추천 이유, 걷기 부담, 혜택의 확인 필요를 순서대로 판단하게 한다. 실제 후기·별점·게시판·예약·결제·운영자 설정은 포함하지 않는다.

## 정보 구조

전역 메뉴는 **여행 / 혜택 / 저장한 코스 / 내 설정**이다. 여행은 시작·취향·여행 조건·지역 비교·경험 선택·코스의 순서로 이어진다. 혜택은 처음부터 독립적으로 열 수 있다. 저장 목록의 과거 조건과 현재 설정은 구분한다.

## 배치·스크롤

Layout: 전체 화면 보드 - 여행자 화면의 흐름 비교 -> intrinsic grid + stack; scroll owner: document; anti-patterns: 개발자 콘솔 사이드바, 화면보다 큰 설명 패널, 본문 글씨를 줄여 모든 내용을 압축.

Layout: 모바일 화면 - 한 화면에서 한 단계의 판단 -> scroll-body-shell; scroll owner: .phone-body; fixed regions: .phone-head / .phone-actions / .phone-nav; anti-patterns: 버튼이 내용 위를 덮음, 화면 이동으로 입력/초안 소실.

Layout: 상세 시트 - 원래 여행/혜택 맥락 위에서 이유·조건 확인 -> overlay-stack; scroll owner: .consumer-dialog; anti-patterns: 닫기를 적용으로 처리, 미입력 학생을 비대학생으로 처리.

보드는 화면당 최대 390×844px의 앱 콘텐츠 프레임을 사용한다. 기기 테두리·OS 시계·브라우저 주소창을 그리지 않는다. 앱 모드는 같은 렌더러로 한 화면씩 열며 390px에서도 가로 넘침 없이 읽도록 한다. 보드의 각 화면은 고정 헤더·주 행동·하단 메뉴와 별도의 본문 스크롤 영역을 갖는다.

## 공통 구성

phone: 헤더 / 스크롤 본문 / 주 행동 / 하단 4개 메뉴. field·field-pair: 보이는 이름·오류·초점. summary: 서로 다른 뜻의 값 3칸. ticket: 개인 조건 위, 공고 안내 아래. timeline: 역·구간·경험 순서. consumer-dialog: 경험 근거·혜택 이유·비교 조건 시트. 상태는 선택/미입력/오류/미확인/저장 전후로 구분한다.

## 상호작용과 자료 경계

화면 이동, 관심·경험 선택, 순서 변경·제거, 명시적 설정/코스 저장, 저장 예시 재열람을 메모리에서 시연한다. 저장본을 여는 동작은 현재 개인 설정을 바꾸지 않는다. 코드의 가상 지역·경험·금액·혜택 안내는 실제 운영 데이터가 아니다. 계산하지 않은 이동 시간·비용을 재계산한 것처럼 보여주지 않고 미확인/예시로 구분한다. 공식 혜택의 실제 자격·현재 모집을 판정하지 않는다.

## 검증 범위

이번 산출물은 사용자 화면 구조를 검토하는 독립 와이어프레임이다. 기존 dist와 저장 데이터는 수정하지 않는다. 실제 실행한 화면·버튼·입력·저장/재열람 검사와 한계는 QA.md에 남기고 이전 시연의 검사 수를 재사용하지 않는다.
