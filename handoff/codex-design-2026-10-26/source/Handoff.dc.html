Growing Travel · 개발 전달 v0.1 · 2026-10-26

화면별 주석 · 미확정 질문 · 자료 목록

디자인 제안을 개발로 옮길 때의 기준이에요. 구현 완료나 실기기 검사 결과가 아니에요.

코드 지금 로컬 시연(dist)에 있는 이름·규칙 새 필드 이번 디자인에 필요한 제안 D 사용자 결정(D15·D16·D17)

화면별 데이터 · 상태 · 이벤트 · 접근성

혜택 판정은 본인이 입력한 값만 비교해요. 후보는 지원 확정이 아니고, 미입력은 비대상이 아니에요.

1 · 혜택 목록 (요약 카드 + 펼치기)

혜택 목록 · 요약 카드 대지, 상태별 화면 6장 D15·D17

데이터
내 조건 age(null 또는 1~120) · residenceRegion(빈 값 또는 17개 시·도) · studentStatus(unspecified/student/not_student) 코드
혜택마다 status(candidate/needs_info/not_matched/not_current), reasons, missingFields, remainingChecks, 공고 code(in_period/ongoing_info/needs_check/upcoming/ended), 출처 URL·verificationLevel·확인일 코드
접힌 카드의 한 줄 이유 shortReason, 학생 표시 여부 hasStudentRoute 새 필드
상태
그룹 순서 고정: 후보 → 확인 필요 → 불일치 → 기간 아님 · 필터 적용 · 결과 0개 · 불러오기 오류 · 조건 바꾸고 저장 전
이벤트
카드 누르기(한 번에 하나 펼침) · 분야/학생 조건 있음/진행 중 칩 · 상태별 바로가기 · 공식 안내 열기(외부) · 조건 수정 열기 · 조건 비교 전체 보기
접근성
카드 요약은 button + aria-expanded·aria-controls · 결과 수는 aria-live="polite" · 칩은 aria-pressed · 상태는 색 외에 아이콘과 글자 · 외부 링크는 새 창 안내 · 펼친 뒤 포커스는 그 버튼에 유지

2 · 조건 수정 시트 (+ 입력 오류)

조건 수정 시트 두 대지

데이터
초안 {age, residenceRegion, studentStatus}, 저장된 내 설정, 바뀜 여부, 필드 오류. 나이 오류 문구는 코드와 같게 “만 나이는 1~120 사이 정수로 입력하거나 비워 두세요.” 코드
상태
그대로 · 바뀜 · 입력 오류(적용 버튼 비활성 + 이유) · 저장 중 · 저장 실패(STORAGE_UNAVAILABLE 등)
이벤트
값 바꾸기 · 비우기 · 내 설정에 저장하고 비교 · 이번 비교에만 적용 제안 · 닫기
접근성
role="dialog" + aria-modal · 열리면 제목으로 포커스 · 시트 안에서만 포커스 이동 · Esc로 닫기 · 닫으면 ‘수정’ 버튼으로 포커스 복귀 · 오류는 aria-invalid + aria-describedby · 대학생 여부는 fieldset/legend

3 · 조건 이유 상세

조건 이유 상세 · 국립현대미술관

데이터
조건 대안별 결과(코드의 anyOf 비교: “대안 1, 대안 2”), checks[{field, result, message}], 남은 확인, 기간, 출처 코드
상태
후보: 맞은 대안만 강조 · 확인 필요: 아직 모르는 대안 나열 · 불일치: 모든 대안과 다름
이벤트
혜택 목록으로 · 공식 안내에서 조건 확인 · 비교 조건 수정
접근성
제목 단계 h1 → h2 · 대안은 목록 · 결과는 ‘맞음 / 확인 필요 / 조건 없음’ 글자로

4 · 여행 조건 (2/5)

여행 2/5 대지 · 가상 자료

데이터
departureId(central/east) · 날짜 · availableMinutes 1~1440 · budget 0~10,000,000 · partySize 1~6(기본 1) · walkingLimitMinutes 0~720 · avoidStairs 코드
상태
입력 가능 · 필드 오류 · 다른 탭에 갔다 와도 초안 유지
이벤트
값 바꾸기 · 지역·혜택 비교하기(검사 후 3/5) · 이전 단계
접근성

5 · 지역·혜택 비교 (3/5)

여행 3/5 대지 · 가상 지역

데이터
regionId, name, fitStatus, reasons, estimate{travelMinutes, walkingMinutes, costPerPerson}, checks{time, walking, budget}(met/unmet/unknown), 추천 경험, 가상 지역 혜택 수 · 정렬 fit/benefits 코드
상태
한도 안 · 한도 근접 기준 미정 · 맞는 경험 부족 · 값 모름(null은 0으로 계산하지 않음)
이벤트
정렬 바꾸기 · 이 지역 선택 · 조건 바꾸기
접근성
수치는 단위와 한도를 글자로 · 모르는 값은 ‘알 수 없음’ · 공식 혜택은 비용에서 빼지 않는다는 안내를 글로

여행 4/5 대지 · 가상 경험

데이터

상태

이벤트
근거 보기/접기 · 코스에 담기/빼기 · 뺀 경험 보기 · 코스 확인하기
접근성

상태

이벤트

접근성

9 · 모든 화면 공통

탭 이동
하단 메뉴 4개(여행 · 혜택 · 저장한 코스 · 내 설정)는 현재 시연 기준이에요. 탭을 오가도 입력과 초안은 남아요. 지금 탭은 aria-current="page".
화면 폭
360~430px 한 열. 하단 메뉴·키보드·안전 영역이 입력칸·오류·저장 버튼을 가리지 않게 해요. 터치 영역 최소 44px.
가상 표시
가상 지역·경험·코스·혜택에는 항상 점선 태그를 붙여요. 공식 혜택을 가상 코스 비용에서 빼지 않아요.
아직 없음
여행 1/5 ‘내 설정 확인’ · 내 설정 탭 · 혜택 불러오는 중 · 저장한 코스 빈 목록과 읽기 실패 화면은 아직 그리지 않았어요.

미확정 질문 사용자 결정 필요

  1. 하단 메뉴 4개를 최종 정보 구조로 확정할까요?
  2. 조건 수정에 ‘이번 비교에만 적용’을 넣을까요? 지금 시연은 저장만 있어요.
  3. 시트를 저장하지 않고 닫으면 바꾼 값을 버릴까요, 초안으로 남길까요?
  4. 혜택 카드는 한 번에 하나만 펼칠까요, 여러 개를 펼칠 수 있게 할까요?
  5. 학생 표시는 혜택 자료의 새 필드로 둘까요, 조건 규칙에서 계산할까요?
  6. 접힌 카드의 한 줄 이유는 자료에 직접 쓸까요, 이유 목록에서 만들까요?
  7. 도보·예산의 ‘한도 근접’ 기준을 몇 %로 할까요? (예: 90%)
  8. 시간·걷기 한도를 선택지 3개로 받을까요, 숫자로 직접 받을까요?
  9. 오류 빨강과 주의 색, Gothic A1 글꼴을 이대로 쓸까요?
  10. 혜택 자료의 확인일이 며칠 지나면 ‘오래된 자료’로 알릴까요?
  11. 학생 조건 혜택이 몇 개 넘으면 탭 방식을 다시 볼까요?
  12. 운영 기술 · AI 모델 · 실기기 검사 계획은 여전히 미정이에요(Q03·Q06).
