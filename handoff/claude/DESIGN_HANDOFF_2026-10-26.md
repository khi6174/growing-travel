# Growing Travel · 디자인 개발 전달 (화면별 주석·미확정 질문·자료 목록)

작성 기준: 2026-10-26 (Asia/Seoul). [디자인 전달서](DESIGN_BRIEF.md)를 바탕으로 디자인 캔버스에서 진행한 1~5단계 결과 중 5단계 ‘개발 전달용 주석’을 문서로 옮겼다. 디자인 제안이며 구현 완료, 실기기·화면 낭독기 검사, 최종 디자인 승인을 뜻하지 않는다.

- 디자인 캔버스: [Growing Travel 혜택 화면 방향 비교](https://claude.ai/artifact/QzW1S3N6DTe1a6NCAsWmSm) — 사용자 계정의 비공개 아티팩트다. 다른 사람은 공유 전까지 열 수 없다.
- 표시 구분: **[코드]** 현재 로컬 시연(`dist/`)에 있는 이름·규칙 / **[새 필드]** 이번 디자인에 필요한 제안 / **[제안]** 디자인 가정 / **D16·D17** 등은 [결정 장부](../../docs/00_DECISIONS_AND_SOURCES.md)의 사용자 결정.
- 필드 이름은 [혜택 비교](../../dist/benefit-matching.mjs), [혜택 목록·기간](../../dist/benefit-catalog.mjs), [개인 설정](../../dist/profile.mjs), [여행 조건·지역](../../dist/journey.mjs), [저장](../../dist/storage.mjs)을 읽어 맞췄다. 이번 작업에서 코드는 바꾸지 않았다.

## 디자인 기준 요약

- 혜택 화면은 B안(여행 티켓) 구조와 흑연 `#202124`·코발트 `#3651E8` 색으로 진행한다(D16). 절취선 위는 개인 조건, 아래는 공고·이동 같은 바깥 정보다.
- 대학생 여부는 탭으로 나누지 않고 비교 조건으로 둔다. 공식 근거로 학생 조건이 확인된 혜택에만 ‘학생 경로 있음’을 표시하고, 목록 필터에 ‘학생 조건 있음’ 칩을 둔다(D17).
- 개인 조건 상태(후보·추가 확인 필요·알려진 조건 불일치·현재 기간 아님)와 공고 상태는 한 배지로 합치지 않는다(D15). 상태는 색 외에 아이콘과 글자로도 구분한다.
- 혜택 카드는 요약만 먼저 보이고 눌러서 펼친다. 판단에 필요한 짧은 이유와 공고 기간은 접힌 상태에서도 보인다. **[제안]**
- 입력·칩·선택지 테두리는 `#8E9197`(흰 바탕 약 3.2:1), 최소 글자는 12px로 맞췄다. 오류 `#B3261E`, 주의 `#FFF4E0`/`#6B3A00`, 글꼴 Gothic A1, 4px 간격 단계는 **[제안]**이다. 대비는 색값으로 계산한 값이다.

## 화면별 데이터·상태·이벤트·접근성

### 1. 혜택 목록 (요약 카드 + 펼치기)

- **데이터**
  - 내 조건 **[코드]**: `age`(null 또는 1~120), `residenceRegion`(빈 값 또는 17개 시·도), `studentStatus`(`unspecified`/`student`/`not_student`).
  - 혜택마다 **[코드]**: `status`(`candidate`/`needs_info`/`not_matched`/`not_current`), `reasons`, `missingFields`, `remainingChecks`, 공고 기간 `code`(`in_period`/`ongoing_info`/`needs_check`/`upcoming`/`ended`), 출처 URL·`verificationLevel`·확인일.
  - **[새 필드]** 접힌 카드의 한 줄 이유 `shortReason`, 학생 표시 여부 `hasStudentRoute`.
- **상태**: 그룹 순서 고정(후보 → 확인 필요 → 불일치 → 기간 아님), 필터 적용, 결과 0개, 불러오기 오류, 조건을 바꾸고 아직 저장하지 않음.
- **이벤트**: 카드 누르기(한 번에 하나 펼침 **[제안]**), 분야·학생 조건 있음·진행 중 칩, 상태별 바로가기, 공식 안내 열기(외부), 조건 수정 열기, 조건 비교 전체 보기.
- **접근성**: 카드 요약은 `button` + `aria-expanded`·`aria-controls`. 결과 수는 `aria-live="polite"`. 칩은 `aria-pressed`. 외부 링크는 새 창 안내. 펼친 뒤 포커스는 그 버튼에 둔다.

### 2. 조건 수정 시트 (+ 입력 오류)

- **데이터**: 초안 `{age, residenceRegion, studentStatus}`, 저장된 내 설정, 바뀜 여부, 필드 오류. 나이 오류 문구는 코드와 같게 “만 나이는 1~120 사이 정수로 입력하거나 비워 두세요.” **[코드]**
- **상태**: 그대로, 바뀜, 입력 오류(적용 버튼 비활성과 이유 표시), 저장 중, 저장 실패(`STORAGE_UNAVAILABLE` 등).
- **이벤트**: 값 바꾸기, 비우기, 내 설정에 저장하고 비교, 이번 비교에만 적용 **[제안]**, 닫기.
- **접근성**: `role="dialog"` + `aria-modal`. 열리면 제목으로 포커스, 시트 안에서만 포커스 이동, Esc로 닫기, 닫으면 ‘수정’ 버튼으로 포커스 복귀. 오류는 `aria-invalid` + `aria-describedby`. 대학생 여부는 `fieldset`/`legend`.

### 3. 조건 이유 상세

- **데이터** **[코드]**: 조건 대안별 결과(`anyOf` 비교의 “대안 1, 대안 2”), `checks[{field, result, message}]`, 남은 확인, 기간, 출처.
- **상태**: 후보는 맞은 대안만 강조, 확인 필요는 아직 모르는 대안 나열, 불일치는 모든 대안과 다름.
- **이벤트**: 혜택 목록으로, 공식 안내에서 조건 확인, 비교 조건 수정.
- **접근성**: 제목 단계 h1 → h2, 대안은 목록, 결과는 ‘맞음 / 확인 필요 / 조건 없음’ 글자로.

### 4. 여행 조건 (2/5)

- **데이터** **[코드]**: `departureId`(`central`/`east`), 날짜, `availableMinutes` 1~1440, `budget` 0~10,000,000, `partySize` 1~6(기본 1), `walkingLimitMinutes` 0~720, `avoidStairs`.
- **상태**: 입력 가능, 필드 오류, 다른 탭에 갔다 와도 초안 유지.
- **이벤트**: 값 바꾸기, 지역·혜택 비교하기(검사 후 3/5), 이전 단계.
- **접근성**: 단계 표시줄 `role="progressbar"` + `aria-valuenow`, 선택지는 `fieldset`, 스위치 `role="switch"`, 오류가 있으면 첫 오류 필드로 포커스.

### 5. 지역·혜택 비교 (3/5)

- **데이터** **[코드]**: `regionId`, `name`, `fitStatus`, `reasons`, `estimate{travelMinutes, walkingMinutes, costPerPerson}`, `checks{time, walking, budget}`(`met`/`unmet`/`unknown`), 추천 경험, 가상 지역 혜택 수. 정렬 `fit`/`benefits`.
- **상태**: 한도 안, 한도 근접(기준 미정), 맞는 경험 부족, 값 모름(null은 0으로 계산하지 않음).
- **이벤트**: 정렬 바꾸기, 이 지역 선택, 조건 바꾸기.
- **접근성**: 수치는 단위와 한도를 글자로, 모르는 값은 ‘알 수 없음’. 공식 혜택은 비용에서 빼지 않는다는 안내를 글로 둔다.

### 6. 경험 추천·근거 (4/5)

- **데이터** **[코드]**: 경험 `id, title, durationMinutes, synthetic`, 근거 `evidence[{claim, sourceLabel}]`, 아쉬운 점, 담김 여부, 조건 때문에 뺀 경험과 이유.
- **상태**: 담김, 안 담김, 근거 펼침, 뺀 경험 있음.
- **이벤트**: 근거 보기·접기, 코스에 담기·빼기, 뺀 경험 보기, 코스 확인하기.
- **접근성**: 담기 버튼은 `aria-pressed`, 버튼 이름에 경험 이름 포함. 담은 개수 변화는 `aria-live`. 근거의 출처 표시까지 읽어 준다.

### 7. 코스 편집·저장 (5/5) + 저장 실패

- **데이터** **[코드]**: 코스 이름, 경험 순서, `legs[{from, to, mode, minutes}]`(minutes는 null 가능), `estimate`, `checks`, `warnings`, 저장 당시 조건 스냅샷.
- **상태**: 편집 중, 저장 중, 저장 완료(저장한 코스로 이동 + 알림), 저장 실패(`STORAGE_UNAVAILABLE`/`STORAGE_CORRUPT`, 초안 유지).
- **이벤트**: 위로·아래로, 빼기, 이름 바꾸기, 코스 저장(직접 눌러야 저장), 다시 저장.
- **접근성**: 순서 버튼 이름에 경험 이름, 옮긴 뒤 “2번째로 옮겼어요” 알림, 첫·끝 버튼 `aria-disabled`, 경고 `role="status"`, 실패 `role="alert"`.

### 8. 저장한 코스

- **데이터** **[코드]**: 저장 키 `growing-travel.local-demo.v1`(브라우저 저장). 코스 이름, 저장일, 경험, 수치, 저장 당시 내 조건·여행 조건.
- **상태**: 방금 저장(알림), 목록, 비어 있음(화면 없음), 읽기 실패(화면 없음).
- **이벤트**: 다시 열기, 알림 닫기.
- **접근성**: 목록은 `ul`, 카드 전체가 하나의 링크. 알림은 `role="status"`이며 너무 빨리 사라지지 않게 한다. 다시 열어도 지금 혜택 비교 조건은 바뀌지 않는다는 점을 글로 둔다.

### 9. 모든 화면 공통

- 하단 메뉴 4개(여행 · 혜택 · 저장한 코스 · 내 설정)는 현재 시연 기준이다. 탭을 오가도 입력과 초안은 남는다. 지금 탭은 `aria-current="page"`.
- 360~430px 한 열. 하단 메뉴·키보드·안전 영역이 입력칸·오류·저장 버튼을 가리지 않게 한다. 터치 영역 최소 44px.
- 가상 지역·경험·코스·혜택에는 항상 점선 태그를 붙인다. 공식 혜택을 가상 코스 비용에서 빼지 않는다.
- 아직 그리지 않은 화면: 여행 1/5 ‘내 설정 확인’, 내 설정 탭, 혜택 불러오는 중, 저장한 코스 빈 목록과 읽기 실패.

## 미확정 질문

결정 장부의 Q 항목으로 올리지 않은 디자인 질문이다. 사용자가 정하면 결정 장부에 기록한다.

1. 하단 메뉴 4개를 최종 정보 구조로 확정할지.
2. 조건 수정에 ‘이번 비교에만 적용’을 넣을지. 지금 시연은 저장만 있다.
3. 시트를 저장하지 않고 닫으면 바꾼 값을 버릴지, 초안으로 남길지.
4. 혜택 카드를 한 번에 하나만 펼칠지, 여러 개를 펼칠 수 있게 할지.
5. 학생 표시를 혜택 자료의 새 필드로 둘지, 조건 규칙에서 계산할지.
6. 접힌 카드의 한 줄 이유를 자료에 직접 쓸지, 이유 목록에서 만들지.
7. 도보·예산의 ‘한도 근접’ 기준을 몇 %로 할지(예: 90%).
8. 시간·걷기 한도를 선택지 3개로 받을지, 숫자로 직접 받을지.
9. 오류 빨강과 주의 색, Gothic A1 글꼴을 이대로 쓸지.
10. 혜택 자료의 확인일이 며칠 지나면 ‘오래된 자료’로 알릴지.
11. 학생 조건 혜택이 몇 개를 넘으면 탭 방식을 다시 볼지.
12. 운영 기술·AI 모델·실기기 검사 계획은 결정 장부 Q03·Q06에 따라 여전히 미정이다.

## 확인한 것과 하지 않은 것

- 확인함: 시연 코드의 필드·상태 이름과 나이 범위(1~120)를 읽고 문서·캔버스 문구를 맞췄다. 캔버스의 펼치기·접기 로직은 화면 없이 따로 실행해 한 번에 하나만 펼쳐지는 것을 확인했고, 사용자가 캔버스에서 직접 눌러 보고 문제가 없다고 알려 주었다.
- 하지 않음: 캔버스 화면 렌더링 자동 검사, 실기기·가상 키보드·화면 낭독기 검사, 앱 자동 검사 재실행, 혜택 공고 재조사, 앱 코드 변경, 외부 전송.

## 추가 · 디자인 스킬 점검 (2026-10-26)

사용자 요청으로 프로젝트 `.claude/skills/`에 frontend-design(Anthropic), web-design-guidelines(Vercel), bencium-controlled-ux-designer(bencium, MIT)를 설치했다. 세 스킬 모두 문서만 있고 실행 코드는 없으며, 설치 전에 내용을 읽었다. 문서 검사 스크립트는 다른 도구 폴더처럼 `.claude`를 검사 대상에서 뺐다. 스킬 문서의 키 이름(F12)을 결정 번호로 잘못 읽었기 때문이다.

Vercel 웹 인터페이스 규칙으로 흑연·코발트 캔버스 화면 20장의 코드를 읽어 점검했고, 다음은 캔버스에 반영했다. 구현할 때도 같은 기준을 따른다.

- 모든 버튼·링크·입력에 보이는 키보드 포커스(`:focus-visible`, 코발트 3px).
- 하단 메뉴와 시트 아래 여백에 `env(safe-area-inset-bottom)`.
- 입력칸에 `name`, 인증과 무관한 칸은 `autocomplete="off"`.
- 시트에 `overscroll-behavior: contain`.
- 입력 오류가 있어도 적용 버튼은 켜 두고, 누르면 첫 오류 필드로 포커스를 옮긴다.
- 숫자는 같은 폭(`tabular-nums`), 제목은 `text-wrap: balance`, `touch-action: manipulation`, `prefers-reduced-motion` 존중.

그림으로 표현할 수 없어 구현 때 처리할 것: 숫자·날짜는 `Intl.NumberFormat`·`Intl.DateTimeFormat`, 저장 중은 ‘저장 중…’과 중복 누름 방지, 저장하지 않은 조건이 있을 때 떠나기 전 확인, 긴 이름은 카드에서 2줄까지, 본문으로 건너뛰기 링크.

사용자 결정이 필요한 시각 제안(캔버스 ‘고도화 · 스킬 점검 결과와 시각 개선 제안’ 대지): 가운뎃점으로 잇는 문장을 이름표+값으로 바꾸기, 화살표(→) 대신 문장, 혜택 카드에만 티켓 반원 홈 되살리기, 안내 상자·요약칸 모서리 12로 낮추기, 코발트를 #3446C9 쪽으로 깊게 하는 비교안, 실제 앱에서 한글 UI 글꼴 비교. 필터·펼친 카드의 URL 반영, 다크 모드, 코스 순서의 끌어서 옮기기, 빼기 되돌리기, 불러오는 중 화면도 결정이 필요하다. 이 점검은 코드 읽기 기준이며 실기기·화면 낭독기 검사가 아니다.

같은 날 사용자 요청으로 시각 제안 중 네 가지를 캔버스에 반영했다. 코발트 색과 글꼴은 그대로 둔다.

- 내 조건 요약은 가운뎃점 한 줄 대신 ‘나이 / 거주 / 학생’ 이름표와 값으로 보여 준다. 학생 값 아래에 ‘본인 입력’을 붙인다. 다른 메타 문장도 가운뎃점 대신 쉼표로 잇고, ‘맞는 이유’ 같은 이름표는 문장 위 한 줄로 둔다.
- 이유 문장에서 화살표를 빼고 문장으로 쓴다(예: “만 23세라서 ‘만 24세 이하’ 조건에 맞아요.”). 순서 자체를 보여 주는 경로(안개정원 → 느린 서가 → 햇살 식탁)는 화살표를 유지한다.
- 혜택 카드에만 절취선 양끝 반원 홈을 둔다. 지역·저장 코스 카드는 점선만 쓴다.
- 모서리는 카드 20, 입력·안내 상자·요약칸 12, 태그 6, 하단 메뉴 24, 버튼은 알약형으로 정리한다.
