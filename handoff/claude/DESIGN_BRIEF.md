# Growing Travel · 클로드 디자인 전달서

기준일: 2026-10-24 (Asia/Seoul). 한국어 스마트폰 앱을 위한 디자인 작업 입력이다. 이 전달서는 현재 제품 범위와 필요한 상태를 설명하며, 최종 디자인·네이티브 기술·실제 서비스 출시를 확정하지 않는다. 문서 안의 인물·테스트 조건은 가상 예시이며 실제 사용자 개인정보가 아니다.

## 제품의 중심

**Growing Travel — 여행할수록 함께 자라는 AI 여행 추천.** 우선 사용자는 20대 청년, 혼자, 차 없이 기차·대중교통·도보로 여행하는 사람이다. 대학생도 포함하지만 대학생만의 서비스는 아니다. 시간·예산·걷기 부담에 맞춰 작은 경험을 찾고 코스를 저장하는 일과, 여행 전에 챙길 공식 혜택을 이해하는 일을 돕는다.

장기 흐름은 경험 발견 → 상황 추천 → 짧은 코스 구성·수정 → 개인 여행 기록 → 선택적 공개·방문 후 확인 → 다음 추천 반영이다. 지금 디자인의 주 범위는 **개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험·근거 → 코스 저장·재열람**, 그리고 언제든 접근하는 **맞춤 혜택 탭**이다. 실제 후기·평점·게시판과 여행 후 기록·공개는 후속이며 현재 화면에 가짜 별점·후기 수를 넣지 않는다.

외국인 전용 한국 여행, 업체용 컨시어지, 자동 예약·결제 서비스로 바꾸지 않는다. 지금 작업은 디자인안 준비이며 운영 앱 구현·배포·가입을 요구하지 않는다. HTML/JavaScript 로컬 시연이 있지만 React Native·Flutter·Android·iOS 기술은 미확정이다.

색·타이포·최종 브랜드 시스템은 제안 영역이다. 현 시연의 녹색 `#245D4D`, 크림색 `#F6F5EF`는 참고 색이며 고정된 브랜드 승인 값이 아니다. 차분하고 가벼운 여행의 느낌과 정보의 명확함을 함께 제안한다. 플랫폼·정확한 지원 기기·예산·디자인 도구는 미확정이다.

하단 탭 왕복과 이전 이동에서 입력·선택·초안이 유지됨을 전제로 한다. 이미 저장한 코스를 다시 열어 표시하는 ‘당시 설정’은 현재 맞춤 혜택의 개인 기준을 조용히 바꾸지 않는다. 현재 혜택 비교에 쓰는 값과 저장 여부가 사용자가 이해할 수 있게 드러나야 한다.

## 맞춤 혜택의 두 가지 상태 축

**개인 조건 상태**와 **공고 진행 상태**를 한 개의 ‘사용 가능’ 배지로 합치지 않는다.

| 개인 조건 상태 | 화면 문구 | 필요한 설명 |
| --- | --- | --- |
| candidate | 조건이 맞는 후보 | 입력과 맞는 알려진 조건, 여전히 필요한 가입·증빙·예산·재고 확인 |
| needs_info | 추가 확인 필요 | 부족한 값·출생연도/시군구 같은 입력 한계·출처 미확인 이유, 수정 경로 |
| not_matched | 알려진 조건 불일치 | 어느 조건이 다른지와 입력 수정 가능성. 영구 자격 거절 표현 금지 |
| not_current | 현재 기간 아님 | 공고 시작 전/종료와 날짜. 현재 신청 후보처럼 표시 금지 |

기본 우선순위는 후보 → 추가 확인 필요 → 불일치 → 현재 기간 아님이다. 뒤의 두 그룹은 다른 혜택으로 명확히 구분해 볼 수 있게 제안할 수 있다. 공고 배지는 `공고 기간 중`, `상시 제도 안내`, `진행 확인 필요`, `시작 전`, `기간 종료`를 별도로 표시한다. 기간 중이더라도 조기 마감될 수 있다.

혜택 카드에 필요한 정보는 명칭, 분야·지원 유형, 개인 조건 상태, 공고 상태, 맞거나 모르는 이유, 신청/사용 기간, 남은 확인, 공식 출처 링크, 자료 확인일이다. 모든 긴 정보를 한 번에 펼칠 필요는 없지만 상태를 판단하는 데 필수인 이유·기간·한계를 상세에만 숨기지 않는다. 문구 길이와 펼침 구조는 제안해 달라.

## 개인 입력의 의미

- 나이는 만 나이이며 생년월일이 아니다. 출생연도 조건을 나이로 단정하지 않는다.
- 거주지는 시·도이며 여행 출발지·목적지와 다르다. 시군구까지 필요한 조건은 추가 확인이다.
- 대학생은 `미입력 / 대학생 / 대학생 아님`. 미입력을 비대학생으로 표시하지 않는다. 자기 보고는 재학 인증이 아니다. 학생 조건이 없는 사업에 학생 배지·우대를 꾸미지 않는다.
- 학교명·학번·학생증·정밀 주소를 추가로 받는 화면을 넣지 않는다. 추가 인증은 후속 미확정이다.

## 디자인 상태를 위한 가상 시나리오

아래 ‘가상 혜택 A’는 **디자인·로직 설명용 창작 예시이며 실제 지원 사업이 아니다**. 실제 정부 로고·신청 링크·실적을 붙이지 않는다. 가상 조건은 만 19~29세·서울 거주·대학생, 신청 기간은 2026-10-01~11-30이다. 카드에는 `가상 예시 · 신청 불가`를 유지한다.

| 가상 입력 / 기준일 | 표현할 상태 |
| --- | --- |
| 만 24세·서울·대학생 / 2026-10-24 | 조건이 맞는 후보. 남은 확인은 가상 증빙·예산 조건. 확정 승인 표현 없음 |
| 나이·거주·학생 모두 미입력 / 2026-10-24 | 추가 확인 필요. 강제 입력 없이 전체 안내 계속 보기 가능 |
| 만 35세·서울·대학생 아님 / 2026-10-24 | 알려진 연령·학생 조건 불일치. 입력 수정 경로 제공 |
| 만 24세·서울·대학생 / 2026-12-01 | 현재 기간 아님. 개인 조건이 맞아도 진행 중 후보로 표시하지 않음 |

실제 공식 자료를 사용하는 화면안에서는 공고 문구·확인일을 원문 근거에 맞춰 별도로 적용한다. 예시로 확인한 K-패스·숙박세일 페스타·청년문화예술패스는 각각 조건과 기간이 다르므로 위 가상 조건을 복사하지 않는다. 확인일 이후 실제 잔여 예산·접수 상태는 보장할 수 없다.

실제 등록 안내는 국립현대미술관 서울관을 포함한 7개를 기준으로 준비한다. [미술관 공식 안내](https://www.mmca.go.kr/visitingInfo/seoulInfo.do)의 무료 관람 조건은 24세 이하 또는 65세 이상, 또는 대학 학부생처럼 대체 경로가 있다. 가상 입력 `만 23세·서울·대학생`은 미술관의 연령 경로와 K-패스의 알려진 개인 조건에 맞는 후보를 설명하는 데 사용할 수 있다. 반면 `만 27세·대학생`은 학부생 여부가 확인되지 않아 미술관은 추가 확인이 필요하다. 대학생 여부가 아니라 나이 때문에 후보가 된 경우 그 이유를 정확히 쓴다. 이 예시도 실제 사용자나 혜택 수혜 사례가 아니다.

## 접근성·상호작용 기준

360~430px 대표 폭에서 한 열 읽기와 손가락 조작을 우선 제안한다. 버튼·탭은 최소 44px 조작 영역, 본문·입력은 읽기 쉬운 크기와 줄 간격, 상태 텍스트는 충분한 대비를 목표로 한다. 색상만으로 후보·확인 필요·불일치를 구분하지 않는다. 하단 메뉴·키보드·안전 영역이 입력·오류·저장 버튼을 가리지 않게 한다. 이 수치는 설계 목표이며 실기기 검사 완료를 뜻하지 않는다.

필드에 지속적으로 보이는 이름을 붙이고 오류를 해당 필드와 연결한다. 필터 결과 수·저장 결과는 보조기술로도 이해할 수 있어야 한다. 상세 창을 닫으면 이전 선택과 초점이 유지되고, 화면 이동 후 현재 위치가 드러나야 한다. 모바일을 우선하면서 데스크톱에서는 앱 폭 미리보기를 고려한다.

## 요청하는 디자인 산출물

1. 정보 구조와 핵심 흐름도, 각 화면의 주된 행동 설명.
2. 혜택 목록·조건 수정·조건 이유 상세의 모바일 와이어프레임. 후보 있음·추가 확인만 있음·불일치·기간 종료·필터 0개·오류 상태를 포함.
3. 개인 설정·여행 조건·추천·코스 저장·저장 목록까지 연결되는 주요 화면안. 후기·게시판은 현재 흐름에 넣지 말고 후속 목록에만 표시.
4. 카드·배지·필터·탭·입력·오류·저장 피드백 컴포넌트와 색·타이포·간격 제안. 제품 결정과 디자인 가정을 구분.
5. 개발 전달용 화면별 데이터·상태·이벤트·접근성 주석, 미확정 질문, 사용한 실제/가상 자료 목록.

이 산출물은 디자인 제안이다. 실제 앱 배포·정부 혜택 신청·외부 서비스 가입·개인정보 전송은 실행하지 않는다.
