# 클로드·클로드 디자인에 복사할 요청문

각 코드 블록 전체를 해당 도구의 새 대화에 붙이고 안내된 전달서를 첨부한다. 아래 요청문은 사용자가 외부 도구에서 사용할 초안이며 현재 도구에 이미 전송된 명령이 아니다.

## 클로드에 보낼 요청문

```text
첨부한 PRODUCT_AND_DEVELOPMENT_BRIEF.md를 기준으로 Growing Travel의 제품·개발 구성을 검토하고, 디자인 작업에 넘길 기획·화면 명세를 정리해줘.

서비스는 ‘여행할수록 함께 자라는 AI 여행 추천’이고, 우선 타겟은 20대의 혼자·무차량·기차/대중교통·도보 여행이야. 현재 흐름은 개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험 추천과 근거 확인 → 코스 수정·저장·재열람이야. 하단에는 여행·혜택·저장한 코스·내 설정이 있어.

이번 핵심은 만 나이·거주 시도·대학생 여부로 공식 근거가 있는 혜택 조건을 비교해 ‘조건이 맞는 후보’를 먼저 보여주고 ‘추가 확인 필요’와 구분하는 거야. 알려진 조건 불일치와 현재 기간 아님도 이유를 표시해. 개인 조건 상태와 공고 진행 상태는 별개이고, 후보는 지원 확정이 아니야. 미입력을 비대상으로 판단하지 말고 출생연도·시군구·재학 인증을 현재 필드에서 추정하지 마. 학생 조건이 없는 사업에는 임의 가점을 주지 마.

우선 코드를 작성하기보다 다음을 정리해줘.
1. 제품 흐름의 빈틈·충돌과 수정 제안
2. 개인 조건·공고 상태의 데이터 계약과 판정 근거
3. 화면별 데이터·상태·사용자 문구와 미입력·불일치·기한 경계·저장 호환·현재 설정과 과거 코스 분리의 검증 시나리오
4. 다음 구현 과제와 사용자 결정이 필요한 미확정 사항

사용자 결정, 구현 제안, 미확정을 분리해줘. 기존 로컬 시연의 HTML/JavaScript·Node.js·localStorage·규칙 기반 처리를 운영용 최종 스택이나 AI 모델 확정으로 취급하지 마. 실제 후기·별점·게시판·여행 후 기록·공개·방문 확인은 후속이야. 가상 지역·장소·동선·가격·지역 혜택을 실제 방문·검증 자료로 바꾸지 마. 공식 혜택은 가상 코스 비용에 적용하지 않아.

외국인 전용 한국 여행, 업체 컨시어지, 자동 예약·결제 대행으로 전환하지 마. 배포·유료 가입·커밋·푸시·외부 신청은 하지 마. 실제 프로젝트 파일을 추가로 제공하고 구현을 요청하면 그때 기존 지침·README·구조·변경분을 읽고 필요한 부분만 병합해줘. 실제로 수행한 검사만 결과로 보고해줘.
```

## 클로드 디자인에 보낼 요청문

```text
첨부한 DESIGN_BRIEF.md를 기준으로 Growing Travel의 한국어 모바일 앱 디자인안을 만들어줘.

서비스는 20대가 혼자 차 없이 기차·대중교통·도보로 여행하면서, 상황에 맞는 경험과 짧은 코스를 찾고 여행 혜택을 이해하도록 돕는 앱이야. 대학생만의 서비스는 아니야. 제품의 중심 흐름과 현재 범위를 바꾸지 말아줘.

하단 메뉴는 여행·혜택·저장한 코스·내 설정으로 구성해줘. 여행 흐름은 개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험 추천·근거 → 코스 편집·저장·재열람이야. 혜택 탭은 설정을 입력하기 전에도 열 수 있어야 해.

디자인의 가장 중요한 과제는 ‘조건이 맞는 후보’와 ‘추가 확인 필요’를 쉽게 구별하면서도 후보를 ‘지원 확정’처럼 보이게 하지 않는 거야. 개인 조건 상태와 공고 진행 상태를 분리하고, 맞는 이유·부족한 정보·남은 확인·공식 출처·확인일을 읽기 쉽게 보여줘. 불일치·기간 종료·필터 0개도 포함해줘. 만 나이·거주 시도·대학생 여부는 선택 입력이며 미입력은 비대상이 아니야. 재학 인증·학교명·학생증 수집 화면을 추가하지 마.

다음 산출물을 순서대로 제안해줘.
1. 정보 구조와 핵심 흐름도
2. 맞춤 혜택·개인 설정 중심 모바일 와이어프레임과 상태별 화면
3. 여행 조건·지역 비교·추천·코스 저장·저장 목록 연결 화면
4. 카드·상태 배지·필터·탭·입력·오류·저장 피드백 컴포넌트와 색·타이포·간격 제안
5. 개발 전달용 화면별 데이터·이벤트·상태·접근성 주석과 미확정 질문

360~430px 모바일 폭, 한 손 조작, 읽기 쉬운 글자, 최소 44px 조작 영역, 색상 외 텍스트 상태 구분, 하단 메뉴·키보드 여백을 고려해줘. 위 수치는 설계 목표이며 실제 기기 검사 완료로 표현하지 마.

사용자 결정과 네 디자인 가정을 분리해줘. 현 시연 색은 참고일 뿐 최종 브랜드 승인으로 취급하지 마. 전달서의 가상 예시는 ‘가상 예시·신청 불가’로 표시하고 실제 정부 혜택 조건에 복사하지 마. 가짜 후기·별점·후기 수·실제 방문 인증을 만들지 마. 실제 후기·게시판은 후속 목록으로만 남겨줘.

운영 스택·AI 모델·React Native/Flutter·Android/iOS를 임의로 확정하지 마. 외국인 전용 플랫폼·업체 컨시어지·예약 결제 대행으로 방향을 바꾸지 마. 결과는 디자인 제안이며 외부 가입·배포·혜택 신청·개인정보 전송은 실행하지 마.
```
