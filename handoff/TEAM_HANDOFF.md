# Growing Travel 팀 인수인계

기준일: 2026-10-27. 현재 대상은 `dist/`의 여행자용 웹 MVP다. 서울 출발 춘천·가평·강릉의 실제 장소를 선택하고 왕복 동선을 편집·저장한다. 추천은 규칙 기반이며 외부 AI 호출은 없다. 이 문서는 저장소 업로드 또는 운영 배포 완료를 뜻하지 않는다.

공유 대상은 비공개 [GitHub 저장소](https://github.com/khi6174/growing-travel)다. 업로드 후 접근 권한이 있는 GitHub 계정으로 로그인해 내려받는다. 404가 표시되면 저장소 주소와 계정의 접근 권한을 확인한다.

## 바로 실행하기

저장소를 내려받고 압축을 풀었다면 `README.md`와 `dist/`가 있는 폴더에서 실행한다. 기존 검증 환경은 Node.js v24.14.0이다. HTML/CSS/JavaScript와 Node.js 기본 모듈만 사용하므로 `npm install`이나 빌드는 필요 없다.

Windows PowerShell:

```powershell
# 실제 내려받은 폴더 경로로 바꾼다.
Set-Location -LiteralPath 'C:\성장 여행 서비스'
node --version
node scripts/serve.mjs
```

macOS / Linux:

```bash
# 실제 내려받은 폴더 경로로 바꾼다.
cd '/path/to/growing-travel'
node --version
node scripts/serve.mjs
```

서버 시작 메시지 후 브라우저에서 <http://127.0.0.1:4173>을 연다. 종료는 `Ctrl+C`다. Web Locks를 지원하는 Chrome 또는 Edge를 사용한다. HTML 파일을 직접 열지 않는다. 기본 포트가 사용 중이면 `node scripts/serve.mjs --port 4174`로 실행하고 <http://127.0.0.1:4174>를 연다. `PORT` 환경변수는 이 서버의 설정 방법이 아니다. 서버는 해당 컴퓨터의 루프백 주소에만 열리므로 팀원은 각자 실행한다.

## AI 추천 설정 (2026-10-30 추가)

AI 추천은 서버(`scripts/serve.mjs`)에서만 호출한다. [.env.example](../.env.example)을 `.env`로 복사해 제공자와 키를 넣는다. `.env`는 Git에 올라가지 않으며 브라우저로 전달되지 않는다. 서버 시작 메시지의 `AI:` 줄에서 적용 여부를 확인한다.

- `AI_PROVIDER=anthropic`(기본, `ANTHROPIC_API_KEY`) · `openai`(`OPENAI_API_KEY`, `OPENAI_MODEL`) · `school`(`SCHOOL_AI_BASE_URL`, `SCHOOL_AI_API_KEY`, `SCHOOL_AI_MODEL`, OpenAI 호환 형식 가정) · `none`
- 키가 없거나, 응답이 늦거나(`AI_TIMEOUT_MS`, 기본 10초), 형식이 틀리면 목적·이동 부담·현장 소식 순서의 규칙 정렬로 3곳을 채운다(2026-11-02 펫 흐름 기준).
- 펫·구·동네 친구·후보지는 [data/](../data/) 아래 JSON 4종, 현장 제보는 `data/runtime/reports.json`(Git 제외)에 저장된다. `node scripts/places.mjs`로 형식을 검사한다.
- 장소 좌표를 TourAPI와 대조하려면 `.env`에 `TOURAPI_KEY`(공공데이터포털 국문 관광정보 서비스의 일반 인증키 Decoding)를 넣고 `node scripts/tourapi-places.mjs`를 실행한다. `--write`일 때만 파일을 바꾸고, 이미 TourAPI 좌표인 곳은 `--all`일 때만 다시 조회한다. 2026-11-02에 한 번 실행해 118곳을 반영했다. 이름이 TourAPI 제목과 달라 검색되지 않는 곳은 places.json의 `tourapi_keyword`에 검색어를 넣는다. 키의 일일 호출 한도는 공공데이터포털 마이페이지에서 확인한다.
- 명세 4장의 시나리오 10개는 `node scripts/scenarios.mjs`로 앱과 같은 API 경로에서 실행하고 통과 기준을 표로 본다. `.env`의 AI를 쓰며, `--rules`는 규칙 정렬만, `--out 파일.json`은 결과를 저장한다. 2026-11-02 규칙 정렬 실행은 10개 모두 통과했다.
- 2026-11-02 펫 흐름의 변경과 검사 범위는 [서울 펫 MVP 기록](../plans/15_SEOUL_PET_MVP.md)에 있다.

## 살아 있는 지도의 카카오맵 키 (2026-11-02 추가)

키가 없어도 지도 화면은 같은 내용을 목록으로 보인다. 카카오맵으로 보려면 키를 받은 사람이 아래를 한다.

1. [카카오 개발자](https://developers.kakao.com)에서 앱을 만든다. 무료 쿼터는 계정에서 처음 활성화한 앱에만 준다.
2. 앱의 [카카오맵] > [사용 설정]을 ON으로 바꾼다.
3. [앱 설정] > [플랫폼 키] > JavaScript 키의 'JavaScript SDK 도메인'에 지도를 여는 주소를 등록한다. 예: `http://localhost:4173`, `http://127.0.0.1:4173`, 휴대폰 시연의 `https://<노트북 주소>:4443`. 앱당 기본 10개까지 등록할 수 있다. IP 주소·포트 등록이 되는지는 아직 확인하지 않았다.
4. `.env`에 `KAKAO_JS_KEY=`(32자리 JavaScript 키)를 넣고 서버를 다시 켠다. 서버 시작 문구의 `지도:` 줄로 확인한다. 이 키는 브라우저로 전달되는 키라서 등록한 도메인에서만 동작한다. REST API 키를 넣지 않는다.

2026-11-02 확인: IP 주소·포트가 들어간 주소(`https://10.155.128.90:4443`)도 등록된다. 핫스팟을 다시 켜서 노트북 주소가 바뀌면 그 주소를 도메인에 다시 등록해야 지도가 뜬다(안 뜨면 목록으로 보인다). 지도 화면에 "카카오맵을 불러오지 못했어요"가 나오면 사용 설정 ON과 도메인 등록부터 본다.

## 휴대폰 시연 (구 도착·동네 친구, 2026-11-02 추가)

11/5 시연 순서와 당일 점검표는 [시연 안내](DEMO_GUIDE_2026-11-05.md)에 있다.

휴대폰 브라우저는 HTTPS 페이지에만 위치를 준다. 노트북과 휴대폰을 같은 와이파이에 두고 아래 순서로 연다. 외부 터널은 쓰지 않는다.

1. `node scripts/make-cert.mjs`: `.cert/`에 30일짜리 자체 서명 인증서를 만든다(Git 제외). 와이파이가 바뀌어 노트북 주소가 달라지면 다시 실행한다. Git for Windows의 openssl을 쓴다.
2. `node scripts/serve.mjs --lan`: 실행 화면의 `휴대폰: https://…:4443/?code=…` 주소를 휴대폰에서 연다. 접속 코드는 실행할 때마다 바뀐다. 사설망이 아닌 주소라는 경고가 나오면 코드를 공유하지 않는다.
3. 인증서 경고에서 '고급 → 계속'(Android Chrome) 또는 '세부사항 보기 → 웹 사이트 방문'(iOS Safari)을 고른다. Windows 방화벽 허용 창이 뜨면 직접 판단한다.
4. 홈의 "구 도착 알림 켜기" → 위치 허용. 처음 잡힌 구와 새로 들어간 구마다 동네 친구 배너가 뜬다.
5. 시연이 끝나면 `Ctrl+C`로 끈다.

휴대폰에서 열리지 않으면 아래를 차례로 본다.

- **주소가 바뀌었는지:** 서버는 켤 때의 노트북 주소로만 답한다. 와이파이를 바꾸거나 다시 연결했다면 `node scripts/make-cert.mjs`와 `node scripts/serve.mjs --lan`을 다시 실행하고 새로 나온 주소를 연다.
- **Windows 방화벽:** Node.js가 '개인 네트워크'에서만 허용돼 있고 지금 와이파이가 '공용 네트워크'로 잡혀 있으면 휴대폰 접속이 막힌다. 믿을 수 있는 와이파이라면 Windows 설정 → 네트워크 및 인터넷 → Wi-Fi → 그 와이파이 → 네트워크 프로필 유형을 '개인'으로 바꾼다. 공용 와이파이에서는 바꾸지 않는다.
- **와이파이의 기기 간 차단:** 카페·학교 와이파이가 기기 간 접속을 막으면 열리지 않는다. 이때는 휴대폰 핫스팟에 노트북을 연결하고, 핫스팟을 개인 네트워크로 둔 뒤 위 두 명령을 다시 실행한다.

2026-11-02 휴대폰 핫스팟(노트북 네트워크 '개인')에서 인증서 경고를 넘기고 위치를 허용하자 동네 친구가 나타나는 것을 확인했다(사용자 보고). 걸어서 구 경계를 넘을 때의 감지와 시연 장소 와이파이는 아직 확인하지 않았다.

## 확인할 기능

1. 홈 → 취향·개인 설정 → 여행 조건 → 지역 비교 → 경험 추천 → 코스 순으로 진행한다. 청량리·서울·용산 출발역, 춘천·가평·강릉 3개 지역, 실제 장소 8개를 제공한다.
2. 장소 상세에서 주소·출처·확인일·운영 안내를 읽고 장소 선택과 순서를 바꾼다. 확인된 화요일 휴무는 소양강스카이워크 추천에서 제외한다.
3. 출발역 → 지역역 → 장소들 → 지역역 → 출발역의 왕복 동선을 확인한다. 카카오 대중교통·도보 링크와 코레일 확인 링크를 열고 필요한 구간 시간을 직접 입력한다. 모든 구간 시간이 있어야 체류 계획을 더한 전체 시간이 표시된다.
4. 코스 이름을 정하고 명시적으로 저장한 뒤 새로고침 → 저장한 코스 → 다시 열기를 확인한다. 순서·입력 시간·당시 조건이 유지되어야 한다. 기존 가상 저장본은 ‘이전 예시 코스’로 구분한다.
5. 초기 화면에서도 혜택 탭을 열 수 있다. 나이·거주지·대학생 여부는 선택 입력이다. 개인 조건 비교와 공고 기간·확인 상태를 각각 읽는다. 혜택 후보는 수혜 확정이 아니며 코스 비용에서 자동 차감하지 않는다.

## 함께 알아둘 범위

- 지도와 코레일은 외부 확인 링크다. 실시간 교통 API·자동 시간표·운임·막차·예약 가능 여부를 가져오지 않는다. 코레일에서는 출발지·도착지·날짜를 별도로 선택한다. 좌표는 장소 대표점이며 출입구·승차장 보장이 아니다.
- 구간 시간은 사용자가 넣은 계획값, 체류 시간은 계획 제안이다. 미확인 비용·도보량은 `null`로 남기며 0원·도보 없음으로 처리하지 않는다. 당일 영업과 실제 이동 가능성은 별도 확인이 필요하다.
- 개인 설정과 코스는 각자의 브라우저 `localStorage`에 저장한다. 팀원이 같은 코드를 받아도 저장 데이터는 공유되지 않는다. `127.0.0.1`과 `localhost`, 다른 포트·브라우저·프로필은 서로 다른 저장 공간이다. 브라우저 데이터 삭제 시 사라질 수 있고 계정·서버 DB·동기화·백업은 없다.
- 개인 설정 삭제는 코스에 담긴 당시 스냅샷까지 삭제하지 않는다. 저장하지 않은 화면 이동은 자동 저장이 아니다. 같은 브라우저 프로필의 다른 사용자에게서 자료를 보호하는 인증 기능이 없으므로 시연에는 테스트용 입력을 사용한다.
- 실제 후기·방문 인증·공개 게시판·예약·결제·운영 배포는 구현·검증 범위에 포함되지 않는다. 실기기·320px·스크린리더 검증도 남아 있다.

`dist/`는 현재 실행 앱, `tests/`는 자동 검사, `scripts/`는 서버·문서 검사다. `wireframes/`는 이전 별도 메모리 시연이며 현재 MVP 실행 대상이 아니다. `handoff/`의 원문·디자인 자료와 `plans/`의 과거 검사는 이력으로 보존한다.
