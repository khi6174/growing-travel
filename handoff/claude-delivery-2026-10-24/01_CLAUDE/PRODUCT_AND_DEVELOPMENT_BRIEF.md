# Growing Travel · 클로드용 제품·개발 전달서

기준일: 2026-10-24 (Asia/Seoul). 이 문서는 독립적으로 읽을 수 있는 제품·개발 입력이다. 현재 로컬 시연과 이번 변경의 목표를 설명하며, 운영 서비스 완성·실데이터 확보·최종 기술 선택을 뜻하지 않는다. 과거 안내서가 열거한 별도 패키지 docs 원문은 확보하지 못했고 이 자료는 사용자 직접 요청과 현재 프로젝트를 정리한 새 문서다.

## 서비스와 사용자

서비스명은 **Growing Travel**, 핵심 문장은 **‘여행할수록 함께 자라는 AI 여행 추천’**이다. 우선 타겟은 20대 청년의 혼자·무차량 여행이다. 기차·대중교통과 도보로 이동하고, 짧은 여행의 시간·예산·걷기 부담을 함께 고려한다. 대학생만을 전체 타겟으로 제한하지 않는다.

장기 중심 흐름은 경험 발견 → 상황에 맞는 추천 → 짧은 코스 구성·수정 → 개인 여행 기록 → 선택적 공개·방문 후 확인 → 다음 추천 반영이다. 현재 구현 범위는 **개인 설정 → 여행 조건 → 지역·혜택 비교 → 경험 추천·근거 확인 → 코스 수정·저장·재열람**이다. 실제 후기·별점·게시판, 여행 기록·공개·방문 확인·다음 추천 반영은 후속이다.

외국인 전용 한국 여행 플랫폼, 한일 업체용 컨시어지, 자동 예약·결제 대행으로 방향을 바꾸지 않는다. 배포·유료 가입·Git 커밋·푸시·외부 예약과 결제는 이번 범위에 없다.

## 결정·선택·미확정 구분

| 구분 | 내용 |
| --- | --- |
| 사용자 결정 | 모바일 앱의 사용 흐름 우선. 혜택 범위는 교통·숙박·여행·문화. 처음부터 혜택 열람 가능. 나이·거주지·대학생 여부로 맞는 후보를 우선 표시하고 추가 확인 필요와 구분. 실제 후기·게시판은 다음 단계 |
| 현재 구현 선택 | HTML/CSS/브라우저 JavaScript 모듈, Node.js 정적 서버, localStorage, 규칙 기반 추천·조건 비교. 단일 단계 화면과 하단 4개 메뉴. 이 구성은 로컬 시연용 |
| 제안 가능한 부분 | 정보 우선순위, 화면 배치·색·글꼴·카드·상세 제시 방법, 추가 검증 시나리오. 기존 데이터와 사실의 의미를 유지해야 함 |
| 미확정 | 운영 스택·AI 모델·Android/iOS 우선순위·실지역·계정/서버 저장·공식 자료 자동 갱신·자격 인증·후기 운영·최종 디자인 |

세부 화면 재디자인은 이전 요청에서 미뤘다. 이번에는 맞춤 혜택 기능을 기존 시연에 반영하고, 별도의 디자인 작업에 사용할 전달 자료를 준비한다. 문서 작성 자체가 디자인 구현 완료를 뜻하지 않는다.

## 현재 정보 구조와 입력

하단 메뉴는 **여행 / 혜택 / 저장한 코스 / 내 설정**이다. 여행 메뉴는 개인 설정·여행 조건·지역 비교·경험 추천·코스 편집의 단계 화면을 연결한다. 혜택은 설정이 비어 있어도 독립적으로 열 수 있다. 탭 이동과 뒤로가기는 입력·선택·초안을 보존한다.

| 입력 | 의미 |
| --- | --- |
| 만 나이 | 선택 입력. 출생연도나 생년월일이 아니며 미입력은 알 수 없음 |
| 거주 시·도 | 선택 입력. 17개 시·도 중 선택. 이번 출발지·목적지와 별개이며 시군구까지 확인되지 않음 |
| 대학생 여부 | `unspecified / student / not_student`: 미입력 / 대학생 / 대학생 아님. 본인 입력이며 재학 인증 아님 |
| 관심·평소 걷기 시간 | 여행 추천의 선호와 기본 걷기 한도. 이번 여행에서 조정 가능 |
| 여행 조건 | 가상 출발역·여행일·왕복 가능 시간·1인 예산·인원(기본 1명)·걷기 한도·계단 회피 |

학교명·학번·학생증·정밀 주소·성별을 추가 수집하지 않는다. 개인 설정 저장은 명시적 선택이며 저장하지 않고도 현재 입력으로 살펴볼 수 있다. 현재 혜택 비교 기준은 개인 설정에서 사용자가 입력한 값이다. 과거 코스를 다시 열 때 표시하는 당시 스냅샷을 현재 혜택 기준으로 조용히 바꾸지 않는다. 화면에서는 현재 입력과 저장 여부를 설명한다.

## 맞춤 혜택의 핵심 계약

혜택의 **개인 조건 상태**와 **공고 진행 상태**를 분리한다. 기간 중이라는 사실은 개인 자격이 맞다는 뜻이 아니며, 후보라는 사실은 오늘 신청·수혜가 가능하다는 뜻이 아니다.

| 개인 조건 상태 | 의미 | 기본 우선순위 |
| --- | --- | --- |
| `candidate` · 조건이 맞는 후보 | 확인된 개인 조건을 입력값이 충족. 가입·증빙·잔여 예산 등 나머지 확인은 여전히 필요 | 1 |
| `needs_info` · 추가 확인 필요 | 필요한 값 누락, 더 상세한 정보 필요, 근거·현재성 부족 등으로 비교 불완전 | 2 |
| `not_matched` · 알려진 조건 불일치 | 공식 근거가 있는 조건 중 입력값과 다른 항목이 있음. 이유와 수정 경로 표시 | 3 |
| `not_current` · 현재 기간 아님 | 공고 시작 전 또는 종료. 개인 조건이 맞더라도 현재 후보처럼 올리지 않음 | 4 |

공고 상태는 공고 기간 중 / 상시 제도 안내 / 진행 확인 필요 / 시작 전 / 종료를 따로 표시한다. 신청 기간과 사용 기간을 구분하고, 예산·수량·좌석의 조기 소진과 확인일 이후 변경 가능성을 노출한다. 필터 결과가 0개면 ‘등록 자료 중 해당 결과 없음’을 설명한다.

비교 결과는 `status`, `label`, `reasons`, `missingFields`, `checks`, `remainingChecks`를 가진다. 조건별 비교는 `met / unmet / unknown / not_used`로 구분한다. 공식 근거가 없는 규칙을 만들어내거나 학생이라는 이유로 임의 가점을 붙이지 않는다. 코드명은 개발 계약이고 사용자 화면에는 이해하기 쉬운 한국어를 쓴다.

나이가 없으면 연령 조건은 확인 필요다. 출생연도 기준은 만 나이만으로 확정하지 않는다. 가능한 출생연도가 대상과 명백하게 겹치지 않을 때만 불일치를 설명하고, 그 외에는 생년 기준 추가 확인을 남긴다. 거주 조건이 시군구까지 필요하면 시도만 입력해도 확인 필요다. 학생 조건이 있는 혜택에서는 자기 보고를 비교에 쓸 수 있지만 기관의 학적 인정 범위·증빙 확인은 별도로 남긴다.

현재 공식 안내는 기존 교통·숙박·여행·문화 6개에 국립현대미술관 서울관 무료 관람 안내를 더한 7개를 대상으로 한다. 각 사업의 조건이 다르며 아래 예시는 2026-10-24 확인 자료 기준이다.

| 실제 안내 예시 | 개인 조건 비교와 남은 확인 |
| --- | --- |
| K-패스 | 확인한 자료 범위에서 만 19세 이상·전국 참여 거주 지역을 비교한다. 거주 시도를 입력하지 않으면 확인 필요. 카드 등록·이용 횟수·실제 주민등록/국적 등은 남은 확인 |
| 국립현대미술관 서울관 무료 관람 | 공식 연령 조건인 24세 이하 또는 65세 이상, 또는 대학 학부생의 대체 경로를 구분. 만 23세는 학생 여부와 관계없이 연령 경로 후보. 만 27세 대학생은 학부생 여부를 현재 필드만으로 확정할 수 없어 추가 확인. 만 27세 비대학생은 알려진 조건 불일치. 전시별 적용·증빙 등은 별도 확인 |
| 청년문화예술패스·숙박 행사 | 출생연도 기준을 만 나이로 확정하지 않는다. 현재 나이와 대상 출생연도가 확실히 겹치지 않으면 불일치를 설명하고, 겹칠 수 있으면 출생연도 확인을 남김 |
| 코레일 안내 중 검색 색인만 확인한 항목 | 명칭·개요는 안내하되 현재 본문 근거·판매 조건을 확인하기 전에는 개인화 후보를 확정하지 않음 |

국립현대미술관의 [공식 서울관 안내](https://www.mmca.go.kr/visitingInfo/seoulInfo.do), [K-패스 안내](https://main.kotsa.or.kr/portal/contents.do?menuCode=01080300) 등 원문 근거와 확인일을 유지한다. ‘나이 또는 학부생’인 조건을 ‘나이와 대학생 모두’로 바꾸지 않는다. 최신 규칙의 근거와 한계는 프로젝트의 공식 출처 기록을 따른다. 새 학생 관련 혜택은 공식 근거가 확보되기 전에는 적용 가능한 사업으로 추가하지 않는다.

## 데이터·저장 경계

실제 공식 혜택 안내와 가상 지역 비교 자료는 다른 자료다. 가상 온유동·바람마을, 역·경험·후기처럼 보이는 설명·동선·시간·가격·지역 혜택은 창작한 시연 값이다. 실제 방문·실제 후기·영업 확인 자료가 아니다. 공식 혜택을 가상 코스 비용에 적용하거나 할인액을 자동 차감하지 않는다.

개인 설정은 `growing-travel.local-profile.v1`, 코스는 `growing-travel.local-demo.v1`에 저장한다. 같은 브라우저 프로필·같은 출처에서만 재열람하며 계정·클라우드 동기화·백업이 없다. 과거 코스의 `profileSnapshot`은 당시 입력이다. 학생 필드가 없는 과거 자료도 읽고 보존한다. 조건 비교나 탭 이동은 저장·삭제·코스 재작성을 실행하지 않는다. 손상된 저장 자료를 자동 초기화하지 않는다.

현재 ‘AI 추천’의 시연 엔진은 규칙 기반이다. 외부 AI 호출이나 개인 설정 외부 전송은 없다. 모델을 연결할 때 필요한 비용·전송 필드·보관·권한은 별도로 결정해야 한다.

## 요청하는 결과물

1. 제품 흐름과 현재 범위에 충돌이 있는지 검토하고 사용자 결정·제안·미확정을 나눠 설명한다.
2. 맞춤 혜택의 데이터 흐름, 상태 전이, 오류·누락·저장 호환·날짜 경계 시나리오를 정리한다.
3. 화면에서 후보의 이유·부족한 값·남은 확인 사항이 드러나는 방안을 제안한다.
4. 구현을 요청받는 경우 기존 파일·사용자 변경을 먼저 읽고 필요한 내용만 병합한다. 완료 보고에는 실제 수정 파일·실행 검사·한계만 적는다.

로컬 실행은 프로젝트 폴더에서 `node scripts/serve.mjs`, 자동 검사는 `node --test tests/*.test.mjs`, 문서 검사는 `node scripts/check-docs.mjs`다. 명령 소개는 실행 결과가 아니다. 직전 단계의 55개 통과 이력은 새 맞춤 혜택 검사의 증거로 재사용하지 않는다.
