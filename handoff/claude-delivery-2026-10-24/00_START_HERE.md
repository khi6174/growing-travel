# Growing Travel · 클로드 전달 ZIP 사용 안내

작성 기준: 2026-10-24. 먼저 압축을 풀고 아래 파일을 첨부한 뒤, 해당 요청문 TXT의 **내용 전체**를 대화 입력란에 붙여 넣는다. TXT는 첨부만 하지 말고 요청문으로 사용한다. ZIP 자체를 읽는 기능에 의존하지 않고 개별 파일로 전달하는 순서다.

2. [화면 설명](03_SCREENS/SCREEN_GUIDE.md)
3. [현재 후보 화면](03_SCREENS/01_CURRENT_CANDIDATE.png)

그다음 [클로드 요청문](01_CLAUDE/PASTE_THIS_REQUEST.txt)을 열어 전체 내용을 복사해 붙인다. 제품 흐름·혜택 조건 계약·검증 시나리오·다음 개발 과제 정리가 목적이다. 공식 조건을 더 검토하게 하려면 [혜택 근거](04_REFERENCE/BENEFIT_SOURCES.md), 검사 범위를 확인하게 하려면 [검사 범위 설명](04_REFERENCE/VERIFICATION_SCOPE.md)을 추가 첨부한다.

3. [현재 후보 화면](03_SCREENS/01_CURRENT_CANDIDATE.png)

그다음 [클로드 디자인 요청문](02_CLAUDE_DESIGN/PASTE_THIS_REQUEST.txt)을 열어 전체 내용을 복사해 붙인다. 정보 구조·와이어프레임·상태별 화면·컴포넌트·개발 전달 주석이 목적이다. 첨부 수를 줄여야 하면 과거 화면 2장을 먼저 빼도 된다. 현재 화면 2장과 화면 설명은 함께 전달한다.

클로드 검토를 먼저 진행했다면 그 결과 중 사용자와 합의한 내용을 디자인 대화에 추가할 수 있다. 디자인 전달서는 단독으로도 사용할 수 있다. 클로드의 제안을 사용자 결정으로 자동 승격하지 않는다.

## 3. 읽는 우선순위와 주의할 차이

- 사용자의 최신 직접 지시 → 해당 전달서의 제품 기준 → 현재 화면 01·02 → 이전 화면 03·04 순서로 읽는다. 과거 화면과 문서가 다르면 현재 전달서가 우선이다.
- 현재 시연의 하단 메뉴는 **여행 / 혜택 / 저장한 코스 / 내 설정** 4개다. 이전 여행 화면의 3개 메뉴는 혜택 탭 추가 전 상태이며 그대로 복제하지 않는다. 4개 메뉴는 현재 구현 기준이고 최종 정보 구조 확정과 구분한다.
- 모든 이미지는 기능 시연 참고다. 최종 디자인 승인이 아니며, 이미지에 없는 화면이 구현되지 않았다는 뜻도 아니다.
- 나이·거주지·대학생 여부는 선택적인 자기 보고다. 후보는 수혜 확정이 아니고, 입력 부족은 조건 미달이 아니다. 가상 여행 자료와 공식 혜택 안내를 구분한다.
- 화면의 나이 등 테스트 조건은 가상 입력이다. 여행 장소·동선·가격은 가상 자료이며 실제 방문·후기·검증 성과가 아니다.
- 혜택 안내는 2026-10-24 확인 자료다. 이 ZIP을 묶는 과정에서 외부 공고·재고·신청 가능 여부를 다시 확인하지 않았다.
- 실제 후기·평점·게시판은 후속이며, 운영 기술 스택·AI 모델·최종 디자인도 미확정이다.

## 4. ZIP 구성과 검사

제품·개발 전달서, 디자인 전달서, 용도별 요청문 TXT 2개, PNG 4개, 화면 설명, 혜택 근거, 검사 범위 설명, 이 안내문과 `MANIFEST.json`이 들어 있다. 코드 실행용 패키지가 아니며 문서 안의 실행 명령에 필요한 앱 코드·Node.js는 포함하지 않는다. 원본 프로젝트의 문서·화면은 별도로 보존했다.

`MANIFEST.json`은 파일별 크기와 SHA-256을 기록한다. 문서 안의 패키지 로컬 링크, 이미지 원본 일치, ZIP 재열기와 파일별 해시를 확인한다. 앱 자동 검사 72개는 직전 구현 단계의 이력이며 이번 압축 작업에서 앱 검사를 재실행했다는 의미가 아니다.

외부 클로드 서비스로 전송하거나 업로드한 파일은 없다. 사용자가 위 안내에 따라 직접 전달할 수 있도록 로컬에 준비했다.
