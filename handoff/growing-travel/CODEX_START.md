# Codex 시작 지시문 — 기획·개발 기준 파일 정리

## 사용 전

새 폴더라면 이 패키지를 압축 해제한 폴더를 작업 대상으로 사용한다.
기존 프로젝트라면 패키지를 `handoff/growing-travel/` 같은 별도 폴더에 둔다.
기존 프로젝트 루트의 파일을 통째로 덮어쓰지 않는다.

아래 지시문은 정확한 저장소 경로나 기술 스택을 미리 안다고 가정하지 않는다.

## 붙여넣을 지시문

```text
이 작업 공간에서 '여행할수록 함께 자라는 AI 여행 추천'의 기획·개발 기준 파일을 정리해줘.
계획만 답하지 말고 실제 문서를 생성·수정하고, 변경 파일과 검증 결과를 보고해줘.

첨부하거나 작업 공간에 넣은 growing-travel-codex-handoff 패키지,
또는 handoff/growing-travel 아래의 문서를 먼저 찾아 읽어줘.
경로가 다르면 현재 작업 공간 안에서 README.md의 프로젝트명을 확인해 해당 폴더를 찾아줘.
다른 폴더나 저장소를 임의로 이번 여행 프로젝트로 간주하지 마.

서비스 방향은 다음과 같아.
일반 여행자가 실제 경험을 바탕으로 내 상황에 맞는 여행을 발견하고,
짧은 코스를 구성·수정하며, 개인 여행 기록을 다음 여행에 다시 활용하는 서비스야.
공개에 동의한 경험만 다른 여행자의 추천에도 사용해.
외국인 전용 한국 여행 플랫폼, 한일 업체용 컨시어지, 예약 대행은 현재 방향이 아니야.

먼저 현재 적용되는 AGENTS.md와 기존 README·설정·변경 사항을 확인하고,
전달 패키지의 아래 문서를 순서대로 읽어줘.
- AGENTS.md
- docs/00_DECISIONS_AND_SOURCES.md
- docs/01_PRODUCT_SPEC.md
- docs/02_UX_FLOWS.md
- docs/03_DATA_AND_AI_CONTRACT.md
- docs/04_DEVELOPMENT_PLAN.md
- docs/05_ACCEPTANCE_TESTS.md
- docs/06_TEAM_AND_VALIDATION.md

이번 작업 범위는 '파일 정리와 개발 준비'야.
1. 기존 코드가 있는지, 같은 여행 프로젝트인지, 실제 실행·검사 명령이 무엇인지 점검해줘.
2. 새 폴더면 이 문서들을 기준 파일로 정리하고, 기존 프로젝트면 겹치는 문서를 비교해 안전하게 병합해줘.
3. 사용자 결정, 구현 제안, 미확정 사항을 구분해줘. 스택·모델·가격을 임의의 확정 사실로 쓰지 마.
4. 제품 명세, 화면 흐름, 논리적 데이터·AI 계약, 개발 순서, 완료 기준을 서로 맞춰줘.
5. plans/01_FILE_SETUP.md에 실제로 확인한 내용과 변경 이력을 채워줘.
6. 첫 개발 과제를 '상황 입력 → 경험 추천과 근거 확인 → 코스 저장'으로 나누고,
   이어서 '개인 기록 → 선택적 공개·확인 → 다음 추천 반영'으로 연결할 계획을 기록해줘.
7. 가상 장소·후기·시연 데이터를 실제 검증 자료로 소개하지 마.
8. 문서 참조와 가상 자료를 검사하고, 기존 테스트가 있으면 적절한 안전한 범위에서 실행해줘.
   실행하지 못한 검사는 이유와 함께 '미실행'이라고 써줘.

기존 사용자 변경분을 삭제하거나 전체 파일을 덮어쓰지 마.
이 단계에서는 전체 앱 구현, 새 기술 스택 설치, 배포, 결제·예약 연동,
외부 업체 연락, 대회 제출, Git 커밋·푸시를 수행하지 마.
기존 프로젝트가 무관하면 그 코드는 건드리지 말고 전달 패키지 안에서 작업해줘.

마지막에는 아래 순서로 보고해줘.
- 생성·수정한 파일과 이유
- 기존 자료와 충돌했던 내용 및 정리 방법
- 실행한 검사·결과·미실행 사항
- 개발에 필요한 미확정 결정
- 다음에 착수할 가장 작은 구현 과제
```

## 이 단계의 완료 모습

서비스 방향이 고정된 파일, 기존 프로젝트 현황, 실제 검사 결과, 첫 구현 과제가 남아 있어야 한다.
미확정인 외부 계정이나 기술 선택을 이유로 문서 작성 전체를 멈추지 않는다.
반대로 문서만 만든 상태를 '서비스 구현 완료'라고 보고하지 않는다.
